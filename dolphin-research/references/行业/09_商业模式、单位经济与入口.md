## 9.1 商业模式本质与变现路径

> 本节导读：本节回答“这门生意的钱到底从哪来、靠什么持续”。研究 AI 模型、云与互联网公司，或硬科技、设备类赛道时，先用变现路径（2C 曲线变现 vs 2B 直接变现）、商业化台阶、云销售形态、巨头捆绑方式给公司定位，再用代际训练成本与领先窗口期的经济账判断商业模式的本质（是软件式的高毛利生意，还是持续融资的资本竞赛）；装机后市场锁定、用户侧储能的价值拆解、场景降维与第二曲线接力，则是 AI 之外的硬件、制造、消费赛道同样适用的商业模式拆解。单位经济账见 9.2，利润率与成本结构测算见 9.3，入口与生态之争见 9.5，融资能力与资本竞赛见 9.6；Chatbot 向 Agent 演进对算力需求、分配与变现的影响链，详见 3.4。

### 9.1.1 AI 变现路径框架：2C 曲线变现 vs 2B 直接变现

**方法要点**：把 AI 的变现先分成“2C 曲线变现”和“2B 直接变现”两类，分别判断公司在两条线上的资源、进度与代价，避免把“有流量、有 MAU”误当成“已经变现”。

**操作步骤 / 拆分口径**

1. 归类：
   - 2C 曲线变现（移动互联网思维）：AI 功能本身不直接收费，作为流量入口，通过广告、电商等既有业务曲线变现。对有存量 C 端业务的公司，这是“防守职能”，目的是守住入口、避免流量被新交互替代。
   - 2B 直接变现（软件思维）：基于工具创造的价值直接收费（按 Token、订阅），是“进攻职能”，能马上产生增量收入。
2. 判断先后与并存：当前 2B 更容易走通；长期两者并存，所以大公司往往要两条线同时投入。
3. 比较 2C 的先天条件：拥有电商、酒旅履约能力的公司，在 2C 曲线变现上比纯模型公司（如 OpenAI）更有优势，因为曲线变现需要后端履约和交易场景来承接。
4. 核算双线探索的代价：两线并投意味着泛 AI 投入长期维持高位，利润预测里要给相关业务的亏损留足空间。
5. 同步更新“替代风险”叙事：随着 2B 工具化（Agent、编程助手等）推进，“被 AI 替代”的担忧会从搜索和广告平台，转向 SaaS 软件公司。

**关键指标与数据来源**：C 端 MAU 与 DAU、留存；Token 收费收入；B 端产品进展（产品发布、客户与收入落地）。来源为公司财报及电话会、第三方 App 监测。

**判断标准**

- 2C 线：MAU 规模只是入口价值的前提，必须配合留存一起看。Chatbot 留存整体偏弱，说明入口黏性还没建立，不能把 MAU 直接折算为变现能力。
- 2B 线：看是否已有按 Token、订阅的收费收入落地，以及 B 端产品是否在持续推进。
- 推理链：2C 是防守（不投就可能丢入口）、2B 是进攻（投了就有增量收入）→ 大公司两线都得投 → 泛 AI 投入维持高位 → 相关业务的亏损短期不会收窄；同时 2B 越成功，估值与风险叙事越要从广告平台转向 SaaS。

**海豚案例**

- 阿里《阿里：电商退位，AI上位》（2026-05-14）：阿里需要在 2C（千问）和 2B（悟空、Qwen Code）两条线上同时投入；千问 MAU 超过 1.6 亿，但 Chatbot 留存整体偏弱；双线探索的代价是泛 AI 投入维持高位，因此 27 财年其他业务亏损不会太低。

**适用场景与注意事项**

- 适合评估互联网公司的 AI 战略，尤其是同时拥有存量 C 端业务和 B 端云业务的平台。
- 2C/2B 分类是用来定位资源投向与考核口径的框架，同一个产品可能同时承担两种职能；使用时要分别写出“防守价值”和“进攻收入”，不要混为一谈。
- 判断 2C 变现能力时，必须核对公司是否真有履约与交易场景；纯模型公司缺这一环。

### 9.1.2 C 端 Chatbot vs B 端 Agent 的付费力对比（三段证据链）

**方法要点**：回答“AI 商业化的钱从哪来”这个问题时，不停留在叙事，而是用开发者调研、收入结构、广告变现三段证据，论证 C 端 Chatbot 商业化艰难、以任务完成为导向的 B 端 Agent 才是付费力所在。

**操作步骤 / 拆分口径**

1. 先交代论证方向的转变：算力成本使“先补贴、再养习惯、再收割”的纯流量打法至少在当下不适用（这一逻辑的展开见 9.5.11）；Chatbot 付费率低、日均时长短，C 端商业化艰难；以任务完成为导向的 Agent 反而能激发企业付费。
2. 证据 ①，开发者调研（Stack Overflow）：Agent 使用率 59%、每天使用 37%；用 AI 工具的开发者中 66% 使用 Coding Agent，其中 73% 每天使用，说明 Agent 已进入高频工作流。
3. 证据 ②，收入结构（以 OpenAI 为例）：B 端（API + 企业订阅）收入 7 月已超过 C 端，4 月时 B 端占比还只有 40%；B 端年化收入 200 亿美元以上，9 月底翻倍。收入口径的毛/净区分与分部倒算方法见 9.3.1。
4. 证据 ③，广告路径不顺：CPM 从灰测期 60 美元降到 15-25 美元，自助投放门槛从 5 万美元降为零；8 月底广告 ARR 仅 10 亿美元，覆盖数万广告主、40 多个国家和地区。
5. 合成结论：Chatbot 的付费与广告两条路径都艰难，B 端 Agent 的付费力更强。

**关键指标与数据来源**：Agent 使用率与每日使用率（Stack Overflow 开发者调研）；B/C 端收入占比；ARR；CPM；广告主数量；来源为开发者调研、公司披露与第三方估算。

**判断标准**

- 证据链要同时覆盖“使用行为”（调研）、“收入结构”（B/C 占比及其变化方向）、“替代路径是否走通”（广告 CPM 与门槛）三个层面，三者方向一致才成立。
- B 端占比从 40% 升到超过 C 端并继续拉开，是“B 端 Agent 起量”的结构性信号；CPM 从 60 美元降到 15-25 美元并对标成熟数字广告平台，说明广告库存定价已回归常态，不再有新品溢价。
- 推理链：Chatbot 日均时长短 → 广告库存有限；付费率低 → 订阅天花板低；Agent 以任务完成交付价值 → 企业愿意按价值付费。

**海豚案例**

- OpenAI《(短评)AI商业化的钱从哪来》（2026-10-16，文章 id 44378894）：用上述三段证据链回答商业化来源。Stack Overflow 调研 Agent 使用率 59%、每天使用 37%，Coding Agent 使用者中 73% 每天使用；OpenAI B 端 7 月已超过 C 端，B 端年化 200 亿美元以上、9 月底翻倍；广告 CPM 从 60 美元降到 15-25 美元，8 月底广告 ARR 10 亿美元。

**适用场景与注意事项**

- 适用于 AI 应用商业模式判断，尤其是比较“流量型”与“任务型”产品的付费力。
- 样本偏重科技公司与 IT 从业者，向其他行业外推要谨慎；结论针对“当下”，算力成本下降会改变 C 端的经济账（见 9.2.6）。
- 与 9.1.1 配合使用：本方法提供“为什么 2B 更先走通”的证据，9.1.1 给出分类框架。

### 9.1.3 AI 模型商业化四台阶：卖模型 → 卖调用 → 卖订阅 → 卖端到端任务

**方法要点**：用“台阶”定位一家模型公司商业模式所处的阶段，并据此判断定价逻辑和估值逻辑的变化；台阶的跃迁是估值重估的核心。

**操作步骤 / 拆分口径**

1. 台阶 1，卖模型：项目制本地部署，重交付、续约不确定，估值折价。
2. 台阶 2，卖调用：云端 API，模型即收入，标准化、轻交付，想象空间大。
3. 台阶 3，卖订阅：以 Coding Plan 等订阅套餐为代表，把调用打包成可预期的经常性收入。
4. 台阶 4，卖端到端任务：直接按任务完成交付结果收费。
5. 用收入拆分定位台阶：看本地部署、云端、订阅三类收入各占多少，占比的迁移方向就是商业模式的演进方向。

**关键指标与数据来源**：本地部署/云端/订阅收入占比；来源为公司财报与业绩会披露。

**判断标准**

- 台阶越高，交付越标准化、定价越贴近价值，估值倍数越能脱离“项目制折价”；停在台阶 1 的公司续约不确定、估值要折价。
- 判断是否“跃迁”要看抓住的场景：智谱抓住 Coding 场景爆发，从卖调用跃进到卖订阅。
- 单纯部署大模型对大企业而言或已是“伪需求”，这是对台阶 1 长期价值的否定性判断。

**海豚案例**

- 智谱（2026-08-31）：抓住 Coding 场景爆发，从卖调用跃进到卖订阅；单纯部署大模型对大企业而言或已是“伪需求”。
- 智谱（2026-03-31）：从项目制本地化部署转向云端 API，涨价后仍算力不够，说明云端 API 的需求强于本地部署。

**适用场景与注意事项**

- 适用于 AI 与软件行业，尤其是大模型、AI 应用公司的商业模式与估值分析。
- 台阶不等于替代：公司可能多台阶并存，关键看增量收入来自哪一级。
- 订阅、端到端任务的定价与毛利要结合 9.3 的单位成本与 9.4 的定价追踪一起验证。

### 9.1.4 云销售形态升级：裸金属租赁 → MaaS/Token 对收入和利润率的影响

**方法要点**：区分云的销售形态——卖“裸金属”算力（客户自建模型）与卖 MaaS 或 Token（预配好模型），据此解释 AI 占比提升时云利润率为何不降反升，消解市场对 AI 投入回报率的质疑。

**操作步骤 / 拆分口径**

1. 区分两种形态：裸金属租赁（只卖算力，客户自己部署和调用模型）与 MaaS/Token（云厂预配好模型，按 Token 计费）。
2. 理论预期：MaaS/Token 的营收和利润率都高于裸金属，最终体现为云营收加速、利润率好于预期。
3. 叠加其他利润率驱动：放弃低毛利业务、算力涨价，共同解释“AI 占比提升、利润率反而上升”。
4. 逐季跟踪云 adj.EBITA 利润率（环比）、MaaS 收入占比、算力租赁价格，对照市场预期（本例市场预期 10%-11%）。

**关键指标与数据来源**：云 adj.EBITA 利润率（环比）、MaaS 收入占比、算力租赁价格；来源为阿里云披露的分部利润与业绩会。

**判断标准**

- 利润率持平或上升，意味着 AI 占比提升并没有拖累云业务，投入回报率的质疑被消解；高于市场预期是正向超预期。
- 推理链：MaaS 利润率高于裸金属 → MaaS 占比提升 → 云利润率走高；若预计 MaaS 将成为最大的收入产品，则后续利润率可能持续走高。

**海豚案例**

- 阿里《阿里：电商再沦陷》（2026-03-19）：云利润率 9%，与上季持平，没有因 AI 比重上升而被拖累；预计 MaaS 将成为最大的收入产品。
- 阿里《阿里：电商退位，AI上位》（2026-05-14）：利润率 9.1%，环比 +0.1pct；MaaS 利润率高于裸金属，后续利润率可能持续走高。
- 阿里《阿里狂投》（2026-08-21）：利润率接近 12%，高于市场预期的 10%-11%。

**适用场景与注意事项**

- 适合云计算厂商，尤其是同时有算力租赁和模型服务的综合云。
- MaaS 利润率高于裸金属是理论推断，需用分部利润率的实际走势验证；算力涨价对利润率的影响可用 9.3.10 的控制变量方法拆解。

### 9.1.5 巨头 AI 变现路径对比：借现有商业模式“丝滑变现”的能力

**方法要点**：国内暂无公司指望单纯靠办公 Agent 赚钱，都靠把 AI 与传统产品、云捆绑变现，所以比较的重点是“借现有商业模式丝滑变现”的能力，包括捆绑方式、收入落点、组织架构调整与销售策略。

**操作步骤 / 拆分口径**

1. 对每家公司，写清三件事：AI 功能与哪个既有产品或云捆绑；收入最终落在哪里（席位、Token/云消耗、订阅、抽佣）；组织与销售怎么配合。
2. 横向比较（海豚君的比较结论为字节 > 阿里 > 腾讯）：

| 公司 | 变现落点 | 路径特征 |
|---|---|---|
| 阿里 | 云钉 + MaaS | 从已掌握的企业采购部门入手，云产品捆绑 + 钉钉渠道自上而下拿客户；提高钉钉留存后卖企业席位，后端消耗 Token 与阿里云资源 |
| 腾讯 | 生态抽佣 + 云 | C 端流量导流（企业微信、微信及外部投流），散客为主，偏订阅与开放生态抽佣 |
| 字节 | 企业 IM + 云 | 中间路线，AI 功能缝合进飞书，同时 C 端投流；飞书负责企业上下文与席位收入，火山负责算力与 Token 收入，豆包工作提高客单价与粘性 |

3. 看组织架构调整：字节把飞书产品并入豆包、飞书销售并入火山，是战略优先级的信号。
4. 看销售策略：字节销售激进，购买火山算力的企业可免费使用三周、100 席以上额度再转付费。

**关键指标与数据来源**：席位收入、Token/云消耗、订阅、抽佣、组织架构调整、试用转化策略；来源为公司公开动作、渠道调研与业绩会。

**判断标准**

- 变现能力强的特征：AI 与已有的付费入口（企业采购、IM 席位、云资源）直接捆绑，客户路径短；弱的特征：主要靠 C 端流量和生态伙伴，散客为主、抽佣为主。
- 组织架构调整（产品并入、销售并入）说明公司把 AI 当作主航道；试用转化策略的激进程度反映抢占份额的决心。
- 推理链：谁能让 AI 的收入落进已有的席位、云消耗体系里，谁的变现就更“丝滑”。

**海豚案例**

- 阿里/腾讯/字节《腾讯、阿里、字节：谁能坐稳 AI 办公的「工头位」？》（2026-10-14）：按上表三家路径逐一对比，结论是在“借现有商业模式丝滑变现”的能力上字节 > 阿里 > 腾讯；字节飞书产品并入豆包、飞书销售并入火山，并以三周免费试用、100 席以上转付费的策略推进。

**适用场景与注意事项**

- 适用于多元业务巨头 AI 业务的变现能力比较。
- 组织架构调整是战略优先级的信号，应与资源投入同步跟踪。
- 比较的是“变现路径与能力”，不等于已实现的收入；落到收入口径还需配合 9.3 的拆分。

### 9.1.6 代际训练成本倍增、无法跨期摊销，以及研发资本化与“长江电力”终局条件

**方法要点**：量化每代模型的训练成本与代际倍数，解释为什么大模型公司的亏损率高达收入的 5-10 倍，并给出商业模式走向“长江电力式”稳定盈利的终局条件。

**操作步骤 / 拆分口径**

1. 量化每代训练成本与代际倍数（2023 年研发一代模型的训练成本在 4000 万到 5000 万美元之间，升级一代基本要提高 3-5 倍）。
2. 结合迭代节奏（一年一代）推出：一代模型只对应接下来一年的推理创收期，无法跨年摊销，只能全额计入当期研发费用，于是出现高于收入 5-10 倍的亏损。
3. 本质判断：这是把一门强资产负债表的资本密集型业务，全部摊在了利润表上。
4. 给出终局条件：
   - 缩放定律失效（增加一点智力所需的算力暴涨），训练频率降低；
   - 一次训练能创收 10-20 年，研发资本化才有商业基础，类似“长江电力”的模式；
   - 前提是头部厂熬死对手、形成像云服务那样的寡头格局，并不再打价格战。

**关键指标与数据来源**：单代训练成本、代际成本倍数、迭代周期、摊销期；来源为公司招股书与财报。

**判断标准**

- 迭代周期越短、代际倍数越高，越无法摊销，利润表越难看；迭代放缓且一次训练的服役期拉长到 10-20 年，才具备资本化与稳定回报的条件。
- 终局三要素缺一不可：缩放定律失效、行业寡头化、停止价格战。
- 推理链：代际倍增（3-5 倍）+ 一年一代 → 费用化 → 5-10 倍亏损率 → 只有迭代放缓才可能转向资产化。

**海豚案例**

- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：2023 年研发一代模型的训练成本在 4000 万到 5000 万美元之间，升级一代训练成本基本要提高 3-5 倍；据此推出无法跨期摊销、全额费用化、亏损率达收入 5-10 倍，并给出缩放定律失效后“长江电力”式终局的条件。

**适用场景与注意事项**

- 适用于判断 AI 模型公司何时能走向盈利；也可迁移到其他技术快速迭代的重研发行业（如芯片流片、创新药）。
- 与 9.3.5（回本覆盖率）、9.3.4（亏损率趋势）配合：本方法解释“为什么亏”，后两者量化“亏得有没有改善”。
- 终局条件是推演而非预测，应将“缩放定律是否失效”作为跟踪信号。

### 9.1.7 领先窗口期经济账：年投入 vs 领先溢价期，商业模式本质为持续融资竞赛

**方法要点**：评估独立 AI Lab 的商业模式时，把“每年的基础设施 + 训练投入”与“换来的领先溢价期”放在一起算账，发现账很难算明白，商业模式本质上就是持续融资的资本竞赛。

**操作步骤 / 拆分口径**

1. 算投入：一年数十亿至上百亿美元的基础设施 + 训练成本。
2. 算回报：换来的领先优势从 12 个月缩短到 3 个月的溢价红利期。
3. 判断竞争是否停歇：在缩放定律失效之前，人人都认为自己能训练出下一个前沿模型，竞争不会停歇，大模型公司是持续的“吞金兽”。
4. 推出商业模式本质：持续融资的资本竞赛。
5. 做预判与跟踪：
   - 下半年一梯队 AI Lab（Anthropic、OpenAI、DeepSeek、Kimi）陆续筹划上市，当所有选手拥有同样融资通道时决战开始；
   - 跑分刷榜推动融资的现象会更频繁；
   - 何时盈利、能否盈利将在每次融资时被反复拷问；
   - 开源追平闭源意味着纯大模型商业模式边际恶化的拐点，可能拉长头部厂商扭亏等待期。

**关键指标与数据来源**：年训练/基础设施投入、领先窗口（月）、融资节奏、上市计划；来源为公司公开融资信息、发布节奏与榜单。

**判断标准**

- 领先窗口期（12 个月 → 3 个月）缩短而年投入不降，则单位投入换来的溢价在下降，商业模式越依赖外部融资。
- 开源追平闭源，是纯大模型商业模式边际恶化的拐点信号。
- 关键比较是“投入回报期”与“护城河持续时间”：回报期长于护城河期，就只能靠融资续命。

**海豚案例**

- 大模型行业《Kimi K3 时刻：中美 AI 产业链叙事要变天？》（2026-07-22）：给出一年数十亿至上百亿美元投入对应 3 个月溢价期的经济账，预判一梯队 AI Lab 下半年陆续筹划上市；引用年初覆盖智谱与 MiniMax 深度报告的观点。

**适用场景与注意事项**

- 适用于独立模型厂、重研发初创公司估值；核心是投入回报期与护城河持续时间的比较。
- 融资缺口倍数与“融资耐力”淘汰赛的具体测算见 9.6.5；融资优势本身如何成为竞争力见 9.6.1。

### 9.1.8 “整机销售 + 长期服务协议（LTSA）”的后市场锁定与转换成本

**方法要点**：拆解设备类公司的盈利模式时，指出主机销售只是开端，20-30 年的维护、备件与升级服务（LTSA）才是持续利润来源，并用转换成本解释客户锁定。

**操作步骤 / 拆分口径**

1. 区分两段收入：主机一次性销售 vs 长期服务协议（LTSA）带来的 20-30 年持续收入。
2. 看锁定机制：巨头通过 LTSA 提前锁定客户未来价值。
3. 量化转换成本：电站运营商若更换主机厂，要承担技术风险、系统重构、人员再培训等巨额隐性成本，被深度绑定在现有生态中。
4. 推导对估值的含义：存量装机越大，服务收入越稳定，周期性被平滑。
5. 用订单验证：服务订单规模与增速印证长周期运维的高毛利现金流价值。

**关键指标与数据来源**：服务协议年限（20-30 年）、服务收入/订单占比、存量装机；来源为公司财报、订单披露与行业调研。

**判断标准**

- 服务收入占比越高、协议期限越长、存量装机越大，现金流越稳、周期性越弱，估值应更偏向“服务型”而非纯设备周期。
- 转换成本越高（技术风险、系统重构、再培训），客户越不会更换主机厂，护城河越深。
- 推理链：主机销售 → 绑定存量装机 → LTSA 锁定未来 20-30 年的服务现金流 → 平滑周期。

**海豚案例**

- 《AI 终极瓶颈…》（2026-04-09）：分析燃机生态与服务壁垒，指出主机销售只是开端、LTSA 才是利润来源。
- 《AI 电荒突围》（2026-04-14）：BE 服务订单约 140 亿美元（+46%），对应 PPA 下长周期运维现金流，印证长周期运维的高毛利现金流价值。

**适用场景与注意事项**

- 适用于装机后市场型的设备公司（燃机、航发、医疗设备等）。
- 需要核对服务收入占比与合同期限的真实性；新增装机增速放缓时，要看存量装机能否继续支撑服务收入。

### 9.1.9 用户侧储能的多重价值拆解

**方法要点**：评估用户侧储能不按单一收益算，而是逐项拆出价值来源；其中“换取并网许可”这一制度价值，把储能从“经济性可选”变成“准入性刚需”。

**操作步骤 / 拆分口径**

逐项列出价值来源：

1. 降低自身峰值负荷（削峰填谷）；
2. 峰谷价差套利；
3. 替代柴油发电机做备用电源；
4. 平抑 AI 负载的剧烈波动，减轻对电网的“劣质冲击”；
5. 制度价值：在 PJM、ERCOT 等区域，配储已成为数据中心获得并网许可、缩短排队时间的“必选项”。

然后判断哪几项是经济性价值（1-3）、哪几项是电网友好性价值（4）、哪一项是准入性价值（5），并推出需求刚性。

**关键指标与数据来源**：峰谷价差、并网排队时长、各 ISO 并网规则（PJM/ERCOT）。

**判断标准**

- 第 5 项把储能从“经济性可选”变成“准入性刚需”，需求刚性随之大幅提升；只要并网规则要求配储，需求就不再完全取决于价差套利的 IRR。
- 推理链：AI 数据中心负荷大且波动剧烈 → 并网排队长、电网压力大 → 配储成为获得并网许可的前提 → 用户侧配储需求与电网侧需求叠加，形成“全面性需求”。

**海豚案例**

- 《AI 终极瓶颈…》（2026-04-09）：用户侧配储五重功能，推出“电网侧和用户侧储能的全面性需求”。

**适用场景与注意事项**

- 适用于储能、虚拟电厂等。
- 需逐区域核对并网规则，制度价值因 ISO 不同而有差异。

### 9.1.10 “场景降维”商业化路径与自动驾驶演进类比

**方法要点**：把“终极形态是否必然”和“能否马上商业化”分开，识别通过技术简化和功能限制先做出可商用产品、同时积累数据逐步逼近终极产品的路径，从而找出短期就有收入的中间形态。

**操作步骤 / 拆分口径**

1. 区分两个问题：终极形态是否必然？是否能马上商业化？两者可以不同步。
2. 找限定场景：初期应用集中在限定场景（特斯拉 Optimus 先在自家工厂收集数据和训练）和对成本不敏感的领域（科研教育）。
3. 找中间形态：某些中间形态可能先达到商业化条件，如两指、三指、较少自由度、欠驱动方案或简化感知硬件，用于半通用半专用场景（如 Robotiq 三指夹爪、BarrettHand 三指手）。
4. 用自动驾驶做类比：有的公司直接冲 L4/L5，有的先做 L2/L3 作为入场券，用现金流反哺研发；辅助驾驶也是先上高速 NOA、再城市通勤 NOA、再全场景 NOA。
5. 抽象路径：通过技术简化和功能限制做出可商用产品，同步积累数据迭代算法，逐步逼近终极产品。

**关键指标与数据来源**：场景限定程度、自由度指数、成本、现金流。

**判断标准**

- 中间形态能否成立的判断：场景是否足够限定、成本是否在客户可接受范围、能否产生现金流并回流数据；满足这三点，就具备“入场券”价值。
- 推理链：终局遥远 → 直接做终极形态需要长期烧钱 → 先以降维场景/简化方案拿到现金流与数据 → 反哺研发，逐步逼近终局。

**海豚案例**

- 人形机器人《人形机器人：为何灵巧手是迈不过去的门槛？》（2026-01-20）：以 Robotiq 和 BarrettHand 三指手为中间形态例子，类比自动驾驶 L2/L3 与 NOA 路径，说明灵巧手之外的欠驱动、少自由度方案可能先商业化。

**适用场景与注意事项**

- 适用于终局遥远但需要现金流过渡的硬科技赛道，可用来识别短期就能产生收入的中间形态公司。
- 类比不等于必然，中间形态也可能成为陷阱（只做简化版而无法向终局升级），需要看数据积累与迭代是否真在逼近终局。

### 9.1.11 判断主业体量瓶颈，以及第二曲线能否接力

**方法要点**：判断核心品类是否接近体量瓶颈、第二曲线的增速能否接力，再叠加区域成熟度，估计公司的下一阶段增长来源。

**操作步骤 / 拆分口径**

1. 判断核心品类是否接近瓶颈：例如增速首次降到个位数、体量逼近天花板。
2. 判断第二曲线能否接力：第二曲线的体量、增速是否足以补上核心品类放缓的缺口，并观察其自身增速是否也在放缓。
3. 看区域成熟度：老区域低增长，新区域靠网点扩张；分区域增速可识别增长来源是否依赖终端扩张。
4. 结合行业渗透率位置，判断瓶颈来自公司自身还是行业整体天花板。

**关键指标与数据来源**：分品类增速、分区域增速；来源为公司财报分品类、分区域披露。

**判断标准**

- 瓶颈信号：核心品类增速首次降到个位数。
- 接力能力：第二曲线增速高、体量在快速扩大才能接力；若第二曲线增速也在放缓（如前期约 200% 降至 50%），接力力度减弱。
- 区域信号：低个位数增长的老区域说明成熟；仍靠终端网点扩张的区域说明增长依赖投入，而非自然需求。

**海豚案例**

- 东鹏（2026-03-30）：能量饮料 30 亿元、+8.5%，近 3 年首次个位数增长，体量离瓶颈越来越近；电解质饮料 4.3 亿元、+50%（前期约 200%），也在放缓；其他饮料 +166%；两广地区低个位数增长，华西、华北仍靠终端网点扩张。
- 三花（2026-03-23）：传统制冷和汽零的天花板在靠近，更应关注机器人和数据中心这两条第二曲线。
- Monster（2026-02-27）：能量饮料在健康化、功能化趋势下仍处于全球渗透率快速提升期，说明核心品类的天花板尚远，没有进入瓶颈。

**适用场景与注意事项**

- 适用于消费品和制造业。
- “增速首次降到个位数”是一个经验信号，需结合渗透率与行业空间判断是否真触顶（Monster 的反例说明同一品类在不同市场的阶段不同）。

**本节速查清单**

## 9.2 单位经济模型

> 本节导读：本节解决“把业务压缩到一个最小单位（一英里、一个用户、一次发射）后，这笔账算不算得过来”的问题。评估 Robotaxi、无人配送、双边平台、免费加广告的 AI 产品，或新硬件产品时，先用现状 UE 找到最大的成本项，再逐项推演降本杠杆与新增成本，最后用情景区间收口并与替代品比较。本节以自动驾驶出行为主线，也包含个人 Agent 与新型火箭的单位账；技术方案之间的单位成本比较见 6.4，利润率与成本结构的财务测算见 9.3，定价与性价比见 9.4。

### 9.2.1 单位里程成本对比：打车价格 vs 私家车持有成本（含非经济因素）

**方法要点**：用“每公里/每英里成本”比较替代品与现有方案的经济性，判断服务替代资产持有的空间有多大，并补充经济账之外的非经济因素。

**操作步骤 / 拆分口径**

1. 算打车单位成本：
   - 中国：滴滴单均 GTV 约 24 元，扣除约 10% 用户激励后用户实付约 21.6 元，单均约 10 公里，即打车约 2.2 元/km（市场整体 2.0-2.5 元/km）。
   - 美国：网约车约 2.5 美元/英里。
2. 算私家车持有成本 = 固定项（折旧、保养、保险、停车）+ 可变项（油电费）：
   - 中国：按年行驶 1.2 万-1.5 万公里，单位成本约 2.1-2.7 元/km，与打车基本持平。
   - 美国：AAA 测算年行驶 1 万-2 万英里时，私家车约 0.7-1.1 美元/英里。
3. 横向比较与推论：美国网约车 2.5 美元/英里大幅高于私家车，所以美国网约车加出租车约占出行市场 3%，低于中国的 9%；私家车垄断 85-90% 的出行市场，原因是“省”。
4. 补充非经济因素：私家车可随时响应临时需求、装大件、去非热门地点，有私密性；在中国还绑定面子和社交价值，网约车只是“从 A 到 B”的工具。
5. 做敏感性分析：私家车成本受年行驶里程影响大，需要给出不同里程下的区间。

**关键指标与数据来源**：单均 GTV、用户激励率、单均里程、私家车固定与可变成本、年行驶里程、AAA 用车成本；来源为滴滴披露、AAA 年度用车成本测算。

**判断标准**

- 替代空间的标准：服务价格能否击穿私家车成本底线；中国两者基本持平，美国网约车明显更贵，所以私家车牢牢主导出行市场。
- 推理链：成本相当（中国）或更高（美国）→ 没有经济性理由放弃私家车 → 再叠加私密性、即时性、面子等非经济因素 → 私家车地位难以撼动，除非单位成本被大幅压低。

**海豚案例**

- 网约车/Robotaxi《Robotaxi出行帝国，能再造特斯拉？》（2026-01-07）：结论是网约车成本在中国和私家车持平、在美国更高，所以私家车牢牢主导出行市场。
- 特斯拉《(短评)Robotaxi击穿私家车成本底线》（2026-01-14，文章 id 37803174）：以美国网约车 2.5 美元/英里 vs 私家车 0.7-1.1 美元/英里锚定现状，解释私家车垄断 85-90% 出行市场的原因是“省”，并以此作为后续推演的起点（完整三线对比见 9.2.5）。

**适用场景与注意事项**

- 适用于任何“服务替代资产持有”类业务（Robotaxi、租赁、订阅、云替代自建）。
- 私家车成本对年行驶里程高度敏感，需要做敏感性分析；各国的 GTV、激励口径不同，不能直接横向套用。

### 9.2.2 平台利润率（EBITDA/GTV）与单位经济拆解：司机分成、乘客激励、变现率

**方法要点**：用 EBITDA/GTV 衡量平台型出行公司的盈利能力，再用 UE 模型拆出最大的成本项，识别“人力成本”是限制利润率与市值的主要因素。

**操作步骤 / 拆分口径**

1. 算利润率：EBITDA/GTV。
2. 拆 GTV 去向：
   - Uber：GTV 的 70% 分给司机（含基础报酬和接单激励），平台变现率（take rate）约 30%；EBITDA/GTV 为行业最高，但仍未突破 10%。
   - 滴滴：GTV 的 80% 分给司机，另拿 GTV 的 10.5% 做乘客激励，最终变现率只有约 10%；EBITDA/GTV 只有低个位数。
3. 找最大成本项：司机分成。
4. 推出结论：高昂的司机人力成本让网约车难以大幅降价，利润率也不高，是限制行业规模和公司市值的主要因素。
5. 引出关键问题：自动驾驶去掉人力成本后，苦生意能否变成好生意？（推演见 9.2.3）

**关键指标与数据来源**：EBITDA/GTV、司机分成比例、乘客激励率、平台变现率（take rate）；来源为 Uber、滴滴财报。

**判断标准**

- 利润率高低主要由“GTV 中有多少留给平台”决定：Uber 约 30%、滴滴约 10%，差距来自司机分成比例与乘客激励投入。
- 推理链：司机分成占 GTV 的 70-80% → 平台变现率有限 → 利润率难以突破 10% → 规模与市值受限 → 去掉人力才可能带来质变。

**海豚案例**

- Uber/滴滴《Robotaxi出行帝国，能再造特斯拉？》（2026-01-07）：Uber 司机分成 70%、变现 30%；滴滴司机分成 80%、乘客激励 10.5%、变现约 10%；Uber EBITDA/GTV 行业最高但未破 10%，滴滴低个位数。

**适用场景与注意事项**

- 适用于双边平台（网约车、外卖、即时配送）的利润率分析。
- 不同公司的 GTV 口径可能不同（例如是否含激励、是否含税费），比较前要先统一口径。

### 9.2.3 Robotaxi 单英里成本 UE 重构：降本四项 / 三杠杆

**方法要点**：先复盘现状 UE，找到成本大头，再逐项推演去人力、降车价、降保险、提效率四个降本杠杆，并把每英里成本抽象为“固定成本 ÷ 年有效载客里程 + 可变成本”的公式，用来判断能否击穿私家车成本底线。

**操作步骤 / 拆分口径 / 公式**

变体 A：完整四项推演（长文版）

1. 复盘现状 UE：Uber 终端定价约 2.5 美元/英里，30% 为平台抽成，70%（约 1.75 美元/英里）归司机端，其中 40% 是纯司机人力回报；按此口径，70% − 40% = 30%，约 0.75 美元/英里，即剔除人力后，车辆硬件运营成本（折旧、能源、保险、维保）约 0.7-0.8 美元/英里，约占 GTV 的 30%。
2. 去除人力：基础成本降到 0.7-0.8 美元/英里，与美国私家车持平或略低。
3. 降购置成本（压折旧）：
   - Cybercab 无方向盘和踏板，2026Q2 投产，目标年产能 200-300 万台（最终 400 万），采用 Unboxing 工艺，目标售价低于 3 万美元；
   - 海豚君估计中期生产成本约 2.5 万美元；
   - 对照：网约车 3.5 万美元购置成本、美国新车均价 4.9 万美元（KBB）；
   - ARK 更乐观，认为能效 5.5 英里/kWh、电池降到 2300 美元/车，总成本可低于 1.5 万美元。
4. 降保险：网约车保险 0.26 美元/英里（比私家车 0.21 高 25%），事故率降到人类的 1/10 时，乐观可降到 0.1 美元/英里。
5. 提运营效率：
   - 收费里程 = 单车日均接单数 × 每单里程；
   - 空驶率从 40% 降到 20%，日均有效时长从 7-8 小时提到 12 小时，单量从 20 单提到 40-50 单，年载客里程从 4 万英里升到 9 万英里，以此摊薄固定成本；
   - 约束：受补能时间和零部件寿命限制，不可能 24 小时运营。

变体 B：三杠杆框架与公式（短评版）

1. 人力：司机约占网约车成本 50-60%，去掉后直接下探。
2. 车辆资本成本：专为自动驾驶设计的车型 BOM（Cybercab 2.5-3 万美元 vs Waymo 8 万美元），叠加拆箱式制造。
3. 运营效率：日运营时长 7-8 小时 → 12 小时，空驶率 40% → 20%，单车年载客里程 4 万 → 9 万英里，固定成本按里程摊薄。

公式：

- 每英里成本 ≈（车辆折旧 + 保险维护等固定成本）÷ 年有效载客里程 + 可变成本；
- 年有效载客里程 = 日运营时长 × 车速 ×（1 − 空驶率）× 365。

**关键指标与数据来源**：单英里定价、平台抽成、司机分成、人力回报占比、车辆折旧/能源/保险/维保单英里成本、车价/BOM、空驶率、日均有效时长、日均单量、年载客里程；来源为 Uber 披露、AAA、KBB、ARK、公司发布会。

**判断标准**

- 底线标准：去人力后的基础运营成本 0.7-0.8 美元/英里，已与私家车（0.7-1.1 美元/英里）持平，这是击穿私家车成本的起点而不是终点。
- 车价杠杆：BOM 2.5-3 万美元对比 Waymo 8 万美元，折旧占比大幅下降；
- 效率杠杆：年载客里程从 4 万提到 9 万英里，对固定成本的摊薄最显著，但要受补能时间与零部件寿命约束，不能无限拉高。
- 推理链：先去人力（最大成本项）→ 再压车价与保险（硬件固定成本）→ 最后用高利用率摊薄固定成本，三者叠加决定单英里成本的下限。
- 参数敏感：空驶率、有效时长、车价等关键假设都对结论影响大，必须配合 9.2.5 做情景分析，并扣除 9.2.4 的新增成本项。

**海豚案例**

- 特斯拉 Robotaxi《Robotaxi出行帝国，能再造特斯拉？》（2026-01-07）：完整四项推演，涵盖 UE 复盘（2.5 美元/英里，30% 抽成，70% 归司机端，40% 为人力回报）、Cybercab 成本（目标 3 万美元以下、海豚君估计 2.5 万美元，ARK 乐观 1.5 万美元以下）、保险（0.26 → 0.1 美元/英里）、运营效率（空驶率 40% → 20%，单量 20 → 40-50 单，年载客 4 万 → 9 万英里）。
- 特斯拉 vs Waymo《(短评)Robotaxi击穿私家车成本底线》（2026-01-14，文章 id 37803174）：三杠杆版本——BOM 2.5-3 万 vs 8 万美元；空驶率 40% → 20%；年载客里程 4 万 → 9 万英里；司机占网约车成本 50-60%。

**适用场景与注意事项**

- 适用于自动驾驶出行、无人配送、无人卡车等“去人力”的重资产运营模式。
- 参数敏感，要做情景分析；乐观版本（如 ARK）的假设往往遗漏成本项，见 9.2.4、9.2.5。

### 9.2.4 识别新商业模式的新增成本项及其随规模摊薄的路径

**方法要点**：不只算降本，也要系统列出新模式引入的新成本，并给出每项随技术成熟的演变路径，避免“只算节省、不算新增”的乐观偏差。

**操作步骤 / 拆分口径**

1. 列出相对旧模式新增的成本项（旧模式下由司机自理或不存在的成本）。
2. 对每一项给出配比和演变路径：
   - 安全员：早期是仅次于折旧的第二大成本；从车内安全员 1:1，到远程安全员（Waymo 目前 1:30），再到只在宕机或极端长尾场景介入（1:1000 以上），规模成熟后趋近于 0。
   - 地勤：网约车时代由司机自理清洁维护，Robotaxi 需要专门团队负责充电、清洁、救援和调度，保守假设地勤与车辆配比 1:10。
   - 增量维保：智驾硬件（摄像头、芯片）需要定期标定和清洁，软件要持续 OTA；日均行驶里程是私家车的 5-10 倍，轮胎和零部件磨损加快。
3. 把新增成本折算到每英里，并从 9.2.3 的降本结果里扣除。

**关键指标与数据来源**：安全员与车辆配比、地勤与车辆配比、传感器标定频率、日均里程；来源为公司披露与行业调研。

**判断标准**

- 安全员配比从 1:1 → 1:30 → 1:1000 以上，是降本的关键里程碑；所处阶段决定当下成本水平。
- 地勤保守取 1:10，说明这一项不会像安全员一样趋近于 0，是长期存在的运营成本。
- 日均里程是私家车的 5-10 倍，磨损随里程放大，维保不能按私家车口径估算。

**海豚案例**

- Robotaxi《Robotaxi出行帝国，能再造特斯拉？》（2026-01-07）：安全员 1:1 到 1:30 再到 1:1000 以上，地勤 1:10，增量维保（标定、OTA、5-10 倍里程带来的磨损）。

**适用场景与注意事项**

- 适用于检验“去人力”模型的乐观假设，避免只算节省、不算新增。
- 新增成本随规模摊薄的路径，取决于技术成熟度与监管（远程接管比例），需要跟踪。

### 9.2.5 远期单位成本三情景，与三线对比（Robotaxi vs 私家车 vs 网约车）

**方法要点**：把外部与公司的最乐观目标拆开，找出其遗漏的成本，再构建务实的三情景区间，并与私家车成本、网约车价格做三线对比，判断 Robotaxi 能否把“资产性消费（买车）”转为“服务性消费（打车）”。

**操作步骤 / 拆分口径**

1. 锚定现状：美国网约车 2.5 美元/英里 vs 私家车 0.7-1.1 美元/英里，解释私家车垄断 85-90% 出行市场的原因是“省”。
2. 列出外部乐观目标：ARK 假设单英里成本最终降到 0.25 美元；马斯克目标 Cybercab 运营成本 0.2-0.3 美元/英里。
3. 拆解遗漏：该区间只覆盖“车辆折旧 + 补能”两项最刚性的硬成本，几乎忽略保险、清洁维护、后台运营等管理费用。
4. 测算去掉司机后的基础运营成本：0.7-0.8 美元/英里，已与私家车持平。
5. 构建 2035 年三情景：

| 情景 | 单英里成本 | 关键假设 |
|---|---|---|
| 悲观 | 0.8 美元 | 运营效率无改善，年载客 4 万英里；低车价红利被安全员 1:30 和高运维成本抵消 |
| 中性 | 0.6 美元 | 年载客 6 万英里，日运营 9.4 小时，安全员 1:50，保险下降 |
| 乐观 | 0.4 美元 | 年载客 9 万英里，日运营 12.4 小时，车价降到 2 万美元，安全员和保险成本骤降 |

6. 结合公司特质判断概率：特斯拉垂直一体化、纯视觉方案、专为全自动驾驶设计的 Cybercab（BOM 已降至 2.5-3 万美元），成本落在 0.4-0.6 美元的概率更高。
7. 对照基准：私家车 0.7-1 美元/英里，Uber/Lyft 实际运营成本 1.7-2 美元/英里。
8. 设定里程碑为加速节点：2026 年 Cybercab 量产。

**关键指标与数据来源**：2035 年单英里总成本、年载客里程、日运营时长、安全员配比、车价、BOM、私家车出行份额；来源为 ARK、马斯克公开目标、AAA、公司披露。

**判断标准**

- 击穿私家车成本底线的标准：Robotaxi 单英里成本低于私家车的 0.7-1 美元；三情景中悲观 0.8 仅与私家车相当，中性 0.6、乐观 0.4 才形成明显优势。
- 外部乐观假设的识别：只覆盖折旧与补能（0.2-0.3 美元）的口径必然偏低，务实区间应在 0.4-0.6 美元之间。
- 概率判断来自竞争优势：垂直一体化、纯视觉方案和专为全自动驾驶设计的车型，使特斯拉更可能落在中性到乐观之间。

**海豚案例**

- 特斯拉《Robotaxi出行帝国，能再造特斯拉？》（2026-01-07）：悲观、中性、乐观分别为 0.8、0.6、0.4 美元/英里；ARK 0.25、马斯克 0.2-0.3 的区间只覆盖折旧与补能。
- 特斯拉《(短评)Robotaxi击穿私家车成本底线》（2026-01-14，文章 id 37803174）：私家车 0.7-1.1、网约车 2.5、Robotaxi 基础 0.7-0.8；2035 年乐观 0.4 / 中性 0.6 / 悲观 0.8；特斯拉落在 0.4-0.6。

**适用场景与注意事项**

- 适用于自动驾驶出行及任何“服务替代自有资产”的商业模式（共享出行、云替代自建）；也适用于对远期颠覆性技术做成本情景，关键是把外部最乐观假设拆开，找出遗漏项。
- 保险、监管、清洁维护等隐性成本未完全纳入时，结论偏乐观；三情景要显式写出各项假设。

### 9.2.6 个人 Agent 单用户经济账：月服务成本 × 12 vs 单用户广告价值，并对标 DAU/MAU 粘性

**方法要点**：测算个人 Agent“成本墙”——每个用户每月的服务成本折算成年成本，与同类平台单用户广告价值比较，检验“免费 + 广告”模式的可持续性，并用 DAU/MAU 衡量粘性是否支撑助理定位。

**操作步骤 / 拆分口径**

1. 确认成本结构：Muse 为每个用户单独配虚拟机，并承担免费与低档付费用户的 Token 成本。
2. 取成本区间：据摩根士丹利测算，按用户每天让 Agent 做 10-20 件事（含后台常驻 Agent），每用户每月总服务成本 15-37 美元（CPU 沙箱 + GPU 算力）；另一渠道专家调研估算 30-50 美元。
3. 取参考值：30 美元/月 × 12 = 360 美元/年（单人全年服务成本）。
4. 对比单用户广告价值（ARPU）：Meta 旗下 Facebook、Instagram 单用户广告价值不到 360 美元。
5. 检查收入端漏损：20 件事的 Token 用量仍在免费额度内，用户无需买付费套餐。
6. 看粘性：Muse 上线一个月 DAU/MAU 仅为 ChatGPT 水平，离真正的助理（至少看齐社交平台）有差距。
7. 结论：短期商业化是问题。

**关键指标与数据来源**：每用户月服务成本（15-37 美元 / 30-50 美元）、单用户广告价值（ARPU）、DAU/MAU、免费额度；来源为摩根士丹利测算、渠道专家调研、Meta 披露。

**判断标准**

- 经济性：年服务成本（360 美元）高于单用户广告价值（不足 360 美元），且用户用量仍落在免费额度内、不会付费，则免费 + 广告模式短期难以成立。
- 粘性：助理类产品的 DAU/MAU 至少要看齐社交平台；仅与 ChatGPT 水平相当，说明还没形成高频依赖。
- 推理链：成本墙（15-50 美元/月）> 广告变现（<30 美元/月）→ 无法靠广告覆盖；免费额度吸收了用量 → 也无付费转化 → 短期商业化是问题。

**海豚案例**

- Meta Muse《AI 入口大战 2.0：腾讯、阿里、字节，谁是 AI 办公的隐形冠军？》（2026-10-13）及《腾讯、阿里、字节：谁能坐稳 AI 办公的「工头位」？》（2026-10-14）：用 30 美元/月 × 12 = 360 美元对比 Meta 单用户广告价值不到 360 美元，并以 DAU/MAU 对标 ChatGPT，得出短期商业化是问题。

**适用场景与注意事项**

- 适用于任何免费 + 广告模式 AI 产品的可持续性检验（LTV vs 服务成本）。
- 算力成本下降会改变结论（单位 Token 成本通缩见 9.3.7）；测算对“每天 10-20 件事”的使用强度假设敏感，需做强度情景；与 9.5.11 的“边际成本不为零”逻辑相互印证。

### 9.2.7 从产品设计创新推导单位经济性（Neutron “Hungry Hippo” 整流罩）

**方法要点**：评估新产品时，把设计创新落到成本结构上，推出“设计 → 可回收部分成本占比 → 单次发射边际成本”的链条，并标出需要验证的跟踪节点。

**操作步骤 / 拆分口径**

1. 明确对标对象：Rocket Lab 的 Neutron 直接对标 Falcon 9，用于大型星座部署和深空探测。
2. 描述设计创新：整流罩“Hungry Hippo”与一级一体化，发射后像河马嘴一样张开释放二级，再随一级返回地面，提高整流罩回收效率、降低回收成本。
3. 找到结构连锁效应：二级放在整流罩内，不需要坚固的箭体结构，可以缩小尺寸，把更多重量和成本分摊到一级，提升一级回收对成本的摊薄效果。
4. 推理链：设计 → 可回收部分的成本占比上升 → 单次发射的边际成本下降。
5. 标出跟踪节点：Neutron 首飞预计 2026 年一季度，以试飞数据验证。

**关键指标与数据来源**：可回收部分成本占比、首飞时间；来源为公司技术发布与试飞数据。

**判断标准**

- 设计创新是否真正带来单位经济性，取决于“可回收部分占总成本的比例”能否提升，以及回收后的复用成本是否低于新造成本。
- 没有试飞数据验证前，推导只是潜在优势，不能当作已兑现的成本。

**海豚案例**

- 《SpaceX 的挑战者们》（2026-04-08）：Neutron 整流罩设计，推导其对可回收部分成本占比与单次发射边际成本的影响，并标出 2026 年一季度首飞节点。

**适用场景与注意事项**

- 适用于硬件产品创新评估，需有试飞数据验证。
- 竞品之间的技术方案单位成本比较，见 6.4。

**本节速查清单**

- [ ] 替代品对比是否按统一单位（元/km 或美元/英里）测算，私家车成本是否做了年行驶里程敏感性？
- [ ] 平台利润率是否用 EBITDA/GTV，并拆出司机分成、乘客激励、变现率三项？GTV 口径是否统一？
- [ ] 降本推演是否覆盖人力、车价/折旧、保险、运营效率四个杠杆，并写出“固定成本 ÷ 年有效载客里程 + 可变成本”的公式？
- [ ] 是否同步列出新增成本项（安全员、地勤、增量维保）及其配比演变路径？
- [ ] 外部乐观目标（如 0.2-0.3 美元/英里）遗漏了哪些成本项？是否给出悲观/中性/乐观三情景和各自假设？
- [ ] 终局单位成本是否与私家车成本和网约车价格同表对比？
- [ ] 免费加广告的 AI 产品：月服务成本 × 12 是否高于单用户广告价值？DAU/MAU 对标了谁？
- [ ] 产品设计创新是否落到“可回收/可摊薄部分的成本占比”上，并设置了试飞/量产验证节点？

## 9.3 收入口径、利润率与成本结构测算

> 本节导读：本节解决“一家公司（尤其是披露不完整的 AI 公司）的收入怎么拆、成本怎么拆、利润率到底有多少、谁在分这块蛋糕”的问题。分析大模型公司与云厂时，先厘清收入口径（毛/净 ARR、B/C 端拆分），再拆投入结构与会计口径，用支出/收入倍数和回本覆盖率判断规模经济与否；落到算力层面，则用单位 Token 成本、控制变量法和自研 ASIC 的 TCO，把毛利在模型商、云厂、芯片商之间的分配算清楚，最后用价格与成本的对冲解释利润率走势。单位账的另一类（平台与出行）见 9.2；定价与性价比见 9.4；融资能力见 9.6；技术方案之间的成本比较见 6.4。

### 9.3.1 收入口径与倒算：ARR 毛/净口径、B/C 端拆分、广告 CPM 与门槛追踪

**方法要点**：面对不完整披露时，先明确收入口径（毛/净），再用“总量 × 占比”倒算分部收入与增速，并用 B/C 端结构变化与广告 CPM、门槛的追踪，验证商业化路径是否走得通。

**操作步骤 / 拆分口径**

变体 A：ARR 毛/净口径与总量 × 占比倒算

1. 明确口径：整体 ARR 650 亿美元为毛口径，净口径 500 亿美元以上；要先问清是否扣除渠道分成，再比较。
2. 用占比倒算分部：B 端（API + Enterprise 订阅）占比超 60%，则 C 端约 250 亿美元（9 月底）。
3. 与前期比较得出增速：C 端较 7 月仅增长不到 40%，从而量化说明 C 端增长慢于 B 端。
4. 自检：B 端 7 月年化 200 亿美元以上、9 月底翻倍，对应约 400 亿美元以上，占 650 亿美元约 60% 以上，与占比口径互相吻合。
5. 误差提示：占比给的是“超过 60%”的下限时，倒算出的 C 端更接近上限，结论方向（C 端慢于 B 端）不变，但具体数值有误差。

变体 B：收入 B/C 端拆分（API + 企业订阅 vs C 端订阅）

1. 把收入拆成 B 端（API、Enterprise 订阅）与 C 端（个人订阅）。
2. 追踪占比的时间变化：B 端付费 7 月已超过 C 端，4 月 B 端占比还只有 40%。
3. 结合 B 端年化规模与增速（年化 200 亿美元以上，9 月底翻倍）证明 B 端 Agent 需求起量。

变体 C：广告 CPM 与门槛追踪

1. 追踪 CPM：从灰测期 60 美元/千次降至 15-25 美元，看齐成熟数字广告平台。
2. 追踪自助投放门槛：最低消费从 5 万美元降为零门槛。
3. 追踪广告规模与广告主覆盖：8 月底广告 ARR 仅 10 亿美元，已覆盖数万广告主、40 多个国家。
4. 结论：Chatbot 的付费与广告变现都很艰难。

**关键指标与数据来源**：B 端/C 端 ARR 及占比、毛/净 ARR 口径、CPM、广告最低门槛、广告 ARR、广告主数量；来源为公司披露、第三方估算与媒体报道。

**判断标准**

- B 端占比持续上升并超过 C 端，是 B 端需求起量的结构性证据；C 端 ARR 增速不到 40%，慢于 B 端。
- CPM 回落到 15-25 美元并看齐成熟平台、门槛归零，意味着广告产品从“稀缺溢价”进入“规模化铺量”，但广告 ARR 仅 10 亿美元，对整体收入贡献有限。
- 口径是前提：毛口径（650 亿美元）与净口径（500 亿美元以上）相差约 150 亿美元，直接比较会误判增速与占比。

**海豚案例**

- OpenAI《AI 入口大战 2.0：腾讯、阿里、字节，谁是 AI 办公的隐形冠军？》（2026-10-13）：B 端付费 7 月超过 C 端（4 月仅 40%），年化 200 亿美元以上、9 月底翻倍；整体 ARR 650 亿美元（毛口径；净口径 500 亿以上），B 端占比超 60%；倒算 C 端 9 月底约 250 亿美元；广告 CPM 60 美元 → 15-25 美元，门槛 5 万美元 → 零，8 月底广告 ARR 10 亿美元。
- OpenAI《(短评)AI商业化的钱从哪来》（2026-10-16，文章 id 44378894）：区分 ARR 毛/净口径（650 亿美元为毛口径，净口径 500 亿以上），用 B 端占比（超 60%）倒算 C 端约 250 亿美元，较 7 月增长不到 40%，量化说明 C 端增长慢于 B 端。

**适用场景与注意事项**

- 适用于未上市或披露有限公司的收入拆分与收入质量分析。
- 占比精度越低，倒算误差越大；毛/净口径（是否扣除渠道分成）差异必须先统一。
- 这一方法提供的是“B/C 付费力”的证据，论证框架见 9.1.2；入口层面的“补贴—养习惯—收割”逻辑见 9.5.11。

### 9.3.2 按可观测性拆解大模型投入三要素（数据 / 算法 / 算力）

**方法要点**：对报表不完整的新兴行业，先把投入要素拆成数据、算法、算力，判断哪些在报表里“看得到”，再集中量化可观测的两项（人力与算力），建立“可观测指标替代”。

**操作步骤 / 拆分口径**

1. 数据：公共语料基本已训完，2026 年转向合成数据与思维链数据；未来来源是落地场景接入、自有数据（大厂优势）和付费私有数据；涉及合规与隐私，报表不披露，先排除。
2. 算法：本质靠人才脑力，对应薪酬支出。
3. 算力：对应芯片和云服务。
4. 集中量化报表里能看到的人力与算力两项：先论证“人太贵了”是不是核心问题，再论证算力是不是核心矛盾。

**关键指标与数据来源**：薪酬支出、训练算力、推理算力；来源为公司招股书与财报。

**判断标准**

- 一个要素是否值得重点量化，取决于它在报表中是否可观测、占总支出的比重是否足够大。
- 推理链：数据不可观测先排除 → 人力占比不构成核心问题（“人太贵了？不是核心问题”）→ 算力才是核心矛盾。

**海豚案例**

- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：先排除数据，再分别论证“人太贵了？不是核心问题”和“算力是核心矛盾”。

**适用场景与注意事项**

- 适用于对报表不完整的新兴行业建立“可观测指标替代”。
- 被排除的要素（数据）仍是长期竞争力变量，只是难以用报表量化，需另用定性方法跟踪。

### 9.3.3 算力成本的会计口径：训练计研发费用，推理计营业成本

**方法要点**：按会计口径把算力成本拆为训练（研发费用）和推理（营业成本），再看固定资产规模判断算力来源，量化训练算力对总支出和亏损率的贡献。

**操作步骤 / 拆分口径**

1. 训练阶段：相当于在做出能产生经济效益的商品之前提前投入的研发，属于“沉淀支出”，计入研发费用。
2. 推理阶段：模型投入推理场景后产生的收入记为收入，推理消耗的算力是创收的直接成本，计入营业成本。
3. 看固定资产规模：固定资产极少，说明算力来自第三方云服务（轻资产），与 OpenAI 自控数据中心不同。
4. 量化：训练算力占总支出的比重，以及对亏损率的贡献。

**关键指标与数据来源**：训练算力（研发费用）、推理算力（营业成本）、固定资产、训练算力/总支出；来源为公司招股书与财报。

**判断标准**

- 训练算力占总支出过半且贡献亏损率的一半以上，说明亏损的主要来源是“沉淀的研发投入”，而不是推理本身不赚钱。
- 固定资产极少 → 轻资产、算力靠租 → 与自建数据中心的路径不同，融资与资本开支结构也不同。

**海豚案例**

- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：两家训练算力都占总支出 50% 以上，贡献了 5-10 倍亏损率中一半以上的支出，量化了“算力吸空产业链利润”的说法。

**适用场景与注意事项**

- 适用于所有 AI 模型公司及有大额研发的科技公司的报表拆解。
- 训练与推理的边界在不同公司的会计处理下可能有差异，比较前要确认科目口径。

### 9.3.4 支出/收入倍数（亏损率）趋势：规模经济还是规模不经济

**方法要点**：把成本加运营开支的总额除以当期收入，得到“支出是收入的几倍”，观察该倍数随收入扩大是收窄（互联网式规模经济）还是扩大（规模不经济）。

**操作步骤 / 拆分口径**

1. 计算：总支出（成本 + 运营开支）÷ 当期收入。
2. 看趋势：随收入扩大，倍数收窄为规模经济，扩大则为规模不经济。
3. 同时对比商业模式的毛利率：to B 约 50%，to C 刚翻正。
4. 用两家同期上市的公司做配对对比，数据更可比；这一步提出核心问题，引出后面对投入密度的拆解。

**关键指标与数据来源**：总支出/收入、毛利率、收入增速；来源为招股书与财报。

**判断标准**

- 倍数收窄：规模经济成立；倍数不降反升：规模不经济，意味着收入越大、亏损越大。
- 毛利率分化提示商业模式质量差异：to B 约 50% 优于 to C 刚翻正。

**海豚案例**

- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：2024 年两家支出约为收入的 10 倍；MiniMax 2025 年前九个月仍在 5 倍以上；智谱 2025H1 更加规模不经济；两家均以约 60 亿美元估值上市后暴涨。

**适用场景与注意事项**

- 适用于高投入期的科技公司；要结合投入的性质（一次性还是持续）来判断。
- 倍数趋势需要与 9.3.5 的回本覆盖率配合，才能区分“收入追不上投入”和“投入本身是一次性的”。

### 9.3.5 模型回本覆盖率：当年创收 ÷ 上一年训练（研发）投入

**方法要点**：基座模型按年更新，一年的训练投入换来的模型约有一年服役期，所以用当年（或当前 ARR）的创收对比上一年的训练投入，衡量模型经济性；也可前瞻反推“下一年收入要达到多少才能维持覆盖率”。

**操作步骤 / 拆分口径**

公式：模型回本覆盖率 = t 年收入（或当前 ARR）÷（t−1）年训练投入

变体 A：以研发支出近似训练投入

1. 取当年（或当前 ARR 的）直接、间接创收。
2. 取上一年研发支出作为训练投入的近似（智谱研发中约 70% 是训练和研发人员支出）。
3. 计算覆盖率并看升降。
4. 前瞻反推：要维持某个覆盖率，下一年收入需要达到多少。

变体 B：以训练算力成本为分母

1. 取 t 年收入，对比 t−1 年训练算力（或同期口径）。
2. 看覆盖率是升还是降：如果训练成本增长斜率高于收入，覆盖率会持续下降，收入跑得再快也追不上一代比一代高的模型投入。

**关键指标与数据来源**：当年收入/ARR、上年研发支出、上年训练算力、覆盖率；来源为招股书、财报与业绩会。

**判断标准**

- 覆盖率持续下降：训练投入增速快于收入，投入回收能力在恶化；覆盖率回升：规模效应开始显现。
- 覆盖率达到约 100% 附近（如 MiniMax 26H1 收入约为 25H1 研发支出的 94%），可以判断“训练回本已不是问题”。
- 前瞻判断：用季度增量外推（如 Q4 相对前三季均值的增量）推算全年收入，对比目标覆盖率所需收入。

**海豚案例**

- MiniMax（2026-03-02）：2025 年创收对 2024 年训练投入的覆盖率反而下降；按 Q4 相对前三季均值的增量推算，若每季增收 800 万美元，2026 年收入超过 1.3 亿美元，对 2025 年 2.5 亿美元研发的覆盖率才能维持约 50%。
- MiniMax（2026-08-26）：26H1 收入约为 25H1 研发支出的 94%，“训练回本已不是问题”。
- 智谱（2026-03-31）：2024 年研发 22 亿、2025 年收入 7.2 亿，只回收 33%；2025 年研发 32 亿，2026 年收入要翻倍到约 14 亿才能达到 45%；3 月 ARR 17.5 亿元人民币已可覆盖 2025 年研发的 55%。
- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：MiniMax 2024 年收入只有 2023 年训练算力的 65%；2025 年前三季度对 2024 年同期训练算力的覆盖率降到 50%；智谱 2025H1 仅 30%。

**适用场景与注意事项**

- 适用于研发投入期与收入期错开的业务：大模型、需要持续高额研发的技术公司（可类比芯片流片）、创新药、游戏。
- 要注意投入的代际周期；以研发支出代替训练投入时，含人员等非训练费用，口径比训练算力略宽。

### 9.3.6 中美模型厂成本结构拆解：算力、人才、电力、补贴，及毛利率与训练成本对比

**方法要点**：拆解中国大模型“性价比”的来源，用成本结构的绝对差额与财务对比，判断低价是否可持续，以及盈利结构拐点何时出现。

**操作步骤 / 拆分口径**

1. 算力硬件：全球统一价（中国因卡脖子采购高端芯片，溢价爆表），这一项没有成本优势。
2. 人才：中国 AI 工程师平均年薪与美国差 3-5 倍。
3. 电力：核心区电价便宜 30-50%。
4. 补贴：更多靠忍受亏损的“补贴”，由投资人与地方政府买单。
5. 用财务对比验证：2026 年 Anthropic 与 OpenAI 毛利率约 60% 上下，智谱预计 2026 年毛利率削弱到 30% 以下；若计入更重的训练成本，经营亏损差距更大，销售管理费用的低价优势难以对冲。
6. 找拐点：判断盈利结构拐点源于下半年中国高端自主芯片量产。

**关键指标与数据来源**：毛利率（A&O 约 60%、智谱 < 30%）、工程师薪酬差（3-5 倍）、电价差（30-50%）、训练成本、补贴；来源为公司披露、行业调研。

**判断标准**

- 性价比来自人才与电力的绝对差额（真实）和补贴（不可持续）两部分，补贴占比越高，低价越难持续。
- 毛利率差距（约 60% vs 30% 以下）加训练成本差距，决定中美厂商的盈利质量差。
- 推理链：算力成本无优势 → 靠人才、电力优势与补贴维持低价 → 毛利率被削弱 → 只有国产高端芯片量产降低算力成本，才可能改善盈利结构。

**海豚案例**

- 智谱/Anthropic/OpenAI《Kimi K3 时刻：中美 AI 产业链叙事要变天？》（2026-07-22）：对比 2026 年 Anthropic 与 OpenAI 毛利率约 60%、智谱预计削弱到 30% 以下，并判断拐点是下半年中国高端自主芯片量产。

**适用场景与注意事项**

- 适用于跨国同业的成本竞争力比较；补贴可持续性是关键不确定性。
- 需结合 9.4.3 对“涨价 = 成本转嫁”的识别一起使用。

### 9.3.7 单位 Token 生成成本（TCO 口径）的通缩：拆分硬件代际效率与软件编排效率

**方法要点**：用 TCO 口径（建设 Capex + 运营 Opex）测算不同芯片的每百万 Token 生成成本，并把效率提升拆成硬件与软件两部分，判断“科技通缩”下的让利与议价权。

**操作步骤 / 拆分口径**

1. 统一口径：采用 SemiAnalysis 的 TCO 口径，以 Qwen 3.5 为统一测试模型，比较每百万 Token 生成成本：GB200 NVL72 约为 H100/H200 的 1/3 到 1/4。
2. 拆硬件：以 DeepSeek R1 为例，相同工程编排下，GB300 每秒输出 Token 约为 H200 的 4 到 10 倍。
3. 拆软件与工程：以 DeepSeek V4 为例，同在 GB300 上、编排方式不同，输出效率可差 2 到 4 倍。
4. 对冲价格：GB300 单价高于 H200，但价差不超过 2 倍；性能暴涨、价格温和上涨，两者对冲后通缩占主导。
5. 结论：AI 时代芯片行业仍维持“科技通缩效应”，每代性能提升中相当大一部分被让渡给了下游。

**关键指标与数据来源**：每百万 Token 生成成本、每秒 Token 产出（tokens/s）、芯片单价比、编排效率差；来源为 SemiAnalysis 与公开 benchmark。

**判断标准**

- 性能提升倍数 > 价格上涨倍数，则单位 Token 成本下降，通缩占主导；差距越大，让渡给下游的比例越高。
- 硬件（4-10 倍）与软件编排（2-4 倍）两部分各自可观，不能把所有进步都归功于芯片。
- 推理链：芯片性能大幅提升 + 价格涨幅有限 → 单位成本通缩 → 芯片商议价权受限，下游模型商与云厂分享红利（分配见 9.3.11）。

**海豚案例**

- 《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：H100/H200、GB200、GB300 的 Token 成本对比，并分拆硬件与软件贡献。

**适用场景与注意事项**

- 适用于判断 AI 硬件的议价权和下游毛利空间。
- 局限：基于特定模型和基准，绝对值不一定代表真实生产环境；趋势与相对高低更可靠。

### 9.3.8 以“推理 Token 成本”衡量 AI 商业化瓶颈与硬件迭代价值

**方法要点**：AI 正从训练主导转向推理主导，训练需求趋稳、推理需求指数级增长，推理 Token 成本成为 AI 应用商业化的最大瓶颈；用它作为单位经济指标，把硬件升级与下游应用的盈利前景连接起来。

**操作步骤 / 拆分口径**

1. 判断主导负载：训练需求趋稳，推理需求指数级增长，所以决定产品定价和盈利能力的是推理 Token 成本。
2. 用该指标衡量硬件平台价值：Rubin 通过“六芯片全系统重构”，把推理 Token 成本降到 Blackwell 的约 1/10。
3. 找出降本的关键技术：ICMS 把 KV cache 下沉到更便宜的介质、释放 HBM 带宽用于计算，是推理成本降低 90% 的核心创新之一。
4. 把单位 Token 成本下降映射到应用端：成本下降 → 产品可降价或提升毛利 → 商业化前景改善。

**关键指标与数据来源**：单 Token 推理成本、推理吞吐（tokens/s）、能效；来源为英伟达发布会及第三方验证。

**判断标准**

- 单 Token 推理成本下降幅度（如降到约 1/10）越大，硬件代际升级的经济价值越高。
- 厂商宣称的降幅需要第三方验证，不能直接采信。

**海豚案例**

- 英伟达 Rubin《老黄解锁Rubin，AI存储又添“一把火”》（2026-01-07）：Rubin 六芯片全系统重构把推理 Token 成本降到 Blackwell 的约 1/10；ICMS 把 KV cache 下沉、释放 HBM 带宽，是降低 90% 推理成本的核心创新之一。

**适用场景与注意事项**

- 适用于评估 AI 硬件代际升级的经济价值和 AI 应用的盈利前景。
- 与 9.3.7 配合：9.3.7 给出实测口径下的通缩幅度，本方法强调其对商业化的意义。

### 9.3.9 单因素毛利敏感性：固定售价，只替换单位成本

**方法要点**：为直观说明成本通缩对利润率的影响，先做最简单的单因素测算——固定售价，只让单位成本变化，看毛利率变化，用单一变量先给出量级感。

**操作步骤 / 拆分口径**

1. 固定售价：以 Qwen 3.5 综合价格每百万 Token 1 美元为售价。
2. 只替换单位 Token 生成成本：从 H200 的约 0.2 美元降到 GB300 的约 0.05 美元。
3. 计算毛利率变化：单位 Token 毛利率提升约 15 个百分点（由 80% 到 95%）。
4. 后续用控制变量法做完整测算（见 9.3.10、9.3.11）。

**关键指标与数据来源**：售价（$/百万 Token）、单位生成成本（$/百万 Token）、毛利率。

**判断标准**

- 毛利率变化 = 成本下降额 ÷ 售价；本例成本降 0.15 美元，对应毛利率提升约 15 个百分点。
- 该数字只表示“成本单因素”的量级，不含售价下降、租价变化等其他因素。

**海豚案例**

- 《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：H200 到 GB300 的单因素测算——售价 1 美元/百万 Token 不变，成本由约 0.2 降到约 0.05 美元，毛利率提升约 15 个百分点。

**适用场景与注意事项**

- 适用于快速估算量级、对外沟通结论，但不能替代多因素模型。

### 9.3.10 控制变量纵向测算：硬件固定为 H200，看软件提效与租价上涨对 AI Lab 和云厂单 GPU 时毛利的影响

**方法要点**：固定硬件，只让时间推移带来的软件进步与租价变化发生，测算它们对 AI Lab 与云厂“单 GPU 时毛利”的影响，把多个驱动因素逐个剥离。

**操作步骤 / 拆分口径**

1. 界定口径：
   - 只测推理毛利率，即推理收入减直接算力成本，不计训练和研发；
   - 统一用 Qwen 3.5 模型，按单 GPU 每小时计算；
   - 说明绝对值未必真实，但趋势和相对高低有意义。
2. 纵向比较：硬件固定为 H200；软件进步带来 20% 以上的 Token 产出效率提升；同时 H200 租价在 2025 年 9 月后上涨约 20%。
3. 读结果：
   - AI Lab：推理毛利从 1.2 美元升到 1.4 美元，由于单位营收同步提高，毛利率变化不大；
   - 云厂：毛利从 0.8 美元升到 1.7 美元（单 GPU 时口径），毛利率从 31% 升到 38%。
4. 两点提示：
   - AI Lab 和云厂通常签长协，实际租价未必随实时价上涨；
   - 测算没有计入存储等非芯片硬件的涨价，这类涨价性能不变、纯属成本上升，会侵蚀云厂毛利。

**关键指标与数据来源**：单 GPU 时收入、成本、毛利额、毛利率；Token 产出效率提升幅度；租价涨幅。

**判断标准**

- 软件提效 + 租价上涨的叠加，使云厂毛利率提升（31% → 38%）而 AI Lab 毛利率基本不变，说明短期红利更多落在云厂一侧。
- 长协签约模式与存储等硬件涨价，是测算结果的两个下调因素。

**海豚案例**

- 《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：H200 在不同时间点的推理毛利对比——AI Lab 1.2 → 1.4 美元，云厂 0.8 → 1.7 美元，毛利率 31% → 38%。

**适用场景与注意事项**

- 适用于需要剥离多个驱动因素的利润率分析。
- 口径简化后要写明局限（只含推理、不含训练研发，不含非芯片硬件涨价，租价取实时价而非长协价）。

### 9.3.11 控制变量横向测算：同一时点比较不同芯片（B300 vs H200）的毛利分配

**方法要点**：软件技术与云租价都取最新水平，只换硬件，横向比较 B300 与 H200，量化毛利在模型商、云厂、芯片商之间如何分配，并得出议价权排序。

**操作步骤 / 拆分口径**

1. 统一软件与租价：都取最新水平。
2. 换硬件：B300 对比 H200——B300 的产出效率约为 H200 的 8 倍，单位租价却不到 H200 的 2 倍。
3. 读结果：
   - AI Lab：单 GPU 时毛利从 1.4 美元升到约 11.6 美元，毛利率从 35% 升到 69%；
   - 云厂：毛利从 1.7 美元升到 3.6 美元，毛利率从 38% 升到 42%。
4. 叠加软硬件两方面进步（GB300 对比旧技术下的 H200）：综合单位毛利从不到 2 美元升到超过 14 美元；绝大部分增量被模型商拿走，云厂只是“喝汤”，但也享受到超过 10 个百分点的毛利率提升。
5. 推出议价权排序：模型商最强，云厂次之，芯片商最弱。

**关键指标与数据来源**：各芯片的 Token 产出倍数、租价倍数、单 GPU 时毛利额与毛利率。

**判断标准**

- 产出倍数（约 8 倍）远大于租价倍数（不到 2 倍）时，增量毛利主要归“用算力生产 Token 并卖出”的一方（模型商）。
- 云厂毛利额增长（1.7 → 3.6 美元）但毛利率提升有限（38% → 42%），所以只“喝汤”；芯片商的定价空间受租价制约，议价权最弱。

**海豚案例**

- 《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：B300 与 H200 的毛利对比，AI Lab 毛利率 35% → 69%，云厂 38% → 42%；GB300 对旧技术 H200 的综合单位毛利由不到 2 美元升到超过 14 美元。

**适用场景与注意事项**

- 适合比较不同代际或不同厂商硬件的经济性。
- 与 9.3.10 配合：纵向看时间，横向看硬件，两者合起来才能说清“谁拿走了通缩红利”。

### 9.3.12 自研 ASIC（Trainium3）的 TCO 拆解：设备折旧加类固定成本，再求毛利率

**方法要点**：评估自研芯片能给云厂多带来多少利润率，先测两个关键指标——Token 生成效率与单 GPU 时 TCO，再据此计算综合毛利率。

**操作步骤 / 拆分口径 / 公式**

1. Token 生成效率：缺少实测数据时用纸面参数推算。Trn3 在 FP8 精度下算力 2.5 PFLOPs，比 H200 高约 25%，约为 B300 的 50%，推得每秒产出 2600 到 4300 个 Token，取偏下边界的 3000 tokens/s（Qwen 3.5 场景）。
2. TCO 拆为两部分：
   - 设备折旧：设备折旧 = All-in-capex（$/W）× 功耗 ÷ 5 年。SemiAnalysis 统计 Trn3 的 All-in-capex 为每瓦 17 到 19 美元，约为 GB300 的一半（海豚君判断只含设备，不含厂房），按 5 年折旧约为每 GPU 时 0.41 美元；
   - 类固定成本（库房折旧、电力、人员）：类固定成本 = $/kWh × 功耗。对近 10 款芯片的测算显示每千瓦时成本集中在 0.44 到 0.51 美元，自研芯片可定向优化，取下限，折合每 GPU 时 0.45 美元。
3. 合计：约每 GPU 时 0.86 美元，比 H200 的 1.41 美元低近 40%。
4. 求毛利率：Trn3 综合能力比 H200 高约 30% 到 40%，成本低 40%，综合毛利率（由云厂与模型商共享）高达 85%，与 B300 接近；用于中小模型推理时，近乎可以等效替代 B300。

**关键指标与数据来源**：FP8 算力（PFLOPs）、tokens/s、All-in-capex（$/W）、折旧年限（5 年）、类固定成本（$/kWh）、TCO（$/GPU 时）；来源为 SemiAnalysis 统计及海豚君测算。

**判断标准**

- 综合能力提升 + 成本下降的叠加决定毛利率：能力高 30%-40%、成本低 40%，综合毛利率达 85%，与 B300 接近，说明自研 ASIC 在中小模型推理上具备替代潜力。
- 取值保守：Token 效率取偏下边界，类固定成本取下限（因自研可优化），其余参数按统计值。

**海豚案例**

- 亚马逊 AWS《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：Trainium3 的 TCO 与毛利测算——设备折旧约 0.41 美元 + 类固定成本 0.45 美元 ≈ 0.86 美元/GPU 时，比 H200 的 1.41 美元低近 40%，综合毛利率 85%。

**适用场景与注意事项**

- 适用于评估云厂自研 ASIC 或其他 GPU 替代方案的经济性。
- 纸面参数到实际产出会有折损，取值要保守；All-in-capex 是否含厂房需要核实。

### 9.3.13 自研芯片租价情景：按竞品（H200）租价的 70% 和 80%，测算云厂与模型商的毛利分配

**方法要点**：在算出自研芯片的 TCO 与产出后，以竞品租价为锚设定折扣比例，倒推云厂与模型商的毛利，判断自研芯片的让价空间与客户迁移动力。

**操作步骤 / 拆分口径**

1. 以 H200 租价为锚，设定自研芯片租价的折扣比例（70%、80%）。
2. 倒推双方毛利：
   - 若 AWS 把 Trn3 云租价定为 H200 的 70%（尽管 Trn3 性能明显强于 H200），云厂和模型商的毛利率与 B300 情景完全一致；
   - 若定为 H200 的 80%，云厂自身毛利率可提高到约 46%，高于 B300 情景的 42%。
3. 推论：在这样的能效比下，只要 AWS 愿意在租价上让一步，就完全有能力吸引客户把推理负载迁到 Trn3 上。

**关键指标与数据来源**：相对竞品的租价比例（70%/80%）、云厂毛利率、模型商毛利率。

**判断标准**

- 租价折扣下仍能保持与 B300 相当的毛利率（70% 情景），说明有充足的让价空间；折扣更小（80%）时云厂毛利率更高（约 46%）。
- 让价空间 = 对客户的吸引力：客户在租价低于竞品、性能不输的情况下，更愿意迁移负载。

**海豚案例**

- 《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：Trn3 两档租价情景——70% 时与 B300 情景毛利率一致；80% 时云厂毛利率约 46%，高于 B300 情景的 42%。

**适用场景与注意事项**

- 适用于评估新进入者或替代产品的定价空间与竞争力。
- 与 9.3.12 衔接：先测 TCO 再做定价情景；客户实际迁移还受软件生态、可靠性等因素影响。

### 9.3.14 “模型降价 vs 算力涨价”的矛盾：利润率对冲拆解

**方法要点**：面对“下游模型在降价、上游算力在涨价”的表面矛盾，先确认成本端确实在涨，再解释降价为何不等于需求不及预期或竞争恶化，并拆解利润率如何被对冲。

**操作步骤 / 拆分口径**

1. 确认成本端在涨：
   - GPU：Ornn B200 租金指数近 30 天涨约 20%；
   - CPU：Agent 提升 CPU/GPU 配比，带来 CPU 成本增量（英特尔等提价、产能售罄）；
   - 存储：TrendForce 预计 Q4 DRAM 合约价环比 +10-15%（含 HBM +15-20%），二阶导放缓但仍在涨。
2. 解释降价不等于需求不及预期或竞争恶化，两条对冲：
   - 轻量模型与架构优化提升 GPU 有效利用率（每小时 GPU 租金在涨，但每小时吞吐量也在提高），单位 Token 成本下降，对冲利润率；
   - 产品矩阵策略：轻量模型承担获客引流、提高交互频率的作用，牺牲部分利润甚至承受亏损，来替代用户维系成本。
3. 验证：需拿到吞吐提升的实际数据来计算对冲幅度。

**关键指标与数据来源**：GPU 租金指数、CPU 价格、DRAM 合约价、每小时 GPU 吞吐、产品矩阵定位；来源为 Ornn、TrendForce 等第三方。

**判断标准**

- 单位 Token 成本 = 每小时 GPU 租金 ÷ 每小时吞吐；租金涨幅被吞吐提升覆盖时，成本下降、利润率可被对冲。
- 轻量模型亏损是否有“获客引流”的功能，是区分战略性降价与竞争性恶化的关键。

**海豚案例**

- Anthropic《(短评)Anthropic发布Claude Haiku 5.5》（2026-10-08，文章 id 44232221）：用 Ornn B200 租金指数、CPU 与 DRAM 涨价确认成本在涨，再用 GPU 有效利用率提升与产品矩阵策略解释降价不等于需求不及预期。

**适用场景与注意事项**

- 适用于判断模型厂/云厂毛利率；需拿到吞吐提升的实际数据。
- 价格追踪与周期位置方法见 5.2、5.3；存储价格上行的传导见 16.1。

**本节速查清单**

- [ ] 收入口径是毛还是净（是否扣渠道分成）？分部收入是否用“总量 × 占比”倒算并与前期比较增速？
- [ ] 报表看不到的要素（数据）是否先排除，可观测的人力与算力是否集中量化？
- [ ] 训练算力计研发、推理算力计营业成本是否分开？训练算力占总支出与亏损率的比重是多少？
- [ ] 支出/收入倍数随收入扩大是收窄还是扩大？毛利率（to B/to C）差异如何？
- [ ] 回本覆盖率（当年收入 ÷ 上年训练投入或训练算力）是升是降？下一年需要多少收入才能维持？
- [ ] 中美同业的成本差异里，真实优势（人才、电力）和补贴各占多少？毛利率差距如何？
- [ ] 单位 Token 成本通缩里，硬件代际与软件编排各自贡献多少？价差是否被性能对冲？
- [ ] 毛利测算是否先单因素给量级、再用控制变量法（纵向看时间、横向看硬件）剥离驱动因素，并写明口径局限？
- [ ] 自研芯片的 TCO 是否拆成设备折旧与类固定成本，取值是否保守？租价情景（70%/80%）下毛利如何分配？
- [ ] 模型降价与算力涨价的矛盾，是否被吞吐提升和产品矩阵策略对冲？是否有实际吞吐数据？

## 9.4 定价策略、定价权与性价比

> 本节导读：本节解决“产品卖多少钱、涨价降价意味着什么、谁在分享成本下降的红利、真正的性价比怎么量”的问题。分析大模型、云服务、SaaS 等价格频繁变动的行业时，先追踪价格、计价单位与套餐变化，判断定价权是否随能力上行，再用产品梯度、旗舰路线判断厂商的竞争策略，最后用单任务成本和多层性价比评估替代标价比较，避免被表面价格误导。大宗商品与硬件价格的追踪见 5.2；利润率的拆解见 9.3；竞争格局与追赶见第 8 章。

### 9.4.1 API/订阅价格变化、计价单位与定价失误的追踪

**方法要点**：持续跟踪模型 API 和订阅套餐的价格涨跌幅、计价方式变化与新老权益衔接，判断模型能力上行是否带来了定价权上行，以及单位算力成本下降的收益归谁。

**操作步骤 / 拆分口径**

1. 跟踪价格：模型 API 与订阅套餐的价格涨跌幅、套餐价格与额度。
2. 跟踪计价方式变化：按调用次数 → 按 Token；速率限制/无月度上限 → 按 Token 额度的套餐。
3. 跟踪新老权益如何衔接：套餐替换引发的用户反应，是定价失误的早期信号（本例 MiniMax 因替换套餐引发不满，最终永久降价 50%）。
4. 判断定价权：模型能力上行是否带来定价权上行（涨价后需求是否依然强劲，是否仍称算力不够）。
5. 结合行业单 Token 算力成本下行趋势，判断降本收益归谁：SOTA 模型商，还是夹在中间、只能以价换量的普通模型商。
6. 把轻量“价格屠夫”版本的推出视为竞争加剧的信号。

**关键指标与数据来源**：API 价格涨跌幅、套餐价格与额度、计价单位、单 Token 算力成本；来源为官方定价页、套餐公告与财报。

**判断标准**

- 涨价后需求依然旺盛（算力仍不够）说明定价权上行；涨价后被迫回调（如永久降价 50%）说明定价超出了客户接受度，属于定价失误。
- 单 Token 算力成本下降时，若自身价格不降反涨，说明在分享降本红利；若只能降价换量，说明红利被 SOTA 模型商拿走。
- 竞品推出价格更低的轻量版本，是竞争加剧、定价权受压的信号。

**海豚案例**

- MiniMax（2026-08-26）：M3 定价较 M2.7 翻倍；Coding Plan（按速率限制、无月度上限）被 Token Plan（Plus 49 元/月 = 6 亿 Token，约 12000 次调用）替代，引发不满后永久降价 50%；单 Token 算力成本下降的收益主要被 Claude 等 SOTA 模型商拿走。
- 智谱（2026-03-31）：GLM-5 发布即涨价，Turbo 后再涨，一季度 API 涨幅 83%，涨价后仍称算力不够；AutoClaw 39 元/3500 万 Token、99 元/1 亿 Token 月卡。
- 智谱（2026-08-31）：8 月底推出 GLM-5.3-Flash，价格低于 MiniMax M3，轻量低价版本成为对 MiniMax 的竞争压力信号。

**适用场景与注意事项**

- 适用于 AI 模型、云服务、SaaS。
- 价格变化要与能力变化（榜单、使用量）一起看；同一套餐的“按次”与“按 Token”口径换算后才可比（见 9.4.4）。

### 9.4.2 “勇攀高峰，沿途下蛋”：旗舰高价 + 蒸馏轻量价格战版的产品梯度策略，与“真性价比”的定义

**方法要点**：复盘厂商一年内的产品发布与定价节奏，推断其“旗舰收费、轻量获客”的梯度策略，并给出“真正性价比国模”的量化标准。

**操作步骤 / 拆分口径**

1. 梳理发布时间线：预训练基座 → 后训练强化 → 轻量“价格屠夫”版 → 下一代大参数。
2. 推断策略：用便宜的开源轻量版获客、培养 Token 使用习惯；用满血旗舰收获 API 和订阅收入。
3. 设定后续跟踪重点：旗舰定价能否稳住或上行。
4. 给出“真性价比”的标准：在 DeepSeek 式定价下仍有 50-70% 的毛利率。

**关键指标与数据来源**：发布时间线、参数量、价格、毛利率；来源为官方发布与财报。

**判断标准**

- 旗舰价格稳住或上行、轻量版负责引流，说明梯度策略有效；旗舰降价则说明竞争力不足。
- 自蒸馏能力强的厂商，可以低成本做出轻量版，对定位“极致性价比”的对手是致命威胁。
- “真性价比”不是“最便宜”，而是在极低定价下仍保有 50-70% 的毛利率。

**海豚案例**

- 智谱（2026-08-31）：产品节奏为 GLM-5（2 月，涨价 83%）→ GLM-5.2（长上下文、长任务强化学习）→ GLM-5.3（8 月中，靠后训练提升能力）→ GLM-5.3-Flash（8 月底，参数和层数减半以上并加入多模态，价格低于 MiniMax M3）→ GLM 6.0（传年底 3T）；自蒸馏能力对定位极致性价比的 MiniMax“非常致命”。

**适用场景与注意事项**

- 适用于模型、软件、芯片等存在高低端产品梯度的行业。
- 毛利率标准需要有成本数据支撑（见 9.3 的单位成本测算）；旗舰涨价能否持续取决于能力领先是否稳固。

### 9.4.3 中国模型“大参数旗舰路线”判断，及“涨价 = 成本转嫁”的识别

**方法要点**：当北美闭源轻量模型在性价比上跑赢多数同性能中国模型后，判断中国模型的应对路线，并识别其涨价是“被迫转嫁成本”还是“竞争力提升”。

**操作步骤 / 拆分口径**

1. 确认触发事件：北美闭源轻量模型首次在性价比上跑赢多数同性能中国模型。
2. 判断冲击：轻量场景的份额被 OpenAI/Anthropic 的产品矩阵压缩。
3. 推出应对：必须提升旗舰模型竞争力（头部厂商下一代旗舰均在 3 万亿参数以上），理由是 Scaling Law 未完全失效，只靠价格战活不下来。
4. 识别涨价性质：推理成本上升 → 中国模型终端涨价是被迫转嫁成本，而非竞争力提升；但涨后仍有相对性价比。
5. 分层判断影响：旗舰层级上，Haiku 5.5 不影响中国模型的性价比优势。

**关键指标与数据来源**：旗舰模型参数量、终端价格变化、相对性价比。

**判断标准**

- 涨价由成本驱动（推理成本上升被迫转嫁）与由竞争力驱动（能力领先带来定价权）要区分：前者不代表竞争力提升。
- 涨价后仍相对便宜，说明相对性价比还在。
- 价格战之外必须有旗舰路线（≥ 3 万亿参数）：这是判断中国模型厂能否保住份额的先决条件。

**海豚案例**

- 智谱/MiniMax《(短评)Anthropic发布Claude Haiku 5.5》（2026-10-08，文章 id 44232221）：轻量场景份额被 OpenAI/Anthropic 产品矩阵压缩，判断中国模型必须走大参数旗舰路线；终端涨价是被迫转嫁成本；旗舰层级 Haiku 5.5 不影响中国模型的性价比优势。

**适用场景与注意事项**

- 适用于判断 AI 厂商定价行为是由成本驱动还是由竞争力驱动。
- 与 9.4.1（价格追踪）、9.4.6（三层性价比）配合；成本端的利润率对冲见 9.3.14。

### 9.4.4 Token 取代流量成为 AI 计价锚：成本结构匹配分析

**方法要点**：论证 AI 时代为什么应以 Token 而不是流量计价——因为 Token 与 AI 的新成本结构精确匹配，并用市场规模与单位成本降幅验证商业化可行性。

**操作步骤 / 拆分口径**

1. 旧计价单位的价格通缩：移动流量从 2011 年几十元/GB 降至 2025 年不足 2 元/GB，流量变现已“白菜价”。
2. AI 时代新成本结构：算力（GPU）、存力、运力、电力的新基建成本飙升，加上模型研发与推理开支，靠流量变现覆盖不了。
3. Token 与成本结构精确匹配，是 AI 服务的计量筹码：ChatGPT 订阅本质是 Token 畅聊包，AI 陪伴设备包月也按 Token 计价。
4. 用市场规模和单位成本降幅验证商业化可行。
5. 结论：Token 与流量包互补，从可选付费走向刚需计价。

**关键指标与数据来源**：流量单价（元/GB）、日均 Token 使用量、厂商 Token 份额、推理单位成本降幅。

**判断标准**

- 计价单位应与成本结构匹配：成本随 Token 消耗而变，计价就应随 Token 而变；流量单价已经通缩，不再能覆盖新成本结构。
- 单位成本大幅下降（两年间下降 90% 以上）+ 日均 Token 使用量增长，说明按 Token 计价的商业化具备可行性。

**海豚案例**

- 字节/阿里/腾讯《(短评)Byte已老Token才是未来》（2026-01-13，文章 id 37768629）：2025H1 中国 AI 日均 Token 30trn，字节份额 49%，豆包日均 50tn；两年间推理单位成本下降 90% 以上。

**适用场景与注意事项**

- 适用于 AI 服务商业模式与计价方式分析。
- Token 口径（输入/输出/缓存）不统一，跨厂商比较需谨慎。

### 9.4.5 “单价 ≠ 性价比”：单任务成本与“智能性 × 单任务成本”二维矩阵

**方法要点**：不看 API 标价，而看完成同一任务的实际成本，再把智能性与单任务成本放进二维矩阵，判断模型是否落在综合优势区域。

**操作步骤 / 拆分口径**

1. 计算单任务成本：单任务成本（单价 × Token 效率 × 速度）——单价是每 Token 价格，Token 效率是完成任务所需的 Token 数，速度影响实际执行耗时与成本。
2. 比较单价与单任务成本的差距：
   - K3 单价约为 GPT-5.6-Sol 的一半，但 Token 使用效率偏低、推理速度偏慢，实际执行任务成本只便宜约 10%（0.95/1.04 = 91%）；
   - GPT-5.6-Sol 单价是 Fable 5 的 30%，Artificial Analysis 单任务成本指标为 Fable 5 的 38%。
3. 画“智能性 & 单任务成本”综合对比表，看是否落在绿色的综合优势区域。
4. 得出结论：K3 短期不具性价比优势，对闭源龙头短期竞争影响有限。

**关键指标与数据来源**：API 单价、Token 效率（每任务 Token 数）、输出速度、单任务成本、AA 智能评分；来源为 Artificial Analysis。

**判断标准**

- 单价低不等于性价比高：单价便宜一半但单任务成本只便宜约 10%，说明被 Token 效率与速度吃掉了大部分价格优势。
- 综合优势区域：既要有足够的智能性，又要有较低的单任务成本，两者同时满足才算真正的性价比优势。

**海豚案例**

- Kimi/OpenAI/Anthropic《Kimi K3 时刻：中美 AI 产业链叙事要变天？》（2026-07-22）：K3 单价约为 GPT-5.6-Sol 的一半、单任务成本仅便宜约 10%（0.95/1.04 = 91%）；GPT-5.6-Sol 单价是 Fable 5 的 30%，单任务成本指标为 Fable 5 的 38%。

**适用场景与注意事项**

- 适用于所有大模型/AI 服务的竞争力比较，避免被标价误导；同理可用于云算力 $/有效 FLOP 比较。
- 单任务成本依赖第三方评测的任务集，换任务类型结论可能不同。

### 9.4.6 新模型发布的“性能 - 价格 - 单任务成本”三层性价比评估

**方法要点**：评估新发布的（尤其是小）模型时，依次从性能、价格、单任务成本三层比较，并关联二级市场反应，避免只看单一层面。

**操作步骤 / 拆分口径**

1. 性能层：
   - Agent 核心能力 Computer use 任务完成率从 16% 提到 72%；
   - 知识工作 GDPval-AA 评分几乎翻倍，接近自家 Sonnet 5.5；
   - 同价位对比直接竞品 GPT 6 Luna；
   - 与中国头部 Flash 模型对比：整体智能指数打平，细分强项（Terminal-Bench 4.0 Agent 编程、HLE）与弱项（SaaS 工作流自动化）各有。
2. 价格层：按单次请求 10 万 Token 以下档位（官方称覆盖 90% 场景，超出则贵 5 倍、性价比优势消失）比较输入/输出/缓存写入/缓存读取单价；除 MiMo-V2.6 Flash 外，中国 Flash 模型都不比它便宜，但 MiMo 性能不及。
3. 单任务成本层：Token 单价降 90%，单任务成本降 75%。
4. 关联二级市场反应：智谱跌 8%、MiniMax 跌 12%。

**关键指标与数据来源**：Computer use 完成率、GDPval-AA、智能指数、Terminal-Bench、HLE、Token 单价（输入/输出/缓存）、单任务成本。

**判断标准**

- 三层要同时成立：性能提升显著、价格不被中国同类产品击穿、单任务成本有大幅下降。
- 价格分档条款会显著改变结论：10 万 Token 以内的档位覆盖 90% 场景，超出则贵 5 倍，要明确适用的场景边界。
- Token 单价降 90% 但单任务成本只降 75%，隐含完成同一任务所需的 Token 约增至原来的 2.5 倍（0.25 ÷ 0.1），所以不能把单价降幅等同于性价比提升，要以单任务成本为准。

**海豚案例**

- Anthropic/智谱/MiniMax《(短评)Anthropic发布Claude Haiku 5.5》（2026-10-08，文章 id 44232221）：按上述三层评估 Haiku 5.5——Computer use 16% → 72%；Token 单价降 90%、单任务成本降 75%；智谱跌 8%、MiniMax 跌 12%。

**适用场景与注意事项**

- 适用于大模型竞品比较；价格分档条款会显著改变结论。
- 与 9.4.5 配合：本方法是发布日快评模板，9.4.5 给出单任务成本的计算逻辑。

**本节速查清单**

- [ ] 是否跟踪了 API 与订阅的价格涨跌幅、计价单位变化、新老权益衔接？有无定价失误（被迫回调）？
- [ ] 单 Token 算力成本下降的收益归 SOTA 模型商还是被迫以价换量的普通模型商？
- [ ] 厂商是否采用“旗舰收费、轻量获客”的梯度策略？“真性价比”是否仍保有 50-70% 毛利率？
- [ ] 涨价是成本被迫转嫁还是竞争力提升？旗舰路线（参数量）是否支撑？
- [ ] 计价单位（Token vs 流量、按次 vs 按 Token）是否与成本结构匹配？Token 口径（输入/输出/缓存）是否统一？
- [ ] 比较性价比时是否用单任务成本（单价 × Token 效率 × 速度）而非标价？是否画了“智能性 × 单任务成本”矩阵？
- [ ] 新模型发布后是否依次评估性能、价格（含分档条款）、单任务成本三层，并关联市场反应？

## 9.5 入口与生态竞争

> 本节导读：本节解决“谁掌握流量与分发权、新入口能否长成超级入口、巨头的生态布局谁更完整”的问题。研究平台型公司面对技术代际切换（如 AI 取代旧交互范式）时，先给“超级入口”设定量化门槛并诊断各家的动机与位置，再用交互范式迁移、渗透率与时长饱和证明为什么要另起入口，用历史类比定义竞争的本质（分发权），然后比较实现路径、终局与垂类博弈，并用边际成本逻辑检验流量打法是否仍成立，最后落到具体的生态布局与办公 Agent 专项对比。商业模式与变现路径见 9.1，AI 入口对资本开支的拉动见第 3 章，竞争格局与份额见第 8 章，互联网平台专题见 16.8。

### 9.5.1 为“超级入口”设量化门槛：日均时长 30 分钟以上、月活 6 亿，用来解释各家对新入口的需求

**方法要点**：把移动互联网时代的超级入口定性为“大流量 + 高时长”，并给出量化门槛，逐家检验以解释它们为什么需要或为什么执着于新入口。

**操作步骤 / 拆分口径**

1. 设定门槛：日均时长 30 分钟以上、月活达到 6 亿（半数网民规模）。
2. 逐家检验：
   - 阿里：淘宝、支付宝都承担不了高时长场景，而且各有压不住的后起之秀（拼多多、微信支付），最缺自然流量，最需要新入口；
   - 百度：手机百度月活 7 亿、日均 40 分钟，符合门槛，但入口地位明显在被持续削弱，需要替补；
   - 字节和微信：几乎拥有全网用户和 100-120 分钟的日均时长，为什么还执着做新入口？
3. 由此引出下一层分析：旧交互范式疲态（见 9.5.4），以及争夺操作系统级入口（见 9.5.6）。

**关键指标与数据来源**：月活、日均使用时长、网民数；来源为第三方 App 监测数据。

**判断标准**

- 达到门槛不等于入口地位稳固：百度满足门槛但地位被削弱，说明要同时看趋势。
- 缺少自然流量或高时长场景的公司（阿里）对新入口的需求最强；已满足门槛的公司（字节、微信）做新入口则是为了应对范式迁移，而不是补流量缺口。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：以日均时长 30 分钟以上、月活 6 亿为门槛，逐家检验阿里、百度、字节、微信的入口现状与动机。

**适用场景与注意事项**

- 适用于判断平台的战略动机。门槛是海豚君自定的，使用时要说明。

### 9.5.2 用“流量积累 → 内容服务生态 → 社交沉淀”的超级入口路径给各家定位

**方法要点**：互联网巨头成为超级入口要经过流量积累、内容服务生态、社交沉淀三步；用它判断各家处在哪一步，并推演终局风险。

**操作步骤 / 拆分口径**

1. 路径设定（借用前文《火拼 AI 互联网（上篇）》）：流量积累 → 内容服务生态 → 社交沉淀。
2. 给各家定位：判断每家产品处在哪一步（以 DAU 规模、生态完整度、社交关系沉淀为衡量指标）。
3. 推演终局风险：关注谁最先完成下一步，尤其是社交沉淀。

**关键指标与数据来源**：DAU 规模、生态完整度、社交关系沉淀。

**判断标准**

- 豆包和千问都在从流量积累向内容服务生态过渡；千问在 DAU 还没到亿级时就推出融合商业服务的产品形态，像是把 Agent 本身当成获客手段；腾讯则直接从社交切入。
- 风险推演：如果豆包完善生态后开始沉淀社交关系（熟人加 AI 混聊），几乎可以说比赛就结束了。

**海豚案例**

- 腾讯（2026-01-26）：用三步路径给豆包、千问、腾讯定位，指出豆包若在生态完善后沉淀社交关系，比赛几乎就结束了。

**适用场景与注意事项**

- 适用于平台型互联网产品的竞争推演。
- 社交沉淀是路径中最难复制的一步，判断时要区分“已有社交”（腾讯）与“尝试建立社交”（豆包）。

### 9.5.3 用日均时长判断 AI 入口是“工具”还是“入口”，并参照“内容-服务-社交”路径判断赢家条件

**方法要点**：用日均时长诊断 AI 产品的用户粘性，并对照微信、抖音已经走通的升级路径，判断谁有机会成为最终赢家。

**操作步骤 / 拆分口径**

1. 看日均时长：渗透率最高的几个 AI 通用入口，日均时长都在 15 分钟以下，且没有改善的趋势；使用频率最高的豆包，人均每天也只有 10 分钟左右。
2. 做性质诊断：说明在大多数用户眼里 AI 入口仍是用完即走的工具；这和模型质量、前端产品无关，海外 AI 入口也有同样问题。
3. 检验同质化：豆包、元宝、千问、文小言的用户界面和前端功能同质化也很高。
4. 对比已成功的超级入口：
   - 微信：本质也是即时通信工具，靠内容（公众号、视频号）、服务（小程序、微信支付）、社交关系沉淀（群聊、朋友圈）拉长用户停留时间；
   - 抖音：高时长来自内容库的精准投喂，生态服务（电商、本地生活）和社交关系还在完善。
5. 得出赢家条件：谁先通过丰富后端生态（内容加服务）或增加社交属性提高用户时长、占住用户心智，谁就掌握最终赢家的主动权；现阶段还没有绝对意义上的赢家。

**关键指标与数据来源**：日均使用时长、界面同质化程度、生态与社交功能；来源为第三方监测数据。

**判断标准**

- 日均时长 < 15 分钟且无改善趋势 → 工具属性；对照超级入口门槛（30 分钟以上）仍有明显差距（见 9.5.1）。
- 用户界面和功能高度同质化 → 无差异化粘性，竞争的关键转向后端生态与社交。
- 推理链：工具属性（用完即走）→ 靠生态/社交拉长时长 → 时长提升带来心智占位 → 才可能成为入口。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：渗透率最高的 AI 通用入口日均时长都在 15 分钟以下（豆包约 10 分钟），对照微信与抖音的升级路径判断赢家条件。

**适用场景与注意事项**

- 适用于判断一个新入口能否长成超级 App。
- 时长数据来自第三方监测，口径与精度有限；还需结合 DAU 趋势验证。

### 9.5.4 用渗透率与时长饱和数据证明旧交互范式见顶，并解释“独立 App 做试验田”的风险对冲逻辑

**方法要点**：用渗透率和人均时长的饱和数据证明传统移动互联网接近天花板，AI 的出现带来增量，并解释巨头为什么要新设独立 App 做试验田。

**操作步骤 / 拆分口径**

1. 看饱和度：传统移动互联网经过 20 年发展已近乎熟透，全民渗透 80%、网民渗透 99%，人均每天约 4 小时的上网时长过去三年没有突破。
2. 看结构：短视频时长份额还在上升，但短视频已成为各 App 的标配内容形式，巨头之间的总时长分布进入新一轮稳定期。
3. 识别增量：AI 是颠覆式的新人机交互，一定程度上把疫情后转到线下的流量又拉回线上——2024 年下半年到 2025 年上半年，网民数和人均时长都出现小幅跳升。
4. 分析巨头的两难：AI 稳定性还不够，巨头既怕新入口侵蚀自己，也怕在技术不成熟时盲改旧入口、导致体验变差和用户流失。
5. 得出对冲策略：新设一个独立 App 做试验田是最佳做法。

**关键指标与数据来源**：全民/网民渗透率、人均上网时长、时长份额结构；来源为第三方监测数据。

**判断标准**

- 渗透率与人均时长几年无突破 → 存量见顶，增量只能靠新交互范式；AI 带来小幅跳升，说明新范式能创造增量。
- 独立 App 做试验田既保护旧入口，又允许 AI 快速试错，是成熟平台面对不成熟新技术的风险对冲。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：以全民渗透 80%、网民渗透 99%、人均约 4 小时三年未突破证明旧范式见顶，并解释独立 App 试验田逻辑。

**适用场景与注意事项**

- 适用于判断成熟平台面对新技术时的产品和组织策略。
- 判断“见顶”要用多年数据；AI 带来的小幅跳升是否可持续，需继续跟踪。

### 9.5.5 交互范式迁移视角：判断超级 App 为何仍需独立 AI 入口

**方法要点**：不从“旧 App 是否衰落”切入，而是先定义两代交互范式，再检验新需求能否嵌入旧产品；嵌不进去，旧 App 时长、月活再高也必须另建入口。

**操作步骤 / 拆分口径**

1. 定义两代范式：
   - 移动互联网 = “图标点击 + 被动接收”（刷视频、发消息）；
   - AI 时代 = “说句话就办事”的主动服务（比价下单、规划旅行等复杂任务）。
2. 检验新需求能否嵌入旧产品的内容流/聊天框：若嵌不进去，旧 App 时长、月活再高也必须另建入口。
3. 推理链：交互范式不兼容 → 需独立入口（豆包、元宝）+ 硬件载体（AI 手机）→ 旧 App 用 AI 做防守（微信搜一搜接 DeepSeek，避免流量流失）。
4. 写法：先用超级 App 的流量体量建立“看起来不需要”的反直觉前提，再解释“为什么仍要做”。

**关键指标与数据来源**：日均使用时长、MAU、日均打开次数；独立 AI 入口（豆包/元宝/千问）与 AI 硬件布局。

**判断标准**

- 若新需求不能嵌入旧产品的交互形态，则流量体量不构成护城河，必须另建入口。
- 旧 App 的 AI 动作是“防守”（避免流量流失），独立入口与硬件是“进攻”（抢占新范式）。

**海豚案例**

- 字节/腾讯/阿里《(短评)字节阿里腾讯疯抢AI入口》（2026-01-13，文章 id 37766735）：抖音日均时长 97 分钟、MAU 近 9.5 亿；微信月活 13 亿、日均打开 50 亿次、时长 123 分钟，仍推豆包、元宝；字节做 AI 手机整合算力 + 模型 + 场景；微信接 DeepSeek 强化搜一搜。

**适用场景与注意事项**

- 适用于平台型互联网公司面对技术代际切换时的入口之争。
- 论证偏定性，未量化独立入口对旧 App 时长的侵蚀，需配合 DAU/时长高频数据验证。

### 9.5.6 分发权历史类比：Windows → App Store → Agent，把 AI 竞争定义为 Agent 操作系统与分发权之争

**方法要点**：把 AI 入口之争放进计算平台代际的分发权演进中类比，把各家动作解读为争夺操作系统级控制权，并用“先天短板—补位”分析解释具体布局。

**操作步骤 / 拆分口径**

变体 A：历次操作系统与分发权更替（长版）

1. PC 时代：操作系统是微软，软件由微软分发和预装。
2. 互联网时代：谷歌、百度等搜索引擎分走了软件分发渠道。
3. 移动互联网时代：苹果等手机厂商承担了操作系统和大部分分发功能。
4. 之后：微信这个超级 App 的小程序生态又侵蚀了手机应用商店的分发权，某种意义上等同于底层操作系统（抖音、支付宝类似，靠主场景的用户粘性，背后连着垂类生态）。
5. 抽取规律：每一轮操作系统更替都伴随人机交互的变化——要么硬件直接变了，要么寄生其上的软件形态变了，本质上变的是触达用户的方式。
6. 类比到 AI：当内容和服务转为通过 Agent 触达用户，巨头争的就是 Agent 的操作系统与渠道分发权，任何一家都得倾全力去做。

变体 B：Windows → App Store → Agent 三段类比与“先天短板—补位”（短评版）

1. 三段类比：PC 时代微软靠 Windows 掌控软件分发，移动时代苹果靠 App Store 掌控应用分发，AI 时代的控制点是 Agent 分发权——用户获取服务可能不再依赖桌面图标，而是智能体。
2. 解读各家动作：字节 = 独立豆包 + AI 手机（握算力、模型、硬件主动权）；微信 = 在社交场景覆盖所有 AI 需求、守住生态中枢。
3. 补一层“先天短板—补位”分析：字节缺硬件入口 → 布局 AI 手机，豆包作为硬件“大脑”。
4. 结论以早期微信类比：用户一旦养成用 AI 入口办事的习惯，新入口终将成为新的流量巨无霸。

**关键指标与数据来源**：分发权归属、人机交互方式、分发控制点（OS/应用商店/Agent）、硬件入口、模型与算力自主度。

**判断标准**

- 分发权控制点的迁移是判断入口之争的主线：谁掌握触达用户的方式，谁就掌握分发权。
- 先天短板决定补位动作（字节缺硬件 → AI 手机）；用户习惯迁移是新入口成立的关键。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：变体 A 的历史回顾（微软/搜索引擎/苹果/微信小程序），类比出 Agent 操作系统与分发权之争。
- 字节/腾讯《(短评)字节阿里腾讯疯抢AI入口》（2026-01-13，文章 id 37766735）：PC-Windows、移动-App Store、AI-Agent 分发权三段类比；字节缺硬件入口 → AI 手机。

**适用场景与注意事项**

- 适合平台战略与生态位的长期定性判断；类比推理要防止过度外推。
- 类比不等于必然，需用入口 DAU、任务完成量等数据验证习惯迁移。

### 9.5.7 “软件/硬件入口 × 封闭/开放生态”二维矩阵比较实现路径

**方法要点**：对定位相同的两款产品（都是“大管家”式 AI 助理），从入口类型与生态开放度两个维度比较实现路径，并推演双方可能互相尝试对方的路径。

**操作步骤 / 拆分口径**

1. 轴一：软件入口还是硬件入口。硬件更上层、更靠近用户，逻辑上权限最高，但实际要和软件方博弈。
2. 轴二：封闭内部生态还是开放外部生态。封闭的融合更快、利益冲突更少（可以做到无跳转）；开放的理论上限更高，但需要牢固的合作关系或绝对的议价优势，海豚君认为目前完全开放不太可能。
3. 定位各家并推演：双方可能互相尝试对方的路径。

**关键指标与数据来源**：入口层级、权限、生态归属。

**判断标准**

- 硬件入口的权限高，但受软件方牵制；开放生态的上限高，但依赖议价权，现实中完全开放不太可能。
- 封闭生态（内部）融合快、冲突少，适合有丰富内部场景的公司。

**海豚案例**

- 阿里（2026-01-16）：千问 App 是软件入口加阿里内部封闭生态，豆包手机是硬件入口加外部开放生态（调用美团外卖、滴滴打车等）；推演：抖音也有较多泛消费业务，可以试封闭模式；阿里若有需要也大概率会尝试硬件入口。

**适用场景与注意事项**

- 适用于平台入口之争的路径比较。
- 开放生态策略的利弊检验见 9.5.14。

### 9.5.8 新入口的终局情景：取代现有入口，还是与现有入口共存

**方法要点**：对新形态产品做终局推演，列出“取代”与“共存”两种情景，分析选择背后牵涉的内部影响，并承认各家都在“边走边看”，不给确定答案。

**操作步骤 / 拆分口径**

1. 情景一：综合 AI 助手成为新一代万物入口、取代现有入口（搜索、社交、购物）。
2. 情景二：作为新入口与现有入口共存（但仍会抢走一部分流量）。
3. 分析选择背后牵涉的内部影响：新入口是否会取代集团现有主入口。
4. 承认不确定性：各家都在“边走边看”。

**关键指标与数据来源**：流量入口份额、内部入口关系。

**判断标准**

- 以新入口对现有入口流量的蚕食程度、集团内部入口之间的关系，判断更可能走向哪一个情景。
- 即使是依靠内部生态的公司，是否让新入口取代现有主入口，牵扯的内部影响短期内也理不清。

**海豚案例**

- 阿里（2026-01-16）：千问 App 的长期目标是取代还是共存仍在摸索；即使是依靠内部生态的阿里，是否让千问取代淘宝或支付宝成为集团最主要的入口，牵扯的影响短期内也理不清。

**适用场景与注意事项**

- 适用于平台型新产品的长期定位判断。
- 终局情景用于设置跟踪信号，而不是下定论。

### 9.5.9 垂类场景两种打法对比（独立 App 工厂 vs 原有 App 内嵌 AI 插件），并推演博弈结果

**方法要点**：比较各家在垂类场景中的打法选择，解释其背后的生态禀赋差异，并推演博弈结果与对利润率的长期影响。

**操作步骤 / 拆分口径**

1. 对比打法：
   - 字节明显选择开 App 工厂，这是它最擅长的打法；
   - 阿里也倾向开发新应用，同时两条腿走路；
   - 百度和微信偏向给传统应用加 AI 插件。
2. 解释原因：腾讯、阿里、百度都是从 PC 时代走过来的巨头，传统生态里已有垂类占位——腾讯靠内研加外投、再加小程序平台，生态最全；阿里靠一路投资延伸生态；百度虽然相对弱，但在搜索、资讯、网盘、金融等高频刚需场景都有占位。所以借 AI 夯实甚至激活原有入口的壁垒是顺理成章的。
3. 验证：QM 数据显示，到 25Q3 末 App 内 AI 插件的用户渗透率大多在 20-30%，类 Chatbot 的 AI 搜索渗透率最高。
4. 博弈推演：如果巨头都同步做 AI 赋能，竞争格局不会变，但所有垂类入口的运营成本都会上升；业绩上看似短期投入产出错配，实际上是为了保持竞争力，不得不长期牺牲变现效率做的增量投入。

**关键指标与数据来源**：AI 插件用户渗透率（20-30%）、各场景渗透排序；来源为 QM 等第三方监测数据。

**判断标准**

- 打法由生态禀赋决定：生态占位少的公司倾向新建应用（App 工厂），生态占位多的公司倾向给原有入口加 AI。
- 囚徒困境式的投入：大家都做 → 格局不变但成本上升 → 不做就落后 → 所以必须做。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：字节 App 工厂、阿里两条腿、百度与微信 AI 插件；25Q3 末 App 内 AI 插件用户渗透率大多在 20-30%，类 Chatbot 的 AI 搜索渗透率最高。

**适用场景与注意事项**

- 适用于判断 AI 投入对利润率的长期影响（囚徒困境式的投入）。
- 渗透率数据是第三方监测，注意口径；结论要与财报中的费用率、变现效率对照。

### 9.5.10 “洗牌者”逻辑：用交互方式的颠覆截流垂类入口，把垂类龙头降级成没有私域的服务提供商

**方法要点**：分析入口颠覆者的动机与路径——通过颠覆人机交互方式打破现有垄断、截流垂类入口，把垂类龙头降级为没有私域流量的“服务提供商”，并推演垂类的反制与博弈结果。

**操作步骤 / 拆分口径**

1. 识别颠覆者动机：字节在互联网时代起步较晚、现有生态布局欠缺，更有动力当洗牌者。
2. 识别颠覆路径：豆包 AI 手机把洗牌思路具体化——通过颠覆人机交互方式打破现有垄断，截流垂类入口；字节不一定亲自下场做本地生活这类脏活累活，而是把现有垂类龙头降级成完全没有私域流量的“服务提供商”。
3. 分层判断垂类受冲击程度：后端壁垒不高的垂类可以被豆包轻易换成新一批提供商；高度依赖线下供应链的垂类也会因失去流量分发权而被“刮皮剜肉”。
4. 垂类的反制手段：用用户隐私授权设卡，限制豆包读取真实的交付数据，削弱 Agent 的实际操作效果。
5. 判断博弈结果：取决于谁掌握更多用户话语权；如果有一天豆包取代微信，成为 AI 时代一超多强的全民级流量入口，垂类的坚持就没有太大意义了。

**关键指标与数据来源**：用户话语权、私域流量、垂类后端壁垒。

**判断标准**

- 垂类的受冲击程度取决于后端壁垒（可替换性）与对流量分发权的依赖；壁垒越低、对分发依赖越高，越容易被降级。
- 数据授权是双方博弈的关键筹码，需要持续观察。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：以豆包 AI 手机为例，分析字节的洗牌者逻辑，以及垂类用隐私授权设卡的反制手段。

**适用场景与注意事项**

- 适用于评估 Agent 对美团等垂类平台的冲击。
- 要持续观察数据授权上的博弈；用户话语权的归属是胜负的终局变量。

### 9.5.11 AI 入口打法变迁：算力边际成本 ≠ 0，使互联网“补贴-养习惯-收割”的纯流量打法失效

**方法要点**：对比互联网与 AI 时代的获客经济学，用边际服务成本是否为零，判断“先补贴、养习惯、再收割”的纯流量打法是否仍然成立。

**操作步骤 / 拆分口径**

1. 互联网时代：边际用户服务成本几乎为零，巨头可先补贴、养习惯、再收割。
2. AI 时代：算力成本使边际服务成本显著为正，纯流量打法至少当下不适用，巨头开始算经济账。
3. 用付费路径证明 Chatbot 商业化困难：C 端付费率低至“知识付费”水平。
4. 用广告路径证明：日均时长短，难以释放足够的广告库存。
5. 反证：任务完成导向的 Agent 反而激发企业端付费力（尤其科技公司与 IT 从业者）。

**关键指标与数据来源**：边际服务成本、付费率、日均使用时长、广告库存。

**判断标准**

- 边际服务成本显著为正时，补贴获客的每个新用户都在烧钱，必须有清晰的付费或广告回收路径。
- 付费率与广告库存是两条回收路径，两者都弱，则纯流量打法不成立。

**海豚案例**

- AI 办公《AI 入口大战 2.0：腾讯、阿里、字节，谁是 AI 办公的隐形冠军？》（2026-10-13）：对比互联网与 AI 的获客经济学，并以付费率（“知识付费”水平）与广告库存证明 Chatbot 商业化困难，而 Agent 激发企业端付费力。

**适用场景与注意事项**

- 适用于 AI 应用商业模式判断；与互联网平台经济做对照时需考虑算力成本下降曲线。
- 与 9.1.2、9.2.6 构成三角：商业化路径证据、单用户经济账、获客逻辑。

### 9.5.12 巨头 AI 生态布局对比矩阵（ToC/ToB × 软/硬 × “1+N”）与获客渠道差异

**方法要点**：用汇总矩阵对比字节、阿里、腾讯、百度的 AI 布局，维度包括模型实力、ToC/ToB 覆盖、流量渠道（内部还是外部投流）与软硬件，并归纳整体生态结构。

**操作步骤 / 拆分口径**

1. 建矩阵：把字节、阿里、腾讯、百度放进同一张汇总图，维度包括模型实力、ToC/ToB 覆盖、流量渠道（内部还是外部投流）、软硬件。
2. 逐家判断：
   - 字节：落地最快，尤其是 ToC 端，靠抖音不限量的流量曝光，软硬件都有产品；ToB 端在追赶，大模型跑分不突出，但凭垂类和性价比优势，火山引擎在 MaaS 领域影响力上升；
   - 阿里：ToB 覆盖更全，得益于大模型硬实力；下半年 ToC 明显发力（重推千问、灵光），但内部缺少抖音级别的高曝光渠道，只能外部投流加口碑传播；
   - 腾讯：原生 AI 上相对佛系——大模型一般、ToB 暂无亮点、ToC 核心在元宝，市场把希望押在还在“修炼”中的微信 Agent；买量主要在鹅系生态内部，外部投流占少数。
3. 归纳整体结构：“1+N”——一个通用入口加 N 个垂类场景。

**关键指标与数据来源**：产品矩阵、流量渠道来源、ToB MaaS 影响力。

**判断标准**

- 流量渠道（内部还是外部投流）是 ToC 落地速度的关键差异：字节靠抖音不限量曝光，阿里缺内部高曝光渠道只能投流。
- 大模型实力决定 ToB 覆盖：阿里模型硬实力强，ToB 更全；字节凭性价比和垂类在 MaaS 上追赶。

**海豚案例**

- 中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：汇总图对比字节、阿里、腾讯、百度的 AI 布局，字节落地最快、阿里 ToB 更全但缺内部高曝光渠道、腾讯原生 AI 相对佛系。

**适用场景与注意事项**

- 适用于比较多家巨头的生态布局，也为后续公司篇提供框架。
- 矩阵是静态快照，需随产品发布与投流变化更新。

### 9.5.13 生态四层布局完善度对比 + 原生 AI 办公 Agent 用户规模追踪

**方法要点**：把各 AI 办公平台的运作拆成关键四层生态布局，逐家打勾比较完善度，并追踪原生办公 Agent 平台的用户规模，同时拆分领先原因。

**操作步骤 / 拆分口径**

1. 拆四层：流量入口、底层模型、Agent/Harness 产品、行业方案/连接生态。
2. 逐家打勾：腾讯、字节、阿里都是全布局生态；智谱缺一个上亿流量的入口级产品导流，相对吃亏。
3. 追踪用户规模：腾讯 Workbuddy 暂时领先（据调研 9 月 DAU 超 600 万）。
4. 拆分领先原因：腾讯 C 端流量优势，与 HY 系列免费 Token 的性价比加持。

**关键指标与数据来源**：生态层完整度、DAU（Workbuddy 9 月超 600 万）、免费 Token 政策；来源为渠道调研。

**判断标准**

- 四层缺一层即存在短板（如智谱缺入口）；全布局生态在早期格局中占优。
- 用户规模领先需区分自然需求与补贴驱动：免费 Token 属于补贴因素，不能直接视为长期壁垒。

**海豚案例**

- 腾讯/阿里/字节/智谱《腾讯、阿里、字节：谁能坐稳 AI 办公的「工头位」？》（2026-10-14）：四层生态打勾比较；腾讯 Workbuddy 9 月 DAU 超 600 万，领先原因拆分为 C 端流量与免费 Token 性价比。

**适用场景与注意事项**

- 适用于平台型竞争的早期格局判断；用户规模领先需区分自然需求与补贴驱动。

### 9.5.14 开放生态策略利弊评估：伙伴提供 know-how 补短板，但合作非排他可被对手复用

**方法要点**：分析“我出 Agent、模型、分发，伙伴出行业数据和 know-how”的开放生态打法，评估其补短板的优势与合作非排他的弊端。

**操作步骤 / 拆分口径**

1. 梳理开放度：
   - 入口补充：Workbuddy 接入 30 多个硬件品牌，覆盖智能眼镜、录音卡、麦克风、耳机等 10+ 品类；
   - 行业 know-how：开放平台首批接入 100 多家伙伴、横跨 20 多个行业、深度合作超 30 家。
2. 判断优势场景：金融营销、零售私域等“对外”场景（企业微信直达微信用户），其 know-how 与数据为另两家所无。
3. 识别弊端：合作关系不一定排他，伙伴同样可接入钉钉、飞书。
4. 判断长期机会：C 端用户数据持续积累、个人 Agent 数据与工作 Agent 数据打通、受益于 OPC（一人公司）等单人生产力趋势；但涉及数据隔离、权限安全，更偏长期壁垒。

**关键指标与数据来源**：接入硬件品牌/品类数、生态伙伴数与行业覆盖、深度合作数。

**判断标准**

- 开放生态能否形成壁垒，关键检验是排他性：非排他则对手可复用，壁垒有限。
- 长期壁垒来自数据积累与打通，但受数据隔离、权限安全约束，需要长期观察。

**海豚案例**

- 腾讯 Workbuddy《腾讯、阿里、字节：谁能坐稳 AI 办公的「工头位」？》（2026-10-14）：接入 30 多个硬件品牌（10+ 品类）、首批 100 多家伙伴（20 多个行业，深度合作超 30 家）；优势在金融营销、零售私域等对外场景；弊端是伙伴可同样接入钉钉、飞书。

**适用场景与注意事项**

- 适用于判断平台开放策略能否形成壁垒（排他性是关键检验）。
- 与 9.5.7 的二维矩阵（开放 vs 封闭）呼应：开放的上限高、依赖议价权。

## 9.6 融资结构与资本竞赛

> 本节导读：本节解决“钱从哪里来、谁承担风险、融资成本高低是否构成竞争力”的问题。分析重资产扩张的云厂与新云、靠融资续命的模型公司，或供应商为客户融资（vendor financing）的新型安排时使用：先排出融资顺序与资本成本的差距，再拆融资平台的风险分担与关键条款，评估担保方的或有负债与动机，最后测算融资缺口并跟踪“融资耐力”淘汰赛。资本开支需求与需求可持续性见 3.1，供给方资本开支见 4.1，模型公司的商业模式本质见 9.1.6、9.1.7，行业事件的冲击与归因见 12.3。

### 9.6.1 融资啄序与资本成本比较：经营现金流 → 账上现金 → 表内债 → 表外债 → 可转债 → 增发

**方法要点**：梳理云厂支撑巨额资本开支的融资路径与顺序，用资本成本（利率、抵押品、稀释）比较新老云的融资能力，说明融资能力本身就是竞争力的一部分。

**操作步骤 / 拆分口径**

1. 排融资顺序：先用经营现金流，用完了动用账上现金，再不够才融资；融资顺序依次是表内发债、表外发债、可转债、发股，股权属性越强，成本越高。
2. 比较新老云的成本与条件：
   - 大厂：发债利率约 5%；
   - 新云（如 CoreWeave）：发债利率高达 8-9%，还要用自购的 GPU 设备或客户合同现金流做抵押；
   - Nebius：一上来就发可转债加增发，融资成本明显偏高。
3. 得出结论：这是一门资金壁垒很重的生意，大厂拿钱的成本明显低于新云，本身就是竞争力的一部分。

**关键指标与数据来源**：债券利率（约 5% vs 8-9%）、抵押品类型、融资工具结构、股权稀释比例；来源为财报附注、债券发行公告。

**判断标准**

- 融资工具越靠后（可转债、增发），说明内部造血和低成本债务越不足，成本越高。
- 需要用设备或合同现金流抵押，意味着缺乏无抵押的信用；利率 8-9% 对比 5%，利差即资金壁垒。
- 推理链：大厂融资顺序靠前、成本低 → 可以以更低成本扩张 → 与新云形成成本差距；新云靠高成本融资，在算力涨价红利之外仍受资金壁垒制约。

**海豚案例**

- 《CoreWeave、Nebius》（2026-08-13）：新老云融资成本与融资工具对比——大厂发债利率约 5%，CoreWeave 8-9% 且需 GPU 设备或客户合同现金流抵押，Nebius 直接发可转债加增发。

**适用场景与注意事项**

- 适用于重资产行业（IDC、新云、航运、电力）的竞争力比较。
- 利率与抵押信息需从财报附注获取。

### 9.6.2 拆解厂商融资平台的风险分担：残值担保比例与信用风险去向

**方法要点**：对公司联合金融机构推出的融资平台，拆清谁出资、谁承担信用风险、公司自己保留什么风险，判断其本质是“带封顶残值担保的结构化租赁/项目融资”。

**操作步骤 / 拆分口径**

1. 拆出资方：平台规模、合作金融机构。
2. 拆信用风险承担方：大头信用风险交给金融机构。
3. 拆公司保留的风险：单笔最高 25% 的残值支持，逐项目评估（项目审核机制）。
4. 定性：带封顶残值担保的结构化租赁/项目融资——公司用有限敞口换取下游客户的购买力。

**关键指标与数据来源**：平台规模、合作机构、残值担保比例、项目审核机制；来源为公司财报与业绩会披露。

**判断标准**

- 担保封顶（单笔最高 25%）意味着公司的风险敞口有限；信用风险大头在金融机构。
- 周期下行时残值风险会集中暴露：担保虽有封顶，但在行业整体下行时，多个项目的残值风险可能同时发生。

**海豚案例**

- 英伟达（2026-08-27）：与 Apollo、BlackRock、Blackstone、Brookfield、Goldman Sachs、KKR 合作推出超过 5000 亿美元的 AI 工厂融资平台，部分项目最高覆盖单笔 25% 残值，把信用风险的大头推给六家金融机构。该披露正是 9.6.3 中“待跟踪条款”（担保比例）的落地。

**适用场景与注意事项**

- 适用于供应商金融、设备租赁模式。
- 周期下行时残值风险会集中暴露；封顶比例只限制单笔，需要同时看总担保规模对毛利的占用（见 9.6.4）。

### 9.6.3 细节未披露时，类比已知交易（Meta 表外融资）拆解新融资平台结构，锁定“残值担保”关键条款

**方法要点**：事件刚发生、细节未披露时，用已知交易的结构做类比，推断新平台的大致结构，并通过“资金方本息从哪来”的推导，锁定最关键的条款，同时列出待跟踪条款。

**操作步骤 / 拆分口径**

1. 描述事件：英伟达牵头，与 Apollo、BlackRock、Blackstone、Brookfield、高盛、KKR 签署谅解备忘录，拟通过独立平台搭建 5000 亿美元融资池。
2. 类比已知交易：参照此前分析 Meta 表外融资时画的结构图，把合资公司的少数出资方换成英伟达加新云、把残值担保方从 Meta 换成英伟达，结构就大致相同。
3. 推导资金方回收来源：本息回收只有两个来源——
   - AI 工厂出租后的稳定租金；
   - 租客违约时变卖厂房设备（厂房折价不大，变化大的是 IT 设备，核心就是 GPU）。
4. 锁定关键条款：资金方要求保本，最好还有保底收益，因此必须由英伟达对 GPU 残值做担保；这是负债累累的新云自己做不到的。
5. 列出待跟踪条款：残值或项目担保比例、具体付息安排，需等英伟达财报披露。

**关键指标与数据来源**：融资池规模、担保方、担保比例、付息安排、GPU 残值；来源为公司公告、已有交易结构图。

**判断标准**

- 结构类比成立的前提是“角色可替换”：出资方、担保方、使用方的角色与已知交易一一对应。
- 资金方回收来源只有租金与处置资产两条，所以关键条款必然是对残值（尤其是 IT 设备/GPU）的担保。
- 条款披露前的推断要标明不确定性，并设置验证节点（财报披露的担保比例与付息安排）。

**海豚案例**

- 《CoreWeave、Nebius：算力涨价、干爹出手，英伟达 “干儿子” 能飒多久？》（2026-08-13）：用 Meta 表外融资结构类比推断英伟达 5000 亿美元融资平台，锁定残值担保条款，并列出待跟踪的担保比例与付息安排；两周后英伟达财报披露单笔最高 25% 残值支持（见 9.6.2），验证了“残值担保”这一判断。

**适用场景与注意事项**

- 适用于解读结构化融资、表外安排类事件。条款披露前的推断要标明不确定性。
- 事件解读的一般路径与信息甄别见 12.1、12.2。

### 9.6.4 评估担保方新增的或有负债，以及毛利能否覆盖担保敞口

**方法要点**：从担保方（英伟达）的角度，拆解新的卖法对收入质量的影响——确认收入时多了一项表外或有负债，并用毛利约束判断担保的上限与动机。

**操作步骤 / 拆分口径**

1. 对比新旧卖法：过去一颗 GPU 成本 25 美元、卖 100 美元，是干净的收入；新卖法下确认收入和利润时多了一项表外或有负债。
2. 设定约束：担保额不能穿透这笔收入里 75 美元的毛利（100 − 25 = 75）。
3. 分析动机：推理时代英伟达 GPU 的护城河在下降、云大厂普遍自研 ASIC；英伟达通过动员社会资本为新云融资，以保住 GPU 市占率、缩小新云与云大厂的成本差距，与 ASIC 算力抗衡。
4. 读取信号：英伟达敢做担保，传递出它认为通过 CUDA 和软件升级可以拉长老一代 GPU 的服役周期，即使某个数据中心经营不善，设备转卖给其他玩家也还有空间。

**关键指标与数据来源**：单位成本与售价（25 vs 100）、毛利额（75）、担保规模、GPU 服役周期。

**判断标准**

- 担保规模占毛利的比例越低，越安全；担保额一旦穿透毛利，等于以亏损方式卖货。
- 担保的合理性取决于 GPU 残值是否稳定：服役周期越长、二手市场越有流动性，担保的实际损失概率越低。
- 推理链：护城河下降 + 云大厂自研 ASIC → 需要保住市占率 → 动员外部资本为新云融资并提供有限担保 → 收入质量中出现或有负债，需要从毛利角度约束。

**海豚案例**

- 《CoreWeave、Nebius：算力涨价、干爹出手，英伟达 “干儿子” 能飒多久？》（2026-08-13）：以单颗 GPU 成本 25 美元、售价 100 美元为例，约束担保额不能穿透 75 美元毛利，并分析英伟达担保的动机与对服役周期的判断。

**适用场景与注意事项**

- 适用于评估厂商金融化或供应商融资（vendor financing）对收入质量的影响。
- 要同时看担保的“账面敞口”与“真实风险”：前者可由合同条款计算，后者取决于 GPU 残值和行业景气。

### 9.6.5 融资缺口倍数测算与“融资耐力”淘汰赛跟踪

**方法要点**：测算在当代模型创收和薪资之外，还需要贴上相当于收入几倍的融资才能给下一代模型续命，并同时跟踪行业的淘汰格局，作为生存概率的参照。

**操作步骤 / 拆分口径**

1. 测算融资缺口倍数：在当代模型创收和薪资之外，需要贴上相当于收入几倍的融资资金，才能给下一代模型续命。
2. 得出趋势结论：越做大、融资窟窿越大——这是“资本比拼”。
3. 判断融资能力的性质：融资能力本身可以是差异化生存能力（类比蔚来），但资金是双向选择，看的是核心人才、模型实力、产品落地。
4. 跟踪行业淘汰格局：记录存活玩家数及掉队者，作为生存概率的参照。

**关键指标与数据来源**：融资额/收入、估值变化、存活玩家数。

**判断标准**

- 融资缺口 / 收入的倍数越高，对外部融资的依赖越强，融资窗口一旦关闭，生存风险越大。
- 融资能力是否构成差异化优势，取决于资金方是否认可核心人才、模型实力与产品落地。
- 行业从“多”走向“少”的淘汰进度，是判断剩余玩家生存概率的参照。

**海豚案例**

- 《深扒 Minimax 与智谱：大模型，算力强度与融资耐力的绝杀？》（2026-01-27）：需要贴上高于收入 3-5 倍的融资资金；中国从百模之战走到基模五强（字节、阿里、阶跃、智谱、DeepSeek），六小龙中零一万物、百川智能已掉队；海外五虎（OpenAI、Anthropic、谷歌 Gemini、xAI、Meta Llama），Meta 已落后。

**适用场景与注意事项**

- 适用于亏损期长、靠外部融资的行业（模型、电动车、创新药）。
- 与 9.1.7（持续融资竞赛的商业模式本质）、9.3.4（支出/收入倍数）、9.3.5（回本覆盖率）相互印证。
