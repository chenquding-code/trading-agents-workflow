# 第13章 跟踪验证与研究纪律

> **本章目的**：让结论可持续更新：用交叉验证与景气指标校准判断，用情景/敏感性/跟踪信号管理不确定性，用分歧处理与叙事纠偏守住研究质量。

**本章小节**：13.1 交叉验证与景气跟踪指标｜13.2 情景、敏感性与跟踪信号设计｜13.3 分歧处理与叙事纠偏

## 13.1 交叉验证与景气跟踪指标

> 本节导读：本节解决“只看一家公司的数字不够可靠、行业判断落不了地”的问题。做法是用产业链上其他公司的财报与指引、行业增速与装机数据、龙头经营指标、同业利润率做交叉验证，再用订单指标（Book-to-Bill、Backlog 覆盖年限）和公司业绩会披露的新品节点，把行业判断变成可以逐季检查的景气指标。研究一次财报、判断行业景气是否真实、检验某个市场共识时都可以用。验证结论要与 13.2 的情景与跟踪信号配合，外部分歧的处理见 13.3；赛道专属拆解（如单车带电量）见 16.6，宏观数据的交叉验证见 14.3，下游资本开支锚见 3.1，份额追踪口径见 8.1。

### 13.1.1 用产业链其他公司的财报与电话会做交叉验证

**方法要点**：不让本公司的数据“自说自话”，而是频繁引用产业链上其他公司的财报、电话会和指引，来验证或质疑本公司的数字与管理层叙事，覆盖同业、上游、下游和龙头四类参照对象。

**操作步骤 / 拆分口径**

1. 先画出本公司在产业链中的位置，确定要对照的“参照公司”：直接竞争对手、上游供应商或同行、下游客户、行业龙头、同类公司。
2. 按五种用法分别取数、对照：
   - 用竞争对手同业务增速判断份额：本公司同一业务的增速与对手相比，高低差指向份额变化（与 13.1.3 的剪刀差同源）。
   - 用上游或同行的观点判断行业供需：引用其对短缺、紧张程度的表态。
   - 用下游客户的 Capex 判断需求：把客户资本开支当作需求的锚（与 13.1.2 配合使用）。
   - 用龙头指引作为门槛：龙头给出的季度数据和指引，是同链条公司需要“跨过”的基准线。
   - 用同类公司的股价分化推断客户偏好：同类公司股价表现的差异，反映客户更认可哪种能力。
3. 把外部数据回写到本公司的判断里：明确写出“外部数据说明了什么、本公司数据与之相符还是背离”。

**关键指标与数据来源**：同行业务增速、上下游管理层表态、龙头指引、同类公司股价表现；来源为产业链各公司的财报、电话会与指引。

**判断标准**

- 外部证据与本公司数据方向一致，判断被强化；方向相反，先质疑本公司的数据或叙事，再回头找差异来源（份额、客户结构、口径）。
- 推理链：竞争对手同业务增速（如英特尔客户端业务 -6.6%）→ 对照本公司同业务 → 判断份额变化；下游客户 Capex（Meta、微软）→ 判断需求是否持续；龙头指引（英伟达）→ 判断本公司是否跨过门槛；同类公司股价分化（AMD 与博通）→ 推断客户偏好的方向。
- 股价分化只是旁证，用来推断偏好，不替代财务数据。

**海豚案例**

- AMD（2026-02-04）：引用英特尔客户端业务 -6.6%（竞争对手同业务增速，用于判断份额），以及 Meta、微软最新财报中的 Capex（下游需求锚）。
- 戴尔（2026-02-27）：引用高通对存储短缺的判断（同行对行业供需的看法）。
- Marvell（2026-08-28）与博通（2026-06-04）：引用英伟达最新季度数据和指引（龙头指引作为门槛）。
- Marvell（2026-03-06）：对比 AMD 和博通的股价表现，推断大型云厂商更看重“规模化集群”能力，而不是单纯卖卡。

**适用场景与注意事项**

- 通用方法，前提是同时覆盖产业链上的多家公司，否则拿不到对照。
- 各公司财年、披露时点、业务口径不同，对照前先对齐（尤其是财年季度与自然季度）。
- 股价分化属于间接证据，只用来推断偏好，需与财务数据互证。

### 13.1.2 上下游交叉验证与买家财报的双重含义

**方法要点**：用下游客户的 capex 指引验证上游设备的收入节奏，用同期多家公司的指引互相印证；读大买家的财报时，把“对产业链”和“对公司自身”分开回答，避免把“利好产业链”直接等同于“利好这家公司”。

**操作步骤 / 拆分口径**

1. 上下游节奏验证：取下游客户的 capex 指引（含季度节奏，例如“前低后高”），与上游设备商的收入节奏和指引对照，看是否吻合。
2. 多家公司互证：同一时期多家公司的指引相互印证，一致则强化判断，不一致则追问差异。
3. 竞争者产能紧张判断溢出订单：当主要竞争者（或主要代工方）产能紧张时，评估是否会有订单外溢给其他供应商，并把它记为潜在机会。
4. 买家财报“双重含义”：对大买家（云厂商等）的财报，分开回答两个问题：
   - 问题一：对产业链是利好还是利空？（看 capex 是否超预期、投向哪些环节）
   - 问题二：对公司自身是利好还是利空？（看 FCF 等自身财务承受力）
5. 把两个答案分别落到对应的受益或受损环节，再对比哪一环节真正受益（例如“只有 capex 超预期”时，受益主要落在设备商）。

**关键指标与数据来源**：客户 capex 指引、设备商收入节奏、FCF。来源为下游客户与上游设备商的财报、电话会。

**判断标准**

- capex 指引节奏与设备商指引吻合，说明上游收入节奏有下游支撑；客户上调 capex，给上游提供“实打实”的支撑。
- 大买家 capex 超预期且 FCF 转负，则出现“利好产业链、不利自身”的分叉。
- 竞争者产能紧张、本公司有闲置能力，可能带来溢出订单；这是机会而非已兑现的收入。
- 推理链：下游 capex（节奏与幅度）→ 上游设备商订单与收入节奏 → 哪一环节直接受益；同时看买家 FCF → 判断买家自身的可持续性。

**海豚案例**

- 台积电《1Q26》：capex“前低后高”，与 ASML 指引吻合。
- ASML（2026-07-15）：美光上调 capex，提供实打实支撑。
- 英特尔：台积电产能紧张，可能带来溢出订单。
- 谷歌《2Q26》：财报“利好产业链”，但 FCF 转负，对自身不利。
- 台积电《26Q2》：只有 capex 超预期，主要利好 ASML。

**适用场景与注意事项**

- 适用于半导体和 AI 硬件产业链，这类链条上下游关系清晰、capex 与设备收入之间有稳定对应。
- 客户 capex 是否全部转化为上游收入，取决于投向与交付节奏，需要核对时间错配。
- “利好产业链”与“利好公司自身”必须分开写结论，尤其是买家 FCF 恶化时。
- 下游资本开支作为需求锚的系统方法见 3.1。

### 13.1.3 公司增速与行业/下游增速的剪刀差（行业 β 校验）

**方法要点**：把公司的出货、收入或销量指引增速，与下游或行业整体增速并排比较，用两者之间的“剪刀差”判断份额变化、渠道备货与客户结构，并校验公司指引是否有足够的行业 β 或份额逻辑支撑。

**操作步骤 / 拆分口径**

公式：剪刀差 = 公司增速 − 下游（行业）增速。

变体 A：出货或收入增速 vs 下游或行业增速（偏事后验证，读份额、备货、客户结构）

1. 取公司出货或收入增速，并取对应的下游增速（如新能源车销量）或行业增速，对齐期间和口径。
2. 读剪刀差：
   - 高于行业：说明份额或单位含量提升，或者有备货，三者需要区分；
   - 低于行业：往往是客户结构的问题（如大客户销量疲软、客户占比变化）。
3. 追查原因：用客户集中度（如第一大客户占比）和大客户销量等数据确认。

变体 B：销量指引增速 vs 行业整体增速（偏事前校验，给管理层指引打折）

1. 取公司全年销量指引增速，与行业整体增速（新能源车大盘、国内零售）及其预期比较。
2. 公司增速远超行业时，检查是否有足够的份额提升逻辑（新品、商业模式）支撑；没有，就打折处理，取保守假设。
3. 随行业数据更新（行业预期调整、月度零售同比）滚动修正自己的取值。
4. 行业数据还可以解释零部件公司（如激光雷达）的出货偏差：出货与行业走势背离，往往指向渗透率的变化。

**关键指标与数据来源**：公司增速、行业增速；新能源车行业销量增速预期、国内汽车零售同比（乘联会等）、公司销量指引；第一大客户占比。

**判断标准**

- 公司增速接近行业，说明主要跟随行业 β；明显高于行业，需要份额、单位含量或新品支撑，或判断为备货；明显低于行业，优先排查客户结构。
- 蔚来的推理链：行业预期仅 5%-15%，管理层指引 +40%-50% → 差距巨大且缺乏可验证的份额逻辑 → 海豚君“只能边走边看”，取保守的 +20%-30% → 随行业预期下调、国内零售转弱继续修正。
- 禾赛的推理链：国内新能源汽车销量同比 -4%，出货却超指引 → 零部件出货强于行业 → 判断渗透率仍在提升。

**海豚案例**

- 宁德时代（2026-03-09）：动力电池出货环比 +48% vs 新能源车销量 +23%，出货增速明显高于下游销量增速（需区分份额、含量提升与备货）。
- 三花智控（2026-03-23）：汽零下半年增速不足 10%，明显低于新能源车行业增速，原因是北美大客户 Q4 销量疲软；第一大客户占比从 12.62% 降到 10.90%。
- Coinbase（2026-02-13）：平台交易量环比 -8% vs 行业 -7%，仅略弱于行业。
- 蔚来（2026-03-10）：行业新能源车 2026 年预期增速仅 5%-15%，管理层指引 +40%-50%（46-49 万辆），海豚君“只能边走边看”，取 +20%-30%。
- 蔚来（2026-05-21）：行业预期下调到 5%-10%。
- 蔚来（2026-09-01）：1-7 月国内零售同比 -18%，内需承压，取 +26%-29%。
- 禾赛（2026-05-19）：一季度国内新能源汽车销量同比 -4%，但出货超指引，判断渗透率仍在提升。

**适用场景与注意事项**

- 变体 A 适用于零部件和中游制造；变体 B 适用于周期性和渗透率驱动的行业。
- 行业数据来源（乘联会、中汽协、上险量）的口径要统一，不要把批发、零售、上险混在一起比。
- “高于行业”有三种可能解释（份额、单位含量、备货），不能直接当成份额提升。
- 同源的“竞争对手同业务增速”用法见 13.1.1，份额追踪口径见 8.1。

### 13.1.4 用国内装机数据与单价季节性验证出货和价格判断

**方法要点**：用公开的行业装机或销量月度数据，判断公司出货变化是行业性还是公司性；遇到单季单价异常，先剥离季节性再判断趋势，并把行业数据当作下一年出货预测的约束。

**操作步骤 / 拆分口径**

1. 取行业装机量（如国内光伏装机同比、全球储能装机）与公司对应市场的出货对照：公司国内出货下滑，是随行业下滑（行业性），还是明显更差（公司性）。
2. 单季单价异常时，先考虑季节性（如一季度为淡季），把季节性因素剥离后，再判断价格趋势是否真实。
3. 把行业装机预期作为约束，推算公司下一年出货与单价。

**关键指标与数据来源**：国内光伏装机同比、全球储能装机、单季单价、季节性。来源为行业协会或官方月度装机数据，以及公司财报。

**判断标准**

- 公司国内出货降幅与行业装机降幅同向且幅度相近，视为行业性；明显偏离，才有理由讨论公司自身原因。
- 单价低于常规水平时，先问“有多少是淡季”；剥离季节性后仍然低，才是趋势性下行。
- 推理链：行业装机同比（-30%）→ 解释公司国内出货下滑 → 剥离季节性后的单价 → 约束全年出货与单价预测。

**海豚案例**

- 阳光电源《收入倒春寒》（2026-04-28）：一季度国内光伏装机同比 -30%，逆变器单价降至 0.16 元/W（含季节性影响），据此预测 2026 年逆变器出货 141GW、单价 0.2 元/W。

**适用场景与注意事项**

- 适用于有公开行业装机或销量月度数据的赛道。
- 判断季节性要用历史同季数据对照，不能直接拿淡季单季价格外推全年。
- 季节、基数的系统性校正见 14.1，需求侧的季节波动见 3.5。

### 13.1.5 把行业龙头的经营指标当作行业供需与消费趋势的晴雨表

**方法要点**：把行业龙头的财报当作行业边际变化的观测窗口，用龙头的 ADR、开关店结构等经营指标，反推行业的供需格局和消费趋势，并与行业数据交叉验证。

**操作步骤 / 拆分口径**

1. 读龙头价格指标（ADR/RevPAR）：龙头 ADR 转正并提速，说明头部品牌溢价能力修复，可以打消“消费降级导致酒店降价换 OCC”的担忧。
2. 读龙头供给结构：龙头主动关闭低端供给、增加中高端供给，印证行业供给从金字塔型向橄榄型演进。
3. 多家公司拼图：结合多家公司（亚朵、华住）财报，比较各档次品牌的 RevPAR 表现，发现中端及中高端品牌是 RevPAR 增长的核心，而老旧经济型酒店降价后 RevPAR 依然下滑。
4. 得出消费结论：酒旅消费结构性上移，体验升级带来的溢价远大于降价带来的客流。
5. 读连锁化率：单体酒店被淘汰，优质资产向头部集中，连锁化率提升。

**关键指标与数据来源**：龙头 ADR/RevPAR、分档次品牌开店增速、关店数、pipeline 线级、行业连锁化率。来源为龙头及同业财报。

**判断标准**

- ADR 由负转正且提速，视为头部品牌溢价修复。
- 关店集中在低端、开店集中在中高端，视为供给结构升级；开店增速在各档次品牌间的差异，反映加盟商和消费者的偏好。
- 推理链：ADR 转正 → 供需格局转变；主动消灭低端落后供给 → 供给向橄榄型演进；中高端品牌更受青睐 → 消费者关注质价比而非单纯性价比。

**海豚案例**

- 华住《华住：深蹲起跳后…》（2026-03-18）：ADR 在 Q3 首次转正、Q4 提速，判断供需格局转变；主动消灭低端落后供给，供给向橄榄型演进；全季 5.0、桔子水晶、亚朵 4.0 见野等更受加盟商和消费者青睐，得出消费者关注质价比而非单纯性价比的结论。

**适用场景与注意事项**

- 适用于集中度较高、龙头数据有代表性的行业。
- 龙头的结构调整也可能是自身战略，不一定代表行业整体，需要和行业数据交叉验证。
- 要同时看多家公司，避免单一龙头样本的偏差。

### 13.1.6 用同业利润率实际值检验行业“底层假设”

**方法要点**：对市场普遍接受的行业假设（如“AI 云的利润率会明显低于传统云”），不直接采信，而是用同业的实际利润率数据去检验，并区分假设对不同类型公司是否成立。

**操作步骤 / 拆分口径**

1. 写出被检验的共识假设：AI 云利润率会明显低于传统云。
2. 取同业实际数据：亚马逊、谷歌云的利润率趋势，CoreWeave 等新云的毛利率趋势。
3. 对照假设：判断同业数据是否支持。
4. 分群结论：区分假设对云巨头和新云分别是否成立。
5. 回到目标公司：检查目标公司是否呈现与同业相同的趋势。

**关键指标与数据来源**：同业云业务利润率、毛利率趋势。来源为各云厂商和新云公司的财报。

**判断标准**

- 同业实际数据未朝假设方向变化，该假设就需要打问号：亚马逊、谷歌云利润率并未明显下滑；CoreWeave 等新云毛利率已触底企稳甚至走高。
- 同业成立不等于目标公司成立：如果目标公司没有出现同业的趋势，就要单独解释。

**海豚案例**

- 甲骨文（2026-06-11）：该假设已有可商榷之处，但对 NeoCloud 更明显。
- 甲骨文（2026-09-11）：Oracle 没有呈现同行毛利率触底企稳的趋势。

**适用场景与注意事项**

- 适用于行业共识假设的验证。
- 同业样本的业务结构、客户合同和折旧口径不同，要先分群再比较（巨头与新云不能混在一起）。
- 同业检验的结论要回写目标公司，同业趋势不能代替公司自身数据。

### 13.1.7 用公司业绩会披露的新品收入节点与产品结构验证行业判断

**方法要点**：把行业逻辑落到公司可追踪的经营节点上，用公司业绩会披露的新品首批收入时间、爬坡阶段和产品结构占比，作为逐季检验行业判断的检查点。

**操作步骤 / 拆分口径**

1. 把行业判断翻译成公司层面的可观测事件：新品首批收入的季度、爬坡阶段。
2. 取公司对产品结构占比的指引（如某产品占整体 bit 出货的比例），记下起点和目标。
3. 识别驱动客户或项目，确认需求来源。
4. 把以上节点列成检查表，在后续每个季度对照实际披露。

**关键指标与数据来源**：新品首批收入季度、产品 bit 出货占比、客户项目进展；来源为公司业绩会。

**判断标准**

- 节点按期出现，且结构占比沿指引路径上升，说明行业逻辑得到公司层面的印证；节点延后或占比不达，说明行业逻辑兑现慢于预期。
- 推理链：行业判断（QLC 在数据湖放量）→ 公司节点（首批收入、爬坡）→ 结构占比（QLC bit 占比 20% 升至 40%）→ 驱动项目（Stargate 超大容量 QLC 在云厂商放量）。

**海豚案例**

- 闪迪《从绿叶到鲜花，AI 推理如何为 NAND“逆天改命”？》（2026-09-30）：超大容量 QLC 在 FQ4'26（即 2026 年 4-6 月）产生首批收入、FQ1'27 早期爬坡；公司指引 QLC 占整体 bit 出货比例由 2025 年约 20% 升至 2026 财年末 40%；驱动项目为 Stargate 超大容量 QLC 在云厂商放量。这些节点作为后续季度验证“QLC 在数据湖放量”逻辑的检查点。

**适用场景与注意事项**

- 适用于从行业判断向个股跟踪的衔接。
- 注意公司指引口径：财年与自然年、bit 与收入不是同一口径，不要混用。
- 检查点要写明预期的时间和数值，才能真正证伪。

### 13.1.8 订单出货比 Book-to-Bill

**方法要点**：用订单出货比验证“需求爆发”是否真实，并区分是行业层面的景气还是个别公司的现象。

**操作步骤 / 拆分口径**

公式：Book-to-Bill = 新签订单金额 / 当期确认收入金额。

1. 取公司新签订单金额与当期确认收入金额，计算 Book-to-Bill，并同时记录新签订单金额与同比。
2. 看是否持续大于 1，并看趋势。
3. 横向对比同行业几家龙头（如三巨头：西门子能源、GEV、三菱重工）。
4. 若几家龙头特征一致，结论落在行业层面的景气；若只有单个公司异常，则是个体现象。

**关键指标与数据来源**：Book-to-Bill（新签订单/收入）、新签订单金额、同比。来源为龙头公司财报与订单披露。

**判断标准**

- 持续大于 1，即需求强劲、行业处于扩张期；反向推论，持续小于 1 则说明订单补充慢于消耗。
- 三巨头横向对比：自 2024 年起新签订单创多年乃至历史新高；2025 财年西门子能源、GEV、三菱重工的订单出货比普遍升至 2 左右，三菱重工达到 3。
- 推理链：新签订单创新高 + 订单出货比普遍在 2 左右 + 多家龙头特征一致 → 行业层面景气，而不是单个公司的个体现象。

**海豚案例**

- 《AI 终极瓶颈…》（2026-04-09）：三巨头 FY2025 订单出货比约 2，三菱约 3。

**适用场景与注意事项**

- 适用于订单驱动型设备行业。
- 各公司财年口径不同，对比前需对齐。
- 订单含服务时需要剔除，否则会高估设备订单强度。
- 与 13.1.9 的 Backlog 覆盖年限配合使用：Book-to-Bill 看“新增流量”，Backlog 覆盖年限看“存量能见度”。

### 13.1.9 在手订单覆盖年限 Backlog Coverage

**方法要点**：用在手订单覆盖了几年收入，衡量未来业绩的确定性和产能的紧张程度，同时反映供给瓶颈。

**操作步骤 / 拆分口径**

公式：Backlog 覆盖年限 = 期末在手订单总额 / 年均收入。

1. 取期末在手订单（Backlog）总额与年均收入，计算覆盖年限。
2. 记录订单排产到哪一年。
3. 把覆盖年限与新签订单增速放在一起看：新签订单远超交付能力，积压会持续创新高。
4. 对产能型公司，可直接比较 Backlog 与规划产能：Backlog 是否已覆盖当年规划产能、是否开始锁定下一年。

**关键指标与数据来源**：在手订单（Backlog）、年均收入、覆盖年限、排产年份。来源为公司财报与电话会。

**判断标准**

- 覆盖年限越长，未来收入确定性越高；同时说明供给瓶颈，因为新签订单远超交付能力。
- 截至 2025 年末/2026 年初，三巨头的覆盖年限均延长到 4.5-5 年以上，订单排产到 2029-2030 年，为未来 4-5 年业绩提供高确定性。
- BE 同理：Backlog 已完全覆盖 2026 年规划产能，并部分锁定到 2027 年。
- 推理链：覆盖年限延长 → 业绩能见度高 → 同时暴露产能与交付瓶颈。

**海豚案例**

- 《AI 终极瓶颈…》（2026-04-09）：三巨头覆盖 4.5-5 年以上，订单排至 2029-2030 年。
- 《AI 电荒突围》（2026-04-14）：BE 200 亿美元 backlog 覆盖 2026 年产能。

**适用场景与注意事项**

- 适用于长交付周期行业。
- 要关注在手订单的取消风险，以及价格条款（固定价还是调价），否则覆盖年限会高估确定性。
- 年均收入的口径要稳定（是否含服务、是否按财年），否则覆盖年限不可比。

### 13.1.10 用行业融资余额、期权结构与加密市场规模判断交易降温

**方法要点**：评估券商交易收入前，先用行业层面的高频数据判断市场情绪冷暖，再对比公司自身表现，判断公司相对行业是更稳健还是更脆弱。

**操作步骤 / 拆分口径**

1. 行业融资余额：看环比增速与逐月绝对值，它最能反映散户情绪。
2. 衍生品总量与结构：看股票期权占比与股指期权（机构对冲）的变化。股票期权占比逐月下滑、股指期权暴增，说明风险偏好下降。
3. 加密市场：看交易量与总市值。
4. 对比公司自身表现（如 DATs、活跃账户是否新高）：若行业情绪降温而公司指标仍在新高，得出公司相对稳健的结论。

**关键指标与数据来源**：行业融资余额（月度）、期权交易量及结构、加密市场交易量与总市值。来源为行业月度统计与交易所数据。

**判断标准**

- 融资余额环比增速放缓且逐月下降，说明散户加杠杆意愿减弱。
- 股票期权占比下滑、股指期权暴增，说明风险偏好下降、机构转向对冲。
- 加密市场规模萎缩，说明相关交易收入的行业环境转弱。
- 推理链：行业情绪降温（融资、期权结构、加密）→ 预期交易收入承压 → 对比公司活跃账户等自身指标 → 判断公司相对稳健与否。

**海豚案例**

- 嘉信《嘉信理财：内生增长稳健…》（2026-04-16）：Q1 融资余额环比增速明显放缓且逐月下降；股票期权占比逐月下滑，股指期权暴增；加密市场规模从 3 万亿出头一度萎缩至不足 2.2 万亿；相比之下嘉信活跃账户创新高，得出公司相对稳健的结论。

**适用场景与注意事项**

- 适用于券商、交易所的季度业绩前瞻。
- 行业情绪高频数据是先行指标，不能直接换算为公司收入，需要再对照公司的客户结构与收入结构。
- 宏观层面的高频数据交叉验证见 14.3。

**本节速查清单**

- [ ] 是否同时引用了产业链上下游与同业多家公司的财报、电话会和指引来验证本公司数据？

- [ ] 公司增速与行业或下游增速的剪刀差是否算出，并区分了份额、含量、备货和客户结构？
- [ ] 管理层指引明显高于行业时，是否有份额逻辑支撑，否则是否已打折取保守假设？
- [ ] 行业数据口径（乘联会、中汽协、上险量、装机数据）是否统一，单季价格是否剥离了季节性？

## 13.2 情景、敏感性与跟踪信号设计

> 本节导读：本节是通用的建模纪律，回答“结论有多脆弱、什么情况下会变、怎么知道它在变”。做测算型或供需型研究时，先用 ±10% 弹性测试找出最敏感的变量，再列出供给（或需求）上下行风险清单；技术路线不确定时，用单一关键变量划分多情景，推导价值流向，并配上可观测的领先跟踪信号和确定性排序；模型被质疑时，公开下调假设并重算。本节只收通用方法，具体领域的情景测算归各自章节：需求情景见第 3 章，TAM 情景见 7.2，毛利与单位成本情景见 9.2、9.3。本节的跟踪信号要与 13.1 的景气指标配合，对外部质疑的回应见 13.3。

### 13.2.1 最敏感驱动变量 ±10% 对供需比的弹性测试

**方法要点**：在供需测算里找出结果对哪个驱动变量最敏感，对该变量做 ±10% 的扰动，把供需比的变化量写进结论，提示结论对这个变量有多依赖。

**操作步骤 / 拆分口径**

1. 列出供需测算模型的各个驱动变量，识别出对结果最敏感的一环（如 HBM 是对 AI 出货最敏感的一环）。
2. 对该变量做 ±10% 扰动（如 2027 年 XPU 出货 ±10%），重算供需比。
3. 记录弹性：变量每变动 10%，供需比变动多少；并给出上下两端的结论（过剩还是缺口、幅度多大）。
4. 把弹性写成“逻辑依赖”：提示价格逻辑高度依赖这个变量，并在结论后附上敏感性区间。

**关键指标与数据来源**：XPU 出货、HBM 供需比。

**判断标准**

- 以 2027 年 XPU 出货为扰动变量：出货每变动 10%，HBM 供需比变动约 0.1。
- 若出货减少一成，HBM 转为约 4% 的过剩；若出货多一成，缺口扩大到约 17%。
- 推理链：HBM 供需比对 XPU 出货的弹性大 → 涨价逻辑高度依赖 AI 芯片出货 → 结论必须附敏感性区间，而不是给单点判断。

**海豚案例**

- 《海力士：超级 AI 加持，存储神话还能牛多久？》（2026-10-08，第 2.3b 节）：对 2027 年 XPU 出货做 ±10% 弹性测试，得出 HBM 供需比变动约 0.1、出货减一成转为约 4% 过剩、多一成缺口扩大到约 17%，提示 HBM 涨价逻辑高度依赖 AI 芯片出货。

**适用场景与注意事项**

- 适用于需求集中于单一驱动的预测；结论应附敏感性区间。
- 先选最敏感的变量，再做扰动，别平均对每个变量都做；敏感性结果要和后文情景、跟踪信号（13.2.3、13.2.4）对应。
- 供需平衡表本身的构建见 5.1，存储赛道的具体拆解见 16.1。

### 13.2.2 供给侧上下行风险清单：迁移提速、产能提前释放、高耗产能产品导入

**方法要点**：在基准供给之外，把会让供给偏离基准的具体变量逐一列出，分成“供给多于预期”和“供给被收紧”两类，作为供需情景分析的敏感性因子。

**操作步骤 / 拆分口径**

1. 先固定基准供给（各厂商产能与出货的基准路径）。
2. 列上行风险（供给多于预期），每项写明变量、时间、幅度：
   - 新进入者或二线厂商产能提前释放：如长江存储产能提前释放。
   - 技术迁移提速带来的单片产出抬升：铠侠 + 闪迪仍有 80% 的位元在 192 层以下，BiCS8（218 层）向 BiCS10（332 层，位密度 +59%，2026 年 7 月送样，预计 2027 年中到下半年量产）的迁移一旦提速，单片产出会直接抬升。
   - 三星 V9（286 层）跨到 V10（约 400 层），2027 年起进入 600 层以上。
3. 列下行风险（供给被收紧）：面向 AI 推理 Staging 场景的 pSLC/SLC 产品若在 2027—2028 年大规模量产，消耗的产能是普通 SSD 的三倍。
4. 比较各家的迁移空间差异：低层数产出占比越高的厂商，迁移弹性越大。
5. 把各项风险折入乐观、基准、悲观情景，并给出触发条件和时间。

**关键指标与数据来源**：各厂层数迁移进度、低层数产出占比、送样与量产时间、pSLC/SLC 产能消耗倍数。

**判断标准**

- 低层数产能占比越高，迁移一旦提速，单片产出抬升越大，该厂商的供给弹性越大。
- 高耗产能产品导入越早，等效有效供给越少。
- 推理链：迁移空间（80% 位元在 192 层以下）→ 迁移提速的产出弹性 → 判断“铠侠 + 闪迪迁移弹性最大”；pSLC 消耗产能是普通 SSD 的三倍 → 供给收紧变量，写进乐观情景。

**海豚案例**

- 闪迪《AI 改不了“DNA”…》（2026-10-06）：基于各厂迁移空间差异判断“铠侠 + 闪迪迁移弹性最大”，同时把 pSLC 作为供给收紧的变量写进乐观情景。

**适用场景与注意事项**

- 适用于做供需情景分析时设定敏感性因子。
- 清单的结构（上行、下行、变量、时间、倍数）同样可以套用到需求侧。
- 每个风险项必须有可观测的时间点和倍数，否则无法进入模型，也无法追踪。
- 有效供给与产能分配的测算见 4.3，扩产追踪见 4.2。

### 13.2.3 以单一关键变量划分三情景：推导技术路径、卡点、价值流向、受益者与周期性

**方法要点**：把复杂的产业问题收敛到一个核心变量（缺容量还是缺带宽），据此划分三种情景，并对每种情景推导技术路径、卡点、价值流向、受益者和周期性，用于技术路线不确定时判断产业链价值分配。

**操作步骤 / 拆分口径**

1. 收敛核心变量：把问题收敛为“卡容量还是卡带宽”这一单一变量。
2. 设定三种情景：容量主导、带宽主导、容量与带宽双告急。
3. 对每个情景依次回答五个问题：技术路径是什么，卡点在哪，价值流向谁，受益者是谁，周期性强弱如何。
4. 明确三种情景并非互斥：训练和前沿推理更吃带宽，大规模 Agent 推理更吃容量，现实中多半并存，区别在于哪种占主导。
5. 配合 13.2.4 的跟踪信号，动态调整各情景权重。

**情景展开**

- 情景一，容量主导（参数平稳，增长来自用户数、上下文和 Agent 执行场景）：
  - 技术路径：单颗 HBM 的层数和带宽无需大升，新增容量由后排内存、常规 DDR 和 HBF 承接，分层架构更快落地。
  - 卡点：工艺不再是主要矛盾。
  - 价值流向：存储回到大宗商品逻辑，价格由供需决定；2027 年后新增产能释放、工艺成熟，单位成本和价格逐步下行。
  - 受益者：产能规模大、成本控制好的厂商，以及承接新增容量的 NAND 产业链（HBF、企业级 SSD）。
  - 周期性：这是最“周期”的情景；各家（包括长鑫等新进入者）产能集中释放时价格压力最大，超额利润最难维持。
- 情景二，带宽成为主要瓶颈（参数继续大步提升、速度要求更高）：
  - 技术路径：层数未必上升，甚至“降层多颗”；竞争焦点从堆叠转向 Base Die 信号速率、中介层布线和 3D 封装。
  - 卡点：落在台积电 CoWoS 和先进制程 Base Die 产能。
  - 价值流向：存储系统总成本和稀缺性继续走高，但稀缺溢价更多被封装和代工拿走；HBM 更定制化，内存厂更像“颗粒供应商”，对大客户依赖更深。
  - 受益者：受益最多的是台积电；内存厂里能提供 Base Die 加封装“一条龙”的主要是三星。
- 情景三，容量和带宽双双告急（参数从 10T 量级迈向 100T 量级，同时用户和上下文持续扩张）：
  - 技术路径：所有路径同时推进。
  - 卡点：DRAM 晶圆（扩产最慢）成为最硬的卡点。
  - 价值流向：内存稀缺性和价格提升最大，内存厂和封装厂价值都提升；内存厂的议价权高于情景二，因为高层数堆叠的良率和键合工艺由内存厂把控。
  - 周期性：呈现内存超级周期，DRAM 晶圆与封装产能同时吃紧，内存厂分量最重。

**三情景对照**

| 情景 | 触发条件 | 卡点 | 价值流向与受益者 | 周期性 |
| --- | --- | --- | --- | --- |
| 一、容量主导 | 参数平稳，增长来自用户数、上下文、Agent 场景 | 工艺不再是主要矛盾 | 回归大宗商品逻辑；产能规模大、成本低的厂商，HBF、企业级 SSD | 最“周期”，产能集中释放时价格压力最大 |
| 二、带宽主导 | 参数继续大步提升、速度要求更高 | CoWoS、先进制程 Base Die 产能 | 溢价被封装与代工拿走，台积电受益最多；三星有“一条龙”能力；内存厂更像颗粒供应商 | 存储稀缺性和总成本走高，内存厂依赖大客户 |
| 三、双告急 | 参数 10T 向 100T 迈进，用户与上下文扩张 | DRAM 晶圆最硬，封装同时吃紧 | 内存厂与封装厂价值都提升，内存厂议价权高于情景二 | 内存超级周期 |

**关键指标与数据来源**：模型参数规模、用户与上下文增速、HBM 层数与颗数、CoWoS 与 DRAM 晶圆产能、存储价格。

**判断标准**

- 价值流向的推理逻辑：谁掌握卡点，稀缺溢价就流向谁（卡点在 CoWoS，溢价流向台积电；卡点在 DRAM 晶圆，溢价留在内存厂）。
- 容量需求提升的确定性最高（用户、用量和 Agent 场景渗透率大概率持续走高），关键看大模型参数规模的提升斜率，它决定带宽压力。
- 三种情景的权重不是一次定死，随跟踪信号（见 13.2.4）更新。

**海豚案例**

- 《从 HBM 限高到 NAND 加量，英伟达 vs 存力到底谁拿捏谁？》（2026-09-29）：以“容量主导 / 带宽主导 / 双告急”三情景推导技术路径、卡点、价值流向、受益者和周期性，海豚君判断容量需求提升是最高确定性，关键看大模型参数规模的提升斜率。
- 《(短评)存力这局怎么收场》（2026-10-09）：把存力终局收敛到“缺容量还是缺带宽”一个变量。卡容量：模型参数不再猛增，需求主要来自用户变多、上下文变长，后排内存、普通 DDR、HBF 就能补上，存储回归大宗商品逻辑，拼产能与成本，也最“周期”，产能一放量价格压力最大；卡带宽：参数继续大步提升、速度要求更高，竞争焦点从堆内存转向封装和基底层工艺，话语权外溢到台积电，内存厂更像颗粒供应商；双双告急：内存超级周期，DRAM 晶圆与封装产能同时吃紧，内存厂分量最重。现实中三者并存，区别在于谁主导。

**适用场景与注意事项**

- 适用于技术路线不确定时判断产业链价值分配、行业终局与受益环节判断。
- 可迁移到其他“瓶颈在哪”的产业问题：先找出单一关键变量，再逐情景推导五个问题。
- 需要配合跟踪信号动态调整各情景权重。
- 供给瓶颈与约束切换的一般方法见 4.4，产业链利润分配见 2.4，技术终局见 6.6，存储赛道要点见 16.1。

### 13.2.4 为情景判断设置可观测的领先跟踪信号清单，并给出确定性排序

**方法要点**：情景分析之后，明确后续要盯的几个可观测领先信号，并给出各判断的确定性排序，让情景权重可以随数据更新，而不是停留在叙事。

**操作步骤 / 拆分口径**

1. 针对每个情景，找出“发生时最先出现、最容易观测”的信号。
2. 写成清单，每个信号注明观测对象和更新频率。
3. 给判断排序：哪个判断确定性最高，哪个依赖于外生变量。
4. 把信号与情景的对应关系写清，信号出现时直接调整情景权重。

**跟踪信号清单**

1. 英伟达、AMD 及各家 ASIC 新品最终采用的 HBM 层数和颗数。
2. HBM4E 的实际运行速率，以及 HBM5 位宽翻倍的落地节奏。
3. CoWoS 与 DRAM 晶圆产能的相对扩张速度。
4. HBF 在 2027 年前后的首批导入情况。

信号与情景的对应关系（由三情景的定义推出）：层数与颗数、HBM 速率和位宽，用来判断带宽压力；CoWoS 与 DRAM 晶圆谁先紧，用来区分卡点落在封装（情景二）还是 DRAM 晶圆（情景三）；HBF 的首批导入，用来判断容量是否由 NAND 承接（情景一）。

**关键指标与数据来源**：新品 HBM 配置、HBM 速率与位宽、两类产能的扩张速度、HBF 导入进度。

**判断标准**

- 确定性排序：容量需求提升确定性最高（用户、用量和 Agent 场景渗透率大概率持续走高）；带宽要求取决于大模型参数规模的提升斜率，确定性次之。
- 信号必须可观测、可定期更新，否则不构成跟踪信号。

**海豚案例**

- 《从 HBM 限高到 NAND 加量，英伟达 vs 存力到底谁拿捏谁？》（2026-09-29）：情景分析后给出四个跟踪信号（新品 HBM 层数和颗数、HBM4E 速率与 HBM5 位宽、CoWoS 与 DRAM 晶圆相对扩张速度、HBF 首批导入），并给出“容量需求确定性最高、带宽取决于参数规模提升斜率”的排序。
- 《(短评)存力这局怎么收场》（2026-10-09）：同样以“新品 HBM 的层数与颗数、HBM4E 实际速率、CoWoS 与 DRAM 晶圆的相对扩产节奏、HBF 首批导入”作为跟踪信号清单。

**适用场景与注意事项**

- 适用于任何情景分析的落地。
- 信号必须可观测、可定期更新；不可观测的“感觉”不进清单。
- 公司层面的节点式检查点（新品首批收入、产品结构占比）的写法见 13.1.7。

### 13.2.5 自我修正：下调关键假设后重算，并公开倍数变化（3 倍到 2 倍）

**方法要点**：在回应外部观点的同时，也修正自己的假设：公式不变，只改假设，每项假设的变化和来源都列出来，并给出新旧倍数对比，让读者可以跟踪。

**操作步骤 / 拆分口径**

1. 保持原公式不变（A + B + C 结构不动）。
2. 逐项复盘关键假设，找出参照错误或过于激进的项，并写明原来的取值来源。
3. 列出假设修正表：

   | 假设 | 原值 | 修正值 | 说明 |
   | --- | --- | --- | --- |
   | 每个任务沙箱的核数 | 4 | 1.5 | 原来的 4 参照的是 NemoClaw 的配额上限 |
   | 中性并发率 | 100% | 150% | 即每个活跃用户平均 1.5 个任务 |
   | CPU 机架占比 | 25% | 15% | CPU 机架和 GPU 机架都按 200kW，对应 1GW 配套 |
   | 超售比 | 6 | 4 | — |

4. 重算并公开结果：
   - A = 30.6 万颗 GPU × 60 ≈ 1,836 万核；
   - B = 1 亿 × 30% × 3/24 × 2 × 2 ÷ 4 ÷ 2 ≈ 188 万核；
   - C ≈ 1,688 万核；
   - 合计 3,712 万核，约为纯 GPU 机架方案的 2 倍。
5. 补足遗漏需求再复核：再算上存储机架 DPU 等需求，预估 Agentic CPU 带动的核数需求仍在 2 倍以上，远高于对方的预测。
6. 给出新旧倍数对比（约 3 倍下调到 2 倍以上），明确哪一步变化最大。

**关键指标与数据来源**：每沙箱核数、并发率、CPU 机架占比、超售比、需求倍数。

**判断标准**

- 修正后的结论仍要能站得住：重算后的需求倍数仍显著高于对方预测，说明修正没有推翻核心判断。
- 好的自我修正：公式不变、只调假设，每项变化有来源，新旧倍数并排展示；差的做法是悄悄换口径或只报新结论。
- 推理链：外部质疑 → 逐项复盘假设 → 下调过高的假设（核数、CPU 机架占比、超售比）、上调被低估的假设（并发率）→ 重算合计 3,712 万核 → 倍数由约 3 倍降到 2 倍以上，结论方向不变。

**海豚案例**

- Muse/DSec《拿 DSec 来套？Muse 如何真正撬动 CPU 需求》（2026-09-29）：在反驳外部测算的同时，海豚君把每沙箱核数从 4 下调到 1.5、并发率从 100% 上调到 150%、CPU 机架占比从 25% 下调到 15%、超售比从 6 改为 4；重算后合计 3,712 万核，Agentic CPU 带动的核数需求从约 3 倍下调到 2 倍以上。

**适用场景与注意事项**

- 适用于测算型研究的迭代。保持公式不变、只调假设，读者容易跟踪。
- 修正假设时要同时检查“下调”与“上调”，避免只往一个方向调。
- 对外部测算的反驳与参照物检验见 13.3.1、13.3.2（同一篇文章中的对应部分）。

## 13.3 分歧处理与叙事纠偏

> 本节导读：本节解决“外部有不同测算或市场出现恐慌叙事时，怎么回应才站得住”的问题。遇到外部测算与自己结论冲突，用“公式并排、逐项找漏项”和“检验参照物是否同质”两步回应；遇到“效率提升”或“技术减配”引发的上游恐慌，用“单位需求不等于整体需求”和“单位通缩不改总量通胀”回到需求第一性原理。使用前提是自己的公式公开、能量化总需求。本节与 13.2.5 的自我修正配合（反驳别人的同时修正自己），与 13.1 的同业与上下游交叉验证配合（用事实而非立场回应）；需求侧效率提升与弹性的系统分析见 3.5。

### 13.3.1 反驳外部测算：双方公式并排列出，逐项找漏项和没拆开的项

**方法要点**：面对市场上的不同测算，不比结论大小，而是把对方的公式与自己的公式并排列出，逐项对照覆盖范围，找出对方的漏项和没拆开的项，从而说明差异来自哪里。

**操作步骤 / 拆分口径**

1. 复述对方的观点和公式。例：X 上 Freda 认为，基准情形下服务 1 亿 DAU 需要 1GW 电力，其中只有约 0.1GW 来自 CPU/VM 层，3-4GW 取决于每个 DAU 每天的推理调用次数。
2. 把双方公式并排列出：
   - 对方：CPU 核数 = DAU × (活跃时长 / 24) × 峰均比 × 冗余系数 × 每个 live VM 的物理核数；
   - 自己：A + B + C（A 为头节点，B 为用户侧固定层，C 为 Agent 侧弹性层）。
3. 逐项对照覆盖范围，标出对方缺哪几项，哪些项没有拆开。
4. 区分合理的口径差异和真正的漏项：对方没有算 A（头节点），可以理解，因为它本来就不算 Agent 增量；真正的问题是对方没有把用户侧（B 固定层）和 Agent 侧（C 弹性层）拆开，而是用一个“每 live VM 物理核数”统一设定。
5. 给出结论：对方实际上只算了 C 的一部分。

**关键指标与数据来源**：公式各项及其覆盖范围。

**判断标准**

- 衡量分歧的标准是公式的覆盖范围，而不是谁的结论更大；差异应能归因到具体的漏项或未拆项。
- 推理链：并排列公式 → 逐项核对覆盖范围 → 区分可理解的缺项（A）与实质性的未拆项（B、C 合并）→ 对方只覆盖 C 的一部分，结论不可直接与自己的总量比较。

**海豚案例**

- Muse/DSec《拿 DSec 来套？Muse 如何真正撬动 CPU 需求》（2026-09-29）：将 Freda 的 CPU 核数公式与海豚君的 A + B + C 公式并排对比，指出对方没有算 A、没有把 B 固定层与 C 弹性层拆开，实际只算了 C 的一部分。

**适用场景与注意事项**

- 适用于回应市场上的分歧观点。
- 前提是自己的公式是公开的、方便对照；否则并排对比无从谈起。
- 先承认对方公式中合理的部分（如不算 A 是口径选择），再指出实质漏项，更有说服力。
- 对方公式拆得对，还要看参照物是否可比，见 13.3.2；反驳时也要同步检查自己的假设，见 13.2.5。

### 13.3.2 检验参照物是否适用：统计口径、数据性质与负载构成

**方法要点**：对类比测算，不只看公式，更要检验参照物本身是否同质：参照数据的统计口径（沙箱还是用户）、数据性质（演示上限还是生产实测）、负载构成（跑什么样的工作）是否与被推算对象一致。

**操作步骤 / 拆分口径**

对方的推算：参照 DeepSeek 的 DSec，188 个物理核/节点 ÷ 800 个 microVM/节点 = 每 live VM 0.23 个物理核，再乘以用户数推规模。海豚君从三方面反驳：

1. 概念（统计口径）：
   - DSec 的 microVM 是 Agent 执行代码、操作 shell、读写文件时按需创建的沙箱，是沙箱数而不是用户数，拿它乘以用户数来推规模不对。
   - 两者只有在“一个用户峰值时恰好只持有一个沙箱”时才相等。
   - Muse 用户的 VM 本机没有浏览器，broker 要再租一台跑浏览器镜像的 VM，一个正在浏览的用户至少占两个沙箱。
2. 数据（数据性质）：
   - 800 是演示上限，生产实测峰值是 524，对应每 VM 0.36 个物理核（188 ÷ 524），而不是 0.23（188 ÷ 800）。
3. 负载（负载构成）：
   - 对方的逻辑建立在“90% 的沙箱平均只用不到申请 CPU 的 5%”这个实测上，但这个 5% 是在 DSec 大量跑脚本、编译、测试的负载下稀释出来的均值。
   - DSec 是跑一段代码、返回结果、销毁；Muse 是常驻的个人计算机，带浏览器、持久记忆和 Chromium 多进程。
   - 一次跨平台比价可能触发多达 146 次页面加载，每次都要做完整的 HTML 解析、JavaScript 执行、DOM 构建和渲染；Chromium 的 JS 主线程是单线程且 CPU 密集的，一个现代商旅页面的渲染要占满一个核好几秒。

可复用的“参照物三问”：它统计的对象与我要推算的对象是同一个口径吗？它是演示上限、理论值，还是生产实测？它的负载构成与我的对象一致吗？

**关键指标与数据来源**：每 VM 物理核数、演示上限 vs 生产峰值、CPU 占用率、页面加载次数。

**判断标准**

- 三问中任何一问不同质，该参照物就不能直接套用。
- 推理链：概念不同（沙箱 ≠ 用户，浏览用户至少占两个沙箱）+ 数据不同（800 为演示上限，实测峰值 524，每 VM 0.36 而非 0.23）+ 负载不同（脚本编译测试 vs 常驻浏览器与多进程渲染）→ 对方的每 VM 核数被低估，类比测算不成立。
- 均值要看是在什么负载下“稀释”出来的：“90% 的沙箱只用不到 5%”在低负载的批量任务下成立，在常驻、高 CPU 的浏览场景下不成立。

**海豚案例**

- Muse/DSec《拿 DSec 来套？Muse 如何真正撬动 CPU 需求》（2026-09-29）：按上述概念、数据、负载三方面反驳以 DSec 为参照物的推算，指出 DSec 的 microVM 是沙箱而非用户、800 是演示上限而生产实测峰值为 524、5% 的 CPU 占用是脚本类负载下的稀释均值，而 Muse 的浏览负载（如一次跨平台比价多达 146 次页面加载）要占满一个核好几秒。

**适用场景与注意事项**

- 适用于检验任何类比测算的参照对象是否同质。
- 重点核对三个维度：统计口径、数据性质（上限、理论、实测）、负载构成。
- 先对比公式（13.3.1），再对比参照物，这样能把分歧精确归因到“结构”还是“取值”。

### 13.3.3 区分“单位需求”与“整体需求”：效率提升不等于硬件总需求下降

**方法要点**：当市场因某项技术进步（如单 Token KV 缓存减少）而担心上游硬件需求下降时，把“单位需求”与“整体需求”拆开：效率提升只降低单位成本，总量往往因为用量扩张而继续增长。

**操作步骤 / 拆分口径**

1. 识别叙事：某技术使“单位”消耗大幅下降（如 K3 的“KV Cache 减少 75%”），市场推导出硬件总需求下降，引发上游恐慌。
2. 拆开两层需求：
   - 单位需求：KDA 只降低单 Token 的存储与计算成本；
   - 整体需求：推理过程的硬件需求总和，并不因此被压缩。
3. 论证总量：
   - 模型参数上升本身提高了部署门槛；
   - 开源模型还会进一步扩大全行业硬件部署规模；
   - 用实际紧缺现象（算力紧缺实测）佐证总需求仍在扩张。
4. 给出逻辑闭环：效率提升 → 成本下降 → 用量扩张（杰文斯悖论式）。

**关键指标与数据来源**：单位存储/计算需求、总部署规模、模型参数量；以及算力、存储的实际紧缺现象。

**判断标准**

- 区分“单位 Token 的资源消耗”与“整体硬件需求”，二者不能混为一谈。
- 判断总量看三点：参数规模是否在上升（部署门槛）、开源模型是否扩大部署范围、市场上是否仍有实际紧缺。
- 推理链：KV 减少 75% 只意味着单 Token 成本下降 → 单位成本下降带来用量扩张 → 加上参数上升、开源扩大部署 → 整体硬件需求没有被压缩，所谓“存储崩了”只是“鬼故事”。

**海豚案例**

- Kimi/存储《Kimi K3 时刻：中美 AI 产业链叙事要变天？》（2026-07-22）：市场因 K3“KV Cache 减少 75%”引发存储恐慌，海豚君指出是“鬼故事”，市场混淆了单位需求与整体需求；KDA 只降低单 Token 的存储与计算成本，不代表推理硬件需求整体被压缩；参数上升提高部署门槛，开源模型进一步扩大全行业硬件部署规模，实际紧缺现象佐证总需求仍在扩张。

**适用场景与注意事项**

- 适用于所有“效率提升利空上游”的叙事判断，例如 DeepSeek 时刻对算力的冲击。
- 前提：用量扩张要有证据（实际紧缺、部署规模），不能只靠“杰文斯悖论”的概念类比；若需求已饱和或缺乏弹性，则效率提升确实可能压缩总量。
- 需求弹性与透支的系统分析见 3.5。
- 与 13.3.4 的区别：本方法针对效率提升（技术变量）对资源消耗的影响，13.3.4 针对单价下行与方案简化（价格变量）对总价值量的影响。

### 13.3.4 单位通缩不改总量通胀：回应技术减配传闻

**方法要点**：当市场传言龙头客户的方案减配、单位价值量下降时，不去揣测尚无官方定论的技术细节，而是回到需求的第一性原理：单位价值量可以下降（单位通缩），但只要总需求的增长更快，总量仍然上升（总量通胀）。

**操作步骤 / 拆分口径**

1. 识别传闻：例如 CES 2026 后传言 Rubin 恢复 GB200 式大冷板、取消冷水机组。
2. 不揣测技术细节：对尚无官方定论的技术方案，不做细节判断。
3. 承认单位通缩：即使降本方案导致单位价值量下降（能耗和成本都要考量，这很正常），也先承认。
4. 回到总需求：量化机柜更高功率带来的散热总需求，看总量是否仍大幅增长（总量通胀）。
5. 补充方向性确定：Rubin 大概率从部分液冷过渡到全液冷，液冷升级方向确定。
6. 比较增速：总需求增速是否大于单位价格降幅。

**关键指标与数据来源**：单位价值量变化；总散热需求（功率）；液冷渗透率（部分液冷到全液冷）。

**判断标准**

- 判断标准：总需求增速是否大于单位价格降幅；若大于，总价值量仍然上升，减配传闻不改变需求增长逻辑。
- 推理链：减配传闻 → 即使成立也是单位通缩 → 机柜功率提升使散热总需求仍大幅增长 → 且方向从部分液冷过渡到全液冷 → 热管理需求增长逻辑本质未变。

**海豚案例**

- 三花智控《三花：AI 机器人时代…》（2026-01-08，第一部分第一节）：回应 Rubin 热管理减配传言，不去揣测技术细节，指出即使单位价值量下降，机柜更高功率带来的散热总需求仍大幅增长，且 Rubin 大概率从部分液冷过渡到全液冷，结论是热管理需求增长逻辑本质未变。

**适用场景与注意事项**

- 适用于产业链对单价下行、方案简化产生恐慌时的逻辑校验。
- 前提是能量化总需求增速，否则只能定性；定性结论的说服力有限。
- 要避免两个错误：把“单位价值量下降”当成“总需求下降”，或者把“总需求增长”当成“每家公司都受益”（价值是否仍留在该环节要另行判断）。
- 效率提升与用量扩张的对应分析见 13.3.3。
