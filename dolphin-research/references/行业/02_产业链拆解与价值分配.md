# 第2章 产业链拆解与价值分配

> **本章目的**：把产业链或系统拆到可计量的环节与器件，回答哪里值钱、增量在哪、利润归谁、冲击如何沿链传导。

**本章小节**：2.1 产业链与系统架构分层拆解｜2.2 BOM、成本树与器件用量配比｜2.3 价值量拆分、排序与增量环节识别｜2.4 产业链利润分配与议价权｜2.5 产业链传导与上下游联动

## 2.1 产业链与系统架构分层拆解

> 本节导读：本节解决“一个复杂系统到底由哪几层、哪几段信号路径、多少个可数的物理单元构成”的问题，是后面做BOM、价值量排序、器件配比测算的前提。研究任何硬件或系统级产业链（AI服务器、网络互连、存储、半导体设备、机器人）时，先用本节方法画出“场景图、层级图、信号路径图、可数清单”，再进入 2.2（BOM、成本树与器件配比）和 2.3（价值量排序与增量环节识别）。赛道专属的产品分类与架构分层（如存储层级二维分类、G1-G4内存架构）见 16.1，不在此展开。

### 2.1.1 按应用场景拆分，逐一明确新技术在每个场景替代谁

**方法要点**：先按物理层级把数据中心的传输场景拆开（Scale-up / Scale-out / DCI），再逐个回答“新技术在这里替代谁、进展快慢如何”，避免把一项新技术笼统地说成“替代某某”。不同场景对应不同的被替代公司和价值量。

**操作步骤 / 拆分口径**

1. 按物理位置与距离由内而外划分场景。基础三分法为 Scale-up（机柜内、服务器内）、Scale-out（机柜或服务器与交换机之间）、DCI（数据中心之间及对外）；DC互联篇把它扩成三层，并给每层标注介质、距离、延迟量级与主要挑战。
2. 每个场景回答：连接的是谁与谁、现在主要用什么介质、新技术替代的是哪种现有方案、进展快还是慢。
3. 把“被替代的对象”映射到具体的被替代公司和价值量，不同场景分别列。
4. 小结：新技术现阶段主要面向哪个场景、未来可能延伸到哪个场景。
5. 用通信语义（而非只看物理位置）校验场景边界。

**场景拆分对照（基础三分法）**

| 场景 | 范围 | 现行主流介质 | 新技术（以CPO为例）的角色 |
|---|---|---|---|
| Scale-up | 机柜内、服务器内，CPU/GPU/网卡/内存/硬盘互连 | PCIe插槽、PCB铜走线、SATA等铜连接 | 替代铜，进展慢于柜间 |
| Scale-out | 机柜或服务器与交换机之间 | 光纤加可插拔光模块 | 替代可插拔光模块，进展快于柜内 |
| DCI | 数据中心之间及对外 | — | 不作重点 |

**DC互联篇的三层口径（由内到外）**

- 托盘内：PCB走线，距离厘米级，延迟纳秒级。
- xPU之间：包含 Scale-up 与 Scale-out 两种。
- 数据中心之间（Scale-across）：相干DWDM，距离数十到数百公里，单波长400G-800G，正向1.6T/3.2T演进，可容忍更高延迟。
- 每层都要写明介质、距离、延迟量级和主要挑战。海豚君指出：Scale-out 的核心挑战已从“送得多快”转向拥塞控制与成本效益。

**关键指标与数据来源**：各场景的连接介质、距离、延迟量级、带宽；巨头在各场景的布局。数据来自厂商发布会、技术文档与论文。

**判断标准**

- 结论形式是“某技术现阶段主要面向哪个场景”：CPO现阶段主要面向机柜间（Scale-out，替代可插拔光模块，进展快于柜内），未来可能延伸到柜内（Scale-up，替代铜）。
- 推理链条：场景拆开→每个场景现有介质不同→被替代的公司不同、价值量不同、进展速度不同→分场景给出受益/受损判断，而不是对整个“网络”下一个总结论。

**海豚案例**

- 《AI 超连接时代：AI 向 “光” 飞奔？》（2026-06-03）：把CPO的应用拆成柜内替铜、柜间替光模块两类，判断柜间先行（Scale-out 先于 Scale-up）。
- 《AI 时代 DC 互联》（2026-09-08）：按物理距离由内而外三层拆解AI网络（托盘内、xPU之间、数据中心之间），逐层标注介质、距离、延迟量级、主要挑战，并指出 Scale-out 的核心挑战已从“送得多快”转向拥塞控制与成本效益。

**适用场景与注意事项**：适用于网络、互连、存储层级这类按距离或层级分工的技术。局限：按物理位置划分 Scale-up/out 并不精确（Rubin Ultra 的 Scale-up 已跨出机架），应结合通信语义判断。

### 2.1.2 组网逐层拆解：芯片→托盘→机架(Cube)→Pod→Superpod

**方法要点**：组网就是拓扑，即网络里各节点怎么连。按物理层级从小到大逐层拆，每层都回答协议、介质、拓扑、带宽四件事，并与英伟达方案对照差异。

**操作步骤 / 拆分口径**

1. Intra-Tray（托盘内）：看托盘内芯片数、物理排布与逻辑拓扑、端口数及分配。
2. Tray-Tray（托盘间）：看有没有交换芯片，是直连还是交换。
3. Cube-Cube（机架间）：看OCS如何把Cube拼成Pod，直到Superpod。
4. Superpod 之间属 Scale-Out：写出链路，如网卡→ToR→Leaf→聚合块→OCS。
5. 每一层逐项回答：走什么协议、用什么介质（PCB / DAC / AEC / 光模块）、带宽多少、和英伟达方案差在哪。
6. 拆完后在小结里按三条概括：Scale-Up 层、Scale-Out 层、关键硬件。
7. AWS 篇对 Trn2 沿用同一套顺序（见案例）。

**关键指标与数据来源**

- 每层芯片数与端口数。
- 单芯聚合双向带宽：ICI v7 1,200GB/s、v8 2,400GB/s；NVLink6 3.6TB/s；NLv4 2,304GB/s。
- Scale-Out 单卡带宽：谷歌 v7 100Gbps、v8t 400Gbps；AWS 200Gb/s；英伟达 800G→1.6T。
- 数据来源：厂商论文、发布会、拆机资料与架构图，对图表依赖强。

**判断标准**：拆完后能回答“Scale-Up 靠什么介质、Scale-Out 靠什么介质、哪些硬件是关键增量”；若某一层的协议、介质、带宽任一项答不出来，说明拆解不完整，后续价值量与配比测算会失真。

**海豚案例**

- 谷歌《叫板英伟达霸权…》（2026-09-21）：Intra-Tray 看到谷歌托盘物理上为1×4、逻辑上为2×2，每颗TPU有6个ICI端口，板内用2个、出板4个；v7托盘含4颗TPU，16个托盘组成64颗、4×4×4的Cube；Cube-Cube 由OCS拼成Pod（4个Cube、256颗），直到Superpod（144个Cube、9,216颗）；Superpod之间是Scale-Out，链路为网卡→ToR→Leaf→聚合块→OCS。
- AWS《AWS 图省事…》（2026-10-12）：Trn2-Ultra 每托盘2卡走PCB直连，8个计算托盘加1个CPU托盘组成16卡服务器（背板铜缆+DAC），4台服务器经AEC相连成64卡3D torus；Trn3 NL72x2 是两个72卡机柜经AEC组成144卡域。

**适用场景与注意事项**：适用于所有AI服务器和集群硬件分析，是后面做价值量、BOM、器件配比测算的前提（见 2.2.7、2.3.2）。需要大量技术文档（厂商论文、发布会、拆机资料），对图表依赖强。

### 2.1.3 把机架拆到可数的物理单元

**方法要点**：把整机架（如NVL72）拆成可以数清的物理单元（托盘数、交换芯片数、每颗GPU链路数、单GPU带宽、端口数、CPU:GPU比），在可计数的基础上再推导成本和性能差异。

**操作步骤 / 拆分口径**

1. 数计算托盘与交换托盘各多少个、每个托盘多少颗芯片、整机架共多少颗GPU与交换芯片。
2. 数每颗GPU引出多少条链路、分别接入哪些交换芯片，算出单GPU聚合双向带宽。
3. 数每颗交换芯片的端口数，检验能否接满全部GPU，判断是否单跳、无阻塞全互连。
4. 数CPU:GPU配比，以及CPU与GPU之间的互连方式与带宽。
5. 两个方案并列对比，再推导成本与性能差异（接 2.2.6）。

**对照数据**

| 项目 | GB300（NVL72） | Helios |
|---|---|---|
| 计算托盘 / GPU | 18个托盘，共72颗GPU（每托盘4颗Blackwell） | 18个托盘，共72颗GPU（每计算托盘配1颗Venice CPU与4颗MI455X） |
| 交换托盘 / 交换芯片 | 9个交换托盘，共18颗NVSwitch 5（上下分布10+9+8） | 6个交换托盘，共12颗Switch ASIC |
| 单GPU带宽 | 18条链路接入18颗交换芯片，聚合双向1.8TB/s | 双向3.6TB/s，是GB300的两倍 |
| 交换芯片端口 | 每颗NVSwitch 72个端口，接满全部GPU，任意两颗GPU单跳、无阻塞全互连 | — |
| CPU:GPU | 每托盘2颗CPU，CPU与GPU之间用NVLink C2C（900GB/s，通用方案多走PCIe） | 1颗CPU对4颗GPU |

**关键指标**：托盘数、GPU数、交换芯片数、链路数、端口数、单GPU带宽、CPU:GPU比。

**判断标准**：能用这些可数的量“闭环验算”——例如GB300里18颗交换芯片×72端口=72颗GPU×18条链路，数字自洽才算拆对；拆对之后，各环节的器件数量才能放心乘以ASP得到价值量。

**海豚案例**：《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：把GB300与Helios的机架逐一拆成托盘、交换芯片、链路、端口，得到上表数据，再据此推导两者的成本与性能差异。

**适用场景与注意事项**：适用于系统级硬件方案对比和BOM测算。拆解依赖官方参考设计与发布会资料；链路数与端口数要互相校验。

### 2.1.4 沿信号流动路径追踪器件，定位增量器件

**方法要点**：换成“信号怎么走”的视角，把孤立的器件串成一个系统，理解各段如何协作，并在路径上定位增量器件（如Redriver / Retimer）与易损件（如飞线）。

**操作步骤 / 拆分口径**

1. 节点内：CPU、GPU、NIC/DPU通过铜电链路相连。信号完整性不够时引入Redriver或Retimer：
   - Redriver 只在模拟域做均衡和放大，噪声也一并放大，成本和功耗较低；
   - Retimer 把衰减严重的信号重新定时后发出，下游看到的是一条全新链路，可延长传输距离。
2. Scale-up：同一域内经专有交换ASIC，用Load/Store指令直接寻址。
3. Scale-out：流量交给NIC/DPU，经电通道进光模块做电光转换，沿光缆跨机架传输；到交换机后光模块还原为电信号，交换ASIC决定下一跳；多级拓扑下依次经过 Leaf、Spine、Super-Spine 到达目标服务器。
4. 逐段写出物理路径，标出每段的介质与距离，并在路径上圈出需要信号修复的位置和易损件。

**关键指标与数据来源**：路径上的器件清单、每段的介质与距离；数据来源为架构图、厂商技术文档。

**判断标准**：路径上凡是“信号需要被修复、被转换、被重定时”的节点，就是增量器件所在；路径越长、速率越高，越需要Retimer、光电转换等器件；路径上的飞线、连接器转接点是成本与维护风险的集中处。

**海豚案例**

- 《AI 时代 DC 互联》（2026-09-08）：按节点内、Scale-up、Scale-out三段讲信号流，梳理Redriver/Retimer、专有交换ASIC、NIC/DPU、光模块、Leaf-Spine-Super-Spine各自的位置。
- 《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：用GB300的逐段物理路径（GPU→托盘走线→托盘连接器→背板连接器→铜缆→交换托盘连接器→飞线→NVSwitch）定位飞线这类易损件。

**适用场景与注意事项**：适用于网络、电源、散热等系统级产业链拆解。与 2.1.2 的静态分层互补：分层回答“有哪些层”，信号路径回答“信号经过哪些器件”。

### 2.1.5 平台架构分层拆解：新增的层就是新增需求的来源

**方法要点**：把新一代平台的各款芯片归入层级，对比上一代的层数，新增的那一层就是新增需求的来源，也通常对应新的供应链受益方。

**操作步骤 / 拆分口径**

1. 列出新平台的全部定制芯片，归入层级：Blackwell 是“算力层+网络层”，Rubin 升级为“算力层+网络层+存储与安全层”。
2. 逐层给出关键规格与代际倍数。
3. 找出新增层，判断它对应哪些环节、哪类供应商受益。

**平台关键规格（Rubin平台6款定制芯片）**

| 芯片 | 所属层（按功能归类） | 关键规格 |
|---|---|---|
| Vera CPU | 算力层 | 88核/176线程，1.5TB LPDDR5X（Grace的3倍），内存带宽1.2TB/s |
| Rubin GPU | 算力层 | 推理50PFLOPS（NVFP4，Blackwell的5倍），训练35PFLOPS（3.5倍），HBM4带宽22TB/s（2.8倍），NVLink 3.6TB/s（2倍） |
| ConnectX-9 | 网络层 | 单端口800Gb/s |
| Spectrum-6 | 网络层 | 102.4Tb/s |
| NVLink 6 Switch | 网络层 | 互连带宽对应Rubin GPU一栏的NVLink 3.6TB/s（2倍） |
| BlueField-4 | 存储与安全层（新增） | 每台管理150TB上下文内存，KV缓存访问提速5倍 |

**关键指标**：各芯片关键规格、代际提升倍数、新增层级。

**判断标准**：新增的存储与安全层是最明显的增量，也是存储股大涨的主因——“新增层=新增需求=新受益方”是推理链条。

**海豚案例**：英伟达《老黄解锁Rubin，AI存储又添“一把火”》（2026-01-07）：把Rubin的6款芯片归入三层，指出新增的存储与安全层带来存储需求的增量。

**适用场景与注意事项**：适用于系统级产品（服务器、汽车电子架构）的增量拆解。注意把“新增层”与“已有层的规格提升”区分开，前者是从0到1，后者是量价提升（后者见 2.3.4）。

### 2.1.6 按前道/后道工艺拆分设备环节，锁定“增量环节+瓶颈环节”

**方法要点**：设备研究先拆工艺，对比传统工艺找出新工艺最难的环节，再在这些环节里选设备机会。

**操作步骤 / 拆分口径**

1. 前道（Fab）：EIC晶圆制造、PIC晶圆制造（硅光集成）、激光器制造、晶圆级测试。
2. 后道：切割贴片、键合、光纤阵列耦合、系统级测试。
3. 与传统电芯片工艺对比，找出新工艺的最大难点——CPO最大的难点在耦合和测试两个环节，设备就重点看这两块。
4. 对重点设备环节拆路线与玩家，判断路线之争的胜负。
5. 区分“增量环节”和“非新增环节”，决定成长性排序，并列出后续催化剂。

**设备路线与玩家**

- 耦合设备分有源与无源路线：
  - ficonTEC（已被罗博特科收购，罗博特科计划在港股上市）是全球少数能提供无源耦合设备的企业，无源方案效率高、成本低，可能是未来方向，但当前量产仍以有源为主；
  - 其他玩家：AIXEMTEC（有源）、Vanguard（有源，并推3D打印光波导的无源路线）、MRSI与万润科技（视觉对准的无源路线）、猎奇智能（无源已量产，主要供中国市场）。
- 测试设备：Teradyne、Advantest 提供ATE，但测试不是新增环节，成长性不如耦合设备。

**关键指标**：各工艺环节难点、设备路线（有源/无源）、厂商量产能力、上市等催化事件。后续催化剂：罗博特科港股上市节奏。

**判断标准**：同时满足“增量环节”和“瓶颈环节”才是设备机会的优先选项；耦合是新增且是瓶颈，成长性高于只是需求扩大的测试。

**海豚案例**：《“‘铜’ 牛夫人” 不走！CPO：真机会 or 镜中花？》（2026-06-24）：设备部分按“增量环节和瓶颈环节”筛选，聚焦耦合与测试，耦合设备再分有源/无源路线并映射到具体厂商。

**适用场景与注意事项**：适用于新工艺导入期的设备选股。需要判断设备路线之争的胜负；当前量产路线（有源）与未来可能的方向（无源）可能不一致，需分别标注。

**本节速查清单**

- [ ] 是否按物理场景（Scale-up/Scale-out/DCI或托盘内/xPU间/数据中心间）拆开，并对每个场景单独给出“新技术替代谁、快慢如何”？
- [ ] 每个层级（芯片→托盘→机架→Pod→Superpod）是否都写清协议、介质、拓扑、带宽，并与对标方案（如英伟达）对照？
- [ ] 机架是否拆到可数的物理单元（托盘、芯片、链路、端口、CPU:GPU比），并做了闭环验算？
- [ ] 是否沿信号路径逐段列出器件，标出需要Retimer/光电转换的位置和飞线等易损件？
- [ ] 新平台相对上一代是否多出“层”，新增层对应哪类供应链？
- [ ] 设备研究是否先按前道/后道拆工艺，并区分增量环节、瓶颈环节、非新增环节？
- [ ] 物理位置的划分是否用通信语义校验过（如Scale-up是否已跨出机架）？

## 2.2 BOM、成本树与器件用量配比

> 本节导读：本节回答“一个系统或产品由哪些物料构成、每一项占多少成本、每颗芯片到底配多少器件”。当 2.1 把系统拆到层级和可数单元后，用本节把它拆到器件级和成本级，得到后续价值量测算里的“量”（配比）与“价”（成本占比）。价值量排序与增量环节判断见 2.3，需求总量测算见 3.3。

### 2.2.1 光引擎按四类功能拆解，并对比不同方案如何去掉DSP

**方法要点**：把核心部件拆到器件级，弄清每个器件的功能和上下游关系，再比较不同方案对器件的取舍，为后面判断价值量、映射标的打基础。

**操作步骤 / 拆分口径**

光引擎按功能拆成四类：

1. 光子电路：调制器（把电信号写成光信号）、探测器PD（光转电）、波导（芯片内的微型光纤）。
2. 电子电路：Driver（把微弱电信号放大，用来驱动调制器）、TIA跨阻放大器（把PD的微弱电流放大成电压）。
3. 光源：激光器（调制器自己不发光）。
4. 信号修复：DSP与CDR（修复电信号损伤、提取时钟，DSP通常集成CDR）。

再比较方案差异：

- CPO 和 LPO 都把高功耗、高成本、带来延迟的DSP移出光引擎。
- CPO 把DSP的部分功能并入交换ASIC、CDR并入高速SerDes；LPO 则靠模拟芯片放大硬扛。

**关键指标与数据来源**：各器件功能、是否被集成或移除、功耗与成本占比、SerDes能力。来源：论文与厂商发布会资料。

**判断标准**

- 推理链条：DSP被移出或并入→独立DSP的价值量在两种路线下都受损→信号修复能力转移到SerDes→SerDes能力成为交换芯片厂商的关键竞争力。
- 反向验证：SerDes强弱直接决定是否要外加Retimer（见案例二与 2.2.6）。

**海豚案例**

- 《AI 超连接时代：AI 向 “光” 飞奔？》（2026-06-03）：引用论文《400G FR4 硅光收发模块的研究》的光引擎结构图，拆解六类器件（调制器、PD、波导、Driver、TIA、激光器），并对比CPO与LPO如何处理DSP；结论是两种路线下独立DSP的价值量都受损。
- 《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：SerDes强弱直接决定是否要外加Retimer，Helios 因托盘内SerDes较弱，加装了以太网Retimer。

**适用场景与注意事项**：适用于需要从系统拆到器件、再找受益标的的硬件研究。需要能拿到技术文献、厂商发布会资料。

### 2.2.2 拆PCB成本树：CCL占约30%，再定位高端材料卡点与供应集中度

**方法要点**：逐层拆成本，找到议价权所在——从成品（PCB/HDI）一路拆到上游材料，再在最上游找出“高端材料卡点”和供应集中度。

**操作步骤 / 拆分口径**

1. 第一层：PCB/HDI的核心是覆铜板 CCL，约占PCB成本的30%。
2. 第二层：CCL自身成本集中在三种上游材料——铜箔约40%，树脂约25%，玻纤布约25%。
3. 第三层：PCB厂商的成本和议价能力，由玻纤布和铜箔这两种高端材料决定。
4. 技术驱动：找出为什么要用高端材料。Vera Rubin 这一代把NVLink飞线全部换成PCB走线，板上长距离传输要求极低的介电损耗（Dk决定时延，Df决定损耗）和极光滑的铜箔表面，因此必须用 Low Dk/Df 玻纤布和 HVLP（高频超低粗糙度）铜箔。
5. 查供应集中度：
   - 三代低介电玻纤布由日东纺和AGC垄断；
   - 二代布正在国产替代，但主要出货仍依赖日东纺、AGC、台玻；
   - HVLP4/5级铜箔中三井金属份额超过80%。

**关键指标**：成本占比（CCL约30%；铜箔40%、树脂25%、玻纤布25%）、Dk/Df、HVLP等级、材料厂份额。

**判断标准**：关键材料集中在少数供应商手中，则供应商掌握议价权；海豚君的判断是“关键材料卡在日系厂商手里”。

**海豚案例**：《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：拆PCB/HDI成本树与上游材料格局，指出玻纤布、铜箔是议价权所在、且集中在日系厂商。后续用各环节毛利率是否稳定来检验“涨价是否被上游独占”，见 2.4.7。

**适用场景与注意事项**：适用于电子材料和PCB产业链。成本比例为行业平均，高端板会有差异。

### 2.2.3 整机BOM按光路顺序拆，区分自研控制部分与外采无源器件（OCS案例）

**方法要点**：在新硬件品类里找“卖水人”——按信号（光路）顺序列出每个部件的功能，再做成本归属：哪些是整机厂自研、哪些外采、外采占多大成本、哪个部件最值得关注。

**操作步骤 / 拆分口径**

1. 抛出关键技术问题：镜面倾多少度才算对准？光束要落进比头发丝细得多的光纤芯，对各部件精度要求很高，由此引出精度敏感的器件。
2. 按光路顺序列部件与功能：
   - 光纤准直器阵列（把散射光梳成平行光，出口处再收回光纤）→
   - 透镜阵列（聚焦）→
   - 两组MEMS微镜阵列（双轴倾转改变光路）→
   - 分色分束器（按波长分流的“单向玻璃”）→
   - 注入模块（发探针光）→
   - 相机模块（盯探针光落点）。
3. 解释关键方案：谷歌的“引路光”方案——1310nm信号光承载数据，850nm探针光与信号光同路，专门监测MEMS对准，输出端用分色分束器把两者分开。
4. 做成本归属：
   - 谷歌自研系统架构和注入、相机等控制部分；
   - 上游无源光学器件（MEMS阵列、分色镜、准直器阵列、透镜阵列）外采，占单机成本60%-70%；
   - 其中MEMS微镜阵列芯片占单台物料成本30%-40%，是最值得关注的环节。

**关键指标**：外采无源器件占单机成本60-70%；MEMS芯片占物料成本30-40%；信号光1310nm、探针光850nm。

**判断标准**：外采且占成本比重大、技术门槛高的环节，就是“卖水人”的所在；MEMS芯片占比最高，是最值得关注的环节。

**海豚案例**：谷歌《叫板英伟达霸权…》（2026-09-21）：按光路顺序拆OCS整机BOM，得出外采无源器件占单机成本60%-70%、MEMS微镜阵列芯片占物料成本30%-40%的结论。

**适用场景与注意事项**：适用于在新硬件品类里找“卖水人”。成本占比来自海豚君测算或产业调研，需要交叉验证。

### 2.2.4 以龙头方案为“灯塔”拆解传动链与BOM环节（人形机器人灵巧手）

**方法要点**：技术路线未收敛时，以最具代表性的龙头方案为基准拆结构，每个环节写明功能、位置、数量和可能的方案，作为后续映射受益环节的底图。

**操作步骤 / 拆分口径**

1. 选定灯塔方案（特斯拉Optimus）。
2. 拆自由度：每只手22个自由度，其中17个主动自由度，由执行器主动控制。
3. 拆执行器传动链：
   - 电机：动力源，布置在手臂，早期6个空心杯电机，2.5版17个主动自由度下电机数量远超6个；
   - 行星齿轮箱：减速增扭；
   - 微型丝杠：旋转变直线，出于体积、精度、寿命考虑；
   - 腱绳：穿过手掌，把直线拉力传给手指，类似肌腱。
4. 加触觉传感器：早期每只手5个、分布在指尖，新版扩展到整个手掌，数量远大于5个。
5. 每个环节写明功能、位置、数量和可能的方案，附执行器技术路线比较表。

**关键指标**：自由度与主动自由度数、电机数量与类型、传感器数量与覆盖面积。

**判断标准**：每代方案相对上一代的“数量与覆盖面”变化（电机数从6个到远超6个，传感器从5个到覆盖整个手掌）直接决定该环节的增量大小。

**海豚案例**：人形机器人：《人形机器人：为何灵巧手是迈不过去的门槛？》（2026-01-20）：用Optimus手臂和手部图解拆出四段传动链，并附执行器技术路线比较表。

**适用场景与注意事项**：适用于技术尚未收敛的新硬件产业链。风险在于龙头方案本身可能被迭代或抛弃。

### 2.2.5 火箭成本BOM拆分：发动机40%-50% / 箭体约25% / GNC约15% / 燃料<3%

**方法要点**：不计研发和地面设施的摊销折旧，按部件拆复杂装备的单发成本，用成本占比决定产业链投资的重点环节。

**操作步骤 / 拆分口径**

1. 拆单发成本：发动机占比最高（40%-50%），其次箭体（约25%），再次GNC系统（约15%），燃料不足3%。
2. 对箭体细分组件做结构说明：整流罩、筒段、贮箱、级间段、箱间段、尾段。
3. 由占比推导结论（见判断标准），并用价值量排序组织后文“上游供应链”。

**关键指标**：各部件成本占比。

**判断标准**

- 降本和回收的核心在发动机和箭体，燃料成本无关紧要，所以可回收的经济性来自硬件复用。
- 价值量高的环节就是产业链投资的重点，后文“上游供应链”首先列出发动机、箭体材料、GNC、3D打印。

**海豚案例**：《SpaceX 的挑战者们》（2026-04-08）：火箭成本构成及 Falcon 9 结构图，据此确定上游投资的先后顺序。

**适用场景与注意事项**：适用于航天器及复杂装备的价值量拆分。注意口径不含研发摊销。

### 2.2.6 逐项对比两套方案的物料用量，并从协议与SerDes能力反推原因

**方法要点**：把两套竞争方案的物料逐项列出来比，对每一处差异从协议、SerDes、互连带宽等技术层面找出原因，从而把“成本更高/更低”的判断落到具体物料上。

**操作步骤 / 拆分口径**

1. 以对标方案（英伟达GB300）为基准，逐项列出被研究方案（Helios）在每种物料上的差异。
2. 对每处差异提出“为什么”：回到协议能力、SerDes、互连带宽找原因。
3. 对原因有多种可能时，写出海豚君推测，并标注是推测。
4. 汇总成对成本、功耗、组装难度、维护风险的影响。

**物料差异清单（Helios vs 英伟达）**

| 物料 | Helios的情况 | 技术原因 |
|---|---|---|
| Retimer | 需加装以太网Retimer，同时推高成本、功耗和组装难度 | 托盘内SerDes能力较弱 |
| 铜缆 | 共10,368根，是英伟达的两倍 | 英伟达的SerDes能在同一对差分线上同时收发 |
| 飞线 | 连接器到Switch这一段保留了GB300设计里的飞线，增加成本和维护风险 | 沿用设计 |
| CPU配比 | 1颗CPU配4颗GPU（英伟达是1:2，且核数也更低），GPU离CPU较远，需用飞线连接Venice CPU与Vulcano网卡 | 见下方推测 |

**海豚君对CPU配比差异的推测**：英伟达自研的NVLink C2C（1.8TB/s）把CPU及其内存纳入GPU的一致性访问域，需要更高的CPU配比；AMD的CPU与GPU之间走IF（仅256GB/s），CPU可能只负责控制和调度，一颗就能带4颗GPU。

**关键指标**：铜缆根数、Retimer数量、飞线段数、CPU:GPU比、C2C与IF带宽。

**判断标准**：物料差异能够追溯到协议/SerDes能力差异，才构成有说服力的成本推断；协议能力弱的一方通常靠加装器件（Retimer、飞线、更多铜缆）补偿，成本、功耗、组装难度随之上升。

**海豚案例**：《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：Helios 与 GB300 的物料差异清单，包括Retimer、10,368根铜缆、飞线、1:4的CPU:GPU配比及其原因推测。

**适用场景与注意事项**：适用于系统方案的BOM对比和成本推断。需要两套方案都有可数的参考设计（见 2.1.3）。

### 2.2.7 按芯片在拓扑中的位置统计连接器件，推出器件/芯片配比

**方法要点**：在 torus 这类直连拓扑里，不同位置的芯片所需的连接器件不同，按位置（内部/表面/棱/角）统计，推出整机的光模块/芯片配比，这个配比乘以ASP就是价值量测算里的“量”。

**操作步骤 / 拆分口径**

1. 在3D torus的Cube里，最里面的芯片6个方向都有邻居，可全部用铜（DAC+PCB）连接。
2. 表面、棱、角上的芯片有些面没有邻居，要经光模块连到Cube对侧的芯片并汇入OCS。
3. 把不同位置的芯片数和对应的连接器件（铜、光模块、OCS端口）做成表，算出整机的光模块/TPU配比约1.5，也就是每多一颗TPU要多1.5颗光模块。
4. 区分两类器件的增长方式：随芯片数线性增长的（光模块）；随域数增长的（OCS，每9,600颗域恒定48台，见 2.2.8）。
5. 配比乘以ASP，得到价值量测算里的“量×价”（接 2.3.2）。

**补充几何验算（连接性说明，便于自行复核）**：4×4×4的Cube共64颗，最里面2×2×2=8颗全铜互连，其余56颗位于表面、棱、角；若每个缺邻居的方向对应一个光端口，则面心24颗×1、棱24颗×2、角8颗×3合计96个，96/64=1.5，与海豚君的配比吻合。

**关键指标**：Cube内部芯片8/64颗；光模块/TPU约1.5；OCS每域48台。

**判断标准**：配比高且随芯片数线性增长的器件，就是组网中增量最大的部分；本案例据此判断光模块是谷歌组网中增量最大的部分。

**海豚案例**：谷歌《叫板英伟达霸权…》（2026-09-21）：4×4×4 Cube里最里面8颗TPU全铜互连，外表面TPU走光入OCS；光模块/TPU配比1.5，据此判断光模块是谷歌组网中增量最大的部分。

**适用场景与注意事项**：适用于 torus 这类直连拓扑的器件用量测算。交换式方案则要按交换芯片端口数和托盘结构来算（见 2.1.3）。前提是拿得到拓扑图和机架设计。

### 2.2.8 集群级交换设备数量测算：OCS台数在域内恒定 vs 胖树随规模增长

**方法要点**：除了单芯片成本，还要看真实负载规模下需要多少台交换设备，做“单芯成本→集群成本”的两级测算，比较不同拓扑的集群TCO。

**操作步骤 / 拆分口径**

1. 查拓扑规则：谷歌v8t下每9,600颗TPU组成一个ICI域，每个域配48台OCS。
2. 域内：规模扩大只增加每台OCS的端口占用，台数不变；跨域后按域数线性增加。
3. 对标方案按其拓扑与端口数算台数：Vera Rubin胖树架构，使用144端口交换机。
4. 在同一集群规模下比较总台数，得出省钱与否的判断。

**关键指标**：每域OCS台数、交换机端口数、集群规模、交换设备总台数。

**判断标准**：10万颗TPU的训练集群约需1,000台OCS；同等算力下，Vera Rubin胖树架构需要近2,600台。据此判断，大集群项目里OCS方案确实能省钱。

**海豚案例**：谷歌《叫板英伟达霸权…》（2026-09-21）：约1,000台OCS vs 近2,600台交换机。

**适用场景与注意事项**：适用于大集群TCO以及交换机、OCS需求量测算。需要拓扑规则和端口数。

### 2.2.9 按“服务对象”判定模糊品类归属，并用参考设计做单机架配置算数

**方法要点**：当一类器件在不同机架里承担不同角色、归类模糊时，不看名字，看这颗芯片主要服务谁；归类之后再用参考设计算出单机架的器件数与核数。

**操作步骤 / 拆分口径**

1. 识别模糊点：BF-4 DPU里有两类CPU——NVL72计算托盘里的是Grace，STX存储机架里的是Vera。
2. 按“服务对象”判定归属：这颗芯片主要服务GPU集群，还是服务Agent负载（持久化Agent状态、KV Cache、长上下文存储）。STX更偏向Agentic。
3. 用参考设计算数：
   - STX机架有16个机箱，每个机箱2个BF-4，每个BF-4含1颗Vera CPU、2个CX-9网卡、2个SOCAMM；
   - 所以一个机架对应32颗Vera CPU、64个CX-9、64个SOCAMM。
4. 算核数并与官方数字校验：单个Vera CPU机架是256颗×88核=22,528核，和官方所说的可支撑超过22,500个沙箱吻合；单个VR NVL72（含DPU）的CPU核数是4,320（=72颗GPU×每GPU 60核），CPU机架的核数是它的5倍。

**关键指标**：单机架CPU颗数与核数、网卡数、SOCAMM数量。

**判断标准**：推算出的数字能与官方说法对上（22,528核对应超过22,500个沙箱），才说明用量测算可信；再用“CPU机架核数是VR NVL72的5倍”这类倍数，衡量新品类带来的CPU增量空间。

**海豚案例**：Muse/CPU《Muse“爆火”…》（2026-09-28）：判定BF-4中Vera CPU属Agentic（服务Agent负载）而非头节点，并用STX参考设计算出32颗Vera、64个CX-9、64个SOCAMM，以及CPU机架22,528核。

**适用场景与注意事项**：适用于从参考设计推算CPU、网卡、内存模组等器件用量。归属判断依赖对芯片实际服务对象的理解，必要时回到产品定位文档。

**本节速查清单**

- [ ] 核心部件是否拆到器件级，每个器件的功能、被集成/被移除情况是否写明？
- [ ] 成本树是否拆到最上游材料（如PCB→CCL→铜箔/树脂/玻纤布），并标出供应集中度与高端材料卡点？

- [ ] 对比两套方案时，每一处物料差异是否都追溯到协议/SerDes/带宽等技术原因？

## 2.3 价值量拆分、排序与增量环节识别

> 本节导读：本节回答“这套系统（或这个新场景）里哪些环节值钱、哪些是新增量、增量有多大”。2.1、2.2 把系统拆成可数的层级与器件、并得到配比与成本占比之后，用本节把“量（配比）×价（速率、形态、材料升级）”乘出来，给环节排序，识别从0到1的新增组件和规格跃升的升级部件，再用标准筛出“心脏与瓶颈”。利润在各环节之间如何分配见 2.4，投资视角的环节排序与选股见 11.3，按自动驾驶等级的激光雷达价值量阶梯见 16.6。

### 2.3.1 单机架网络物料归并为四个环节，并按价值量排序

**方法要点**：按单机架物料测算，把全部网络物料归并为少数几个环节，按价值量从高到低排序。这个排序既决定研究优先级，也用来评估方案迭代时价值量往哪里转移，是系统级硬件产业链研究的起点。

**操作步骤 / 拆分口径**

1. 以一个具体方案的单个机架为对象（如 Helios 机架），把全部网络物料列出来（机架的可数单元见 2.1.3，物料差异见 2.2.6）。
2. 归并为四个环节：光连接（光模块和光器件）、交换、铜连接（铜缆和连接器）、PCB&ABF。
3. 逐环节按“配比（量）×ASP（价）”估算单机架价值量及占比（口径见 2.3.2），从高到低排序：**光连接 > 交换 > 铜连接 > PCB&ABF**。
4. 以这个排序为目录，依次分析每个环节的供需、格局、毛利和标的，用排序组织后文的产业链分析。
5. 方案换代或换厂商时重做一遍：排序是“方案相关”的（例如谷歌方案排出来是光>PCB>交换>铜，见 2.3.2），不能把一个方案的排序直接套到另一个方案上。

**关键指标与数据来源**：单机架各环节价值量及占比。数据来自参考设计的物料清单加上器件ASP的测算。

**判断标准**

- 排序靠前的环节，研究优先级高；先把价值量最大的环节讲清楚，再往后排。
- 同一机架在不同方案迭代下，若某环节在排序中上升或下降，即说明价值量正在向该环节转移，据此评估方案切换的受益与受损环节。
- 推理链条：先数清物料（2.1.3）→ 乘配比与ASP得到各环节单机架价值量 → 排序 → 再进入环节内部的供需、格局、毛利分析。

**海豚案例**

- 《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：按单机架物料测算，把 Helios 全部网络物料归为四个环节，价值量排序为光连接>交换>铜连接>PCB&ABF，并以此顺序组织后文逐环节的产业链分析。

**适用场景与注意事项**：适合作为系统级硬件产业链研究的起点。排序基于单机架物料测算，口径不含机架外的数据中心级设备；方案不同排序可能完全不同，引用前核对是哪个方案、哪个口径。

### 2.3.2 单机柜价值量排序，并按“量（器件/芯片配比）×价（速率与形态升级）”逐环节拆

**方法要点**：先排各环节的单机柜价值量，再对每个环节分别拆“量”和“价”，判断是量价齐升、只有量增、还是边角料，最后给出“哪个环节最确定、增量最大”的结论。

**操作步骤 / 公式**

1. 公式：环节价值量 = 器件/芯片配比（量）× ASP（价）。
2. 量的拆法：器件/芯片配比由拓扑决定（见 2.2.7）；区分随芯片数线性增长的器件（如光模块）和随域数增长、域内恒定的器件（如 OCS 每域48台，见 2.2.8）。
3. 价的拆法：速率升级（如800G→1.6T）、形态升级（可插拔→NPO/CPO）、材料/层数/面积升级（如PCB，见 2.3.3）。
4. 逐环节判断“增量从哪来”，再汇总为单柜价值量排序和确定性判断。

**谷歌方案逐环节的量价拆解**（单柜价值量排序：光连接>PCB>交换>铜）

| 环节 | 量 | 价 | 判断 |
|---|---|---|---|
| 光模块 | 每颗TPU配1.5颗，随芯片数线性增长（OCS则恒定每域48台） | 速率从800G到1.6T、形态从可插拔到NPO/CPO都带来ASP提升；英伟达、博通等巨头入场 | 基本确立量价齐升，是增量最大的部分 |
| PCB | 大规模组网推动数量与面积 | 面积、材料、层数升级推动ASP（材料等级见 2.3.3） | 量价均有支撑 |
| 交换ASIC | 只在超出ICI域的场景有增量 | — | 增量有限 |
| 铜缆 | — | 下一代延续拓扑，意味着DAC不会升级为AEC | 在谷歌方案里是边角料 |

**关键指标与数据来源**：各环节单柜价值量、器件/芯片配比、ASP演进（800G→1.6T、可插拔→NPO/CPO）。数据来自拓扑图、厂商路线图与产业调研。

**判断标准**

- “量价齐升”：量由配比随规模线性增长保证，价由速率或形态升级保证；两者同时成立，才给出最高确定性。
- 只有“量”或只有“价”、或者两者都没有升级空间的环节（如延续拓扑下不升级的DAC），判为边角料。
- 增量只出现在特定场景的环节（如交换ASIC只在超出ICI域时才有增量），要写明触发条件，不能给泛化结论。
- AWS 篇用同样方法给出单柜价值量排序：铜连接最大，PCIe Retimer最小。

**海豚案例**

- 谷歌《叫板英伟达霸权…》（2026-09-21）：单柜价值量光>PCB>交换>铜；光模块每颗TPU配1.5颗、随芯片数线性增长，速率与形态升级带来ASP提升，结论是光模块为增量最大的部分；PCB量由组网规模推动、价由面积/材料/层数升级推动；交换ASIC仅在超出ICI域时有增量；铜缆是边角料。
- AWS《AWS 图省事…》（2026-10-12）：排序为铜>光>交换>PCB>Retimer。
- AWS《AWS 组网靠「买」…》（2026-10-13）：排序为铜>交换>光>PCB>Retimer。同一系列两篇对“光”与“交换”的先后口径不一致。

**适用场景与注意事项**：适用于给硬件产业链各受益环节排序。同一作者的不同篇可能随信息更新调整了排序，引用前要核对，并优先采用较新一篇、说明口径差异；本方法的“量”依赖 2.2.7 的配比测算，“价”依赖对速率与形态路线图的判断。

### 2.3.3 PCB以材料等级（M2-M9，低Dk/Df）作为ASP驱动与确定性判断依据

**方法要点**：把PCB的价值拆成“量”（大规模组网推动面积和数量）和“价”（材料、层数、面积要求提升），其中材料等级是最核心的ASP驱动；再用“无论技术路线如何分叉，材料都要升级”来判断PCB环节的确定性。

**操作步骤 / 拆分口径**

1. 价值拆分：量=组网规模推动的面积和数量；价=材料、层数、面积要求提升。
2. 材料等级：采用松下制定的M系列行业标准，M2到M9依次增强（Dk为介电常数、Df为损耗因子，越低越好）。
3. 速率—材料对应：单通道速率到200G，需要M9乃至更高等级的材料。
4. 逐方案查材料规格：谷歌的直连拓扑对PCB走线传信号的要求相对宽松，但市场普遍预期8t会用M9板，从而抬高该环节ASP。
5. 做路线分叉下的稳健性检验：假设下一代走不同的互连路线，材料是否都要升级（见下文AWS案例）。

**关键指标与数据来源**：PCB材料等级（M2-M9）、Dk/Df、层数、单通道速率（64G/200G）。需跟踪各代产品的材料规格与市场预期。

**判断标准**

- 材料等级随单通道速率上升而上移（200G需要M9乃至更高），等级每上一档，ASP随之抬升。
- 确定性判断的推理链条：不论下一代继续走PCIe Gen7（板材压力更大），还是转向NVLink或UALink（200G需要M9），板材都要升级，所以PCB环节的确定性最强；相反，Retimer和SerDes不是刚需，板材增强后甚至可能去掉部分Retimer。
- 反过来，若直连拓扑对走线要求宽松，材料升级是否发生只取决于“市场预期”，需要持续跟踪，不能直接当作既定事实。

**海豚案例**

- 谷歌《叫板英伟达霸权…》（2026-09-21）：谷歌直连拓扑对PCB走线要求相对宽松，但市场普遍预期8t会用M9板，从而抬高PCB环节ASP。
- AWS《AWS 图省事…》（2026-10-12）、《AWS 组网靠「买」…》（2026-10-13）：PCB被评为确定性最强的环节，Trn4无论走PCIe Gen7还是转向NVLink/UALink，板材都要升级；Retimer与SerDes不是刚需。

**适用场景与注意事项**：适用于判断PCB/CCL行业在AI服务器中的受益程度。需要跟踪各代产品的材料规格；材料等级抬升之后的上游成本与议价权见 2.2.2，利润是否能传导见 2.4.7。

### 2.3.4 识别规格跃升的增量部件，并比较其内部技术路线与竞争格局（激光器 EML vs CW）

**方法要点**：新架构使某个部件的规格大幅提高时，用“规格提升倍数→单位价值量提升”推价值量增量，再拆该部件内部的技术路线，判断格局会不会松动、国产厂商有没有机会。与 2.1.5 的“新增层”不同，这里是已有部件的规格升级，属于量价提升而非从0到1。

**操作步骤 / 拆分口径**

1. 找集成边界：CPO 只能集成光电转换部件，激光器难以直接集成，仍需外置光源——这类“集成不进去、规格要求却大幅提高”的部件就是候选。
2. 量化规格跃升：CPO 对激光器的功率要求至少提高3-4倍，性能和可靠性要求也大幅提高，单位价值量随之大增。
3. 拆部件内部路线并对照新架构的需求：

| 路线 | 结构特点 | 适用与优劣 | 格局 |
|---|---|---|---|
| EML | 激光器与调制器集成 | 适合200G以上的高带宽、长距离通信 | 被Lumentum、II-VI（Coherent）、住友垄断 |
| CW（连续波） | 激光器完全独立 | 成本和功耗占优，更匹配CPO，供应也更灵活 | 中国的源杰科技、仕佳光子、长光华芯已量产70mW/100mW产品并拿到大额订单 |

4. 用路线选择判断格局：路线从EML转向CW，垄断格局是否松动、国产厂商是否有机会。
5. 追踪上游产能与技术资源（InP晶圆产能、异构集成能力），确认谁有能力承接新规格。

**关键指标与数据来源**：激光器功率要求提升倍数（3-4倍）、功率规格（70/100mW）、各路线的垄断程度、供应商订单、InP晶圆产能。资料来源包括厂商产品资料（如住友电工）与订单公告。

**判断标准**

- 规格提升倍数越大、可替代路线越少，单位价值量增量越确定。
- 新架构更匹配的路线若恰好不是旧格局的垄断路线（CW 优于 EML 的成本与功耗），则格局可能松动；若新规格仍由旧垄断者的产能与技术支撑，则格局稳固。
- 国产厂商机会的验证点：是否已有量产产品（70mW/100mW）并拿到大额订单。

**海豚案例**

- 《AI 超连接时代：AI 向 “光” 飞奔？》（2026-06-03）：激光器是CPO的核心增量部件，功率要求至少提高3-4倍；比较EML与CW两条路线，EML被Lumentum、II-VI（Coherent）、住友垄断，CW更匹配CPO，中国的源杰科技、仕佳光子、长光华芯已量产70mW/100mW产品并拿到大额订单（资料来源：住友电工）。
- 《“‘铜’ 牛夫人” 不走！CPO：真机会 or 镜中花？》（2026-06-24）：Lumentum 拥有全球最大的InP晶圆产能，可提供ELS外部光源；Coherent 拥有全球首条6英寸InP量产线，并能把InP器件直接异构集成到硅衬底上。

**适用场景与注意事项**：适用于架构变化导致某个部件规格跃升的场景。注意：规格提升带来的单价上涨，可能被用量减少或良率改善抵消，要把“单价×用量×良率”放在一起看。

### 2.3.5 逐项回答“旧方案为什么用不到”，论证新方案的新增组件需求（FAU/PMF/Fiber Shuffle/MPO）

**方法要点**：识别新架构的新增组件时，不只罗列名词，而是用新旧对照说明“为什么必须用”。每一个“必须”都对应一块增量市场和一批供应商，是寻找“从0到1”增量环节的方法。

**操作步骤 / 拆分口径**

1. 列出新架构相对旧方案多出来的组件。
2. 对每个组件逐项写“旧方案为什么用不到”（旧方案怎么解决同一问题）。
3. 再写“新方案为什么必须用”（新架构带来了什么新约束）。
4. 把每个“必须”映射成增量市场和供应商。

**新旧对照（以CPO的四大光纤组件为例）**

| 组件 | 旧方案为什么用不到 | 新方案（CPO）为什么必须 | 供应商映射 |
|---|---|---|---|
| FAU（光纤阵列单元） | 光纤直接插标准接口 | 光纤要与芯片表面的波导做微米级耦合 | 康宁 |
| PMF（保偏光纤） | 直接调制，对偏振不敏感，且PMF成本极高 | 由外置激光器供光，偏振态会造成巨大能量损耗 | — |
| Fiber Shuffle（光纤分配盒） | 一发一收两路光纤，人工连接即可 | 光纤密度高，需要重排光纤位置 | 安费诺、TE |
| MPO（多芯连接器） | 400G以下无需多芯并行 | 400G以上需要8根甚至16根光纤并行，而面板空间有限 | 康宁、安费诺、TE |

**关键指标与数据来源**：每端口光纤根数、耦合精度、偏振损耗、面板空间。图片与资料来源包括 Corning、Hyoptic、Senko/US Conec。

**判断标准**

- 只有“旧方案用不到、新约束使其必须”同时成立，才算真实的增量需求；若旧方案同样能解决，则只是已有需求的扩张。
- 增量环节若被传统巨头把持（如康宁、安费诺、TE），成长弹性有限；需要结合 2.3.6 的竞争强度判断。

**海豚案例**

- 《AI 超连接时代：AI 向 “光” 飞奔？》（2026-06-03）：对四大光纤组件（FAU、PMF、Fiber Shuffle、MPO）逐一做新旧对照，说明各自在CPO中“为什么必须”（图片来源：Corning、Hyoptic、Senko/US Conec）。
- 《“‘铜’ 牛夫人” 不走！CPO：真机会 or 镜中花？》（2026-06-24）：把四大组件映射到标的，康宁供FAU、MPO，安费诺与TE供MPO、Fiber Shuffle。

**适用场景与注意事项**：适用于架构切换时寻找“从0到1”的增量环节。注意：增量环节若被传统巨头把持，成长弹性有限；新增组件的需求大小还要回到每端口用量与架构渗透率去测算（见 2.2.7、第7章）。

### 2.3.6 按“价值量×毛利率×竞争强度”给硬件模组定性定位

**方法要点**：把AI网络硬件按模组归类，每类以专用芯片为核心，分别提供集群所需的带宽、信号完整性和计算卸载能力，再用价值量、毛利率、竞争强度三个维度给每类模组做定性定位，用于初步筛选环节与选股。

**操作步骤 / 拆分口径**

1. 按功能把硬件归为交换机、光器件、连接介质（铜缆、光纤）、NIC/DPU，每类找出核心专用芯片。
2. 对每类给出“价值量、毛利率、竞争强度”的定性判断，做成矩阵。
3. 按矩阵得到后续环节排序与选股的先验：芯片优于模组，品牌优于白牌。
4. 用后续数据（毛利率、份额）对定性判断做量化校验。

**定性矩阵**

| 模组 | 价值量 | 毛利率 | 竞争强度 | 核心与说明 |
|---|---|---|---|---|
| 交换机 | 产业链价值量高 | 高 | — | 核心是交换芯片，直接决定整机吞吐、延迟和功耗 |
| 光器件 | 芯片环节高；模组环节也高 | 芯片环节高 | 模组环节竞争激烈 | 芯片环节价值量高、毛利高 |
| 连接介质（铜缆、光纤） | 中等 | — | 竞争激烈 | — |
| NIC/DPU | — | — | — | 正向SmartNIC演进，把非计算任务从CPU上卸载；DPU进一步接管网络、存储、安全任务 |

**关键指标与数据来源**：各模组的价值量、毛利率、竞争者数量。

**判断标准**

- 价值量高、毛利率高、竞争强度低的环节优先；价值量高但竞争激烈的环节（如光模块环节）要打折扣。
- 同一类硬件中，核心芯片环节优于模组组装环节，品牌厂优于白牌厂。
- 定性矩阵只是初筛，需要后续数据验证。

**海豚案例**

- 《AI 时代 DC 互联》（2026-09-08）：给出交换机、光器件、连接介质、NIC/DPU的定性矩阵，以专用芯片为核心划分模组。
- 《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：进一步量化，如交换芯片毛利率50-70%。

**适用场景与注意事项**：适用于硬件产业链的初步筛选。定性判断需要后续数据验证；矩阵中没有明确的格子要留空而不是臆测。投资层面的环节排序与选股准则见 11.3。

### 2.3.7 高价值环节四标准：价值占比、毛利率、供给紧张度、对整机性能的决定性

**方法要点**：判断产业链中谁是“心脏与瓶颈”，要求同时满足四个条件。四条同时成立，才定为产业链首选的高价值赛道，也是识别“卖水人”的通用筛子。

**操作步骤 / 判断标准（四标准缺一不可）**

1. 价值量最大：该环节占整机成本的比例显著高于其他环节。
2. 毛利率最高：附加值与毛利率“双高”。
3. 供给最紧张：稀缺产能直接锁死下游主机交付上限。
4. 技术壁垒最高、决定整机性能：该环节的物理极限划定整机性能上限。

**案例中的数字（燃气轮机叶片）**

| 标准 | 燃机涡轮叶片的情况 |
|---|---|
| 价值量最大 | 叶片（尤其涡轮叶片）约占燃机整机成本35%，显著高于压气机、燃烧室、控制系统 |
| 毛利率最高 | 涡轮叶片毛利率常年在40%以上，附加值与毛利率“双高” |
| 供给最紧张 | 稀缺产能直接锁死下游主机交付上限 |
| 性能决定性 | 叶片耐温极限划定了涡轮进口温度（TIT）的物理上限 |

**关键指标与数据来源**：成本占比（35%）、环节毛利率（40%+）、产能约束、性能决定性。数据来自行业估算，需与上游公司分部财报交叉验证。

**判断标准**：四条同时成立才定为首选；只满足其中一两条（例如价值量大但供给宽松、或毛利率高但对性能无决定性）只算次优环节。推理链条是：占比最大→利润最厚→产能最稀缺→物理极限最硬，层层递进地说明该环节既值钱又卡脖子。

**海豚案例**：《AI 电荒突围：谁能替代重燃？》（2026-04-14）：用四标准把涡轮叶片定为燃机产业链的最高价值环节（占整机成本约35%、毛利率常年40%+、产能稀缺锁死主机交付、耐温极限决定TIT上限）。

**适用场景与注意事项**：适用于任何产业链“卖水人”识别。数据来自行业估算，需与上游公司分部财报交叉验证；四条标准应分别给出证据，而不是只给结论。

### 2.3.8 系统价值量分环节拆分（一次侧 vs 二次侧），估算可触达市场的扩张

**方法要点**：公司从低价值环节延伸到高价值环节时，用系统价值量的分布判断可触达市场（TAM）扩大了多少倍，再看客户层级（间接还是直接对接终端大厂），把直连终端大厂视为后续弹性。

**操作步骤 / 公式**

1. 拆系统价值量分布：以液冷系统为例，一次侧占25-30%，二次侧的泵、冷板、阀门、传感器、控制器占70-75%。
2. 标出公司原覆盖环节与新延伸环节，按公式估算可触达市场的变化：可触达市场倍数 = （原覆盖环节占比 + 新延伸环节占比）÷ 原覆盖环节占比。实际计算时要按公司真正能供货的部件来拆（如只含CDU阀门、传感器，冷板是后续），不能把整个二次侧都算进去。
3. 看客户层级：通过Tier1集成商间接供货，还是直接对接CSP。
4. 把“直连终端大厂”记为后续弹性，而非当前已兑现的收入。

**关键指标与数据来源**：各环节价值量占比、新业务收入、客户层级。

**判断标准**

- 若价值量集中在公司尚未覆盖的环节（二次侧占70-75%），则延伸成功意味着可触达市场成倍扩大；
- 客户层级决定兑现节奏：经Tier1集成商供货，说明尚未直接获得终端大厂订单；直连终端大厂（CSP）才是后续弹性所在。

**海豚案例**：三花（2026-08-27）：液冷产品从一次侧（微通道换热器）延伸到二次侧（CDU阀门、传感器，以后是冷板），二次侧价值占70-75%；客户是英维克、维谛等Tier1，还没有直接对CSP量产，直供CSP是后续弹性。

**适用场景与注意事项**：适合零部件公司向系统高价值环节延伸的情况。价值占比为行业估算，需用BOM数据和公司披露交叉验证；新延伸环节的收入占比、份额要看财报兑现，不能只靠TAM倍数。

### 2.3.9 单位价值量膨胀逻辑：存量倍数加未来升级驱动拆解（单车价值量）

**方法要点**：对有“单车（单机）价值量”逻辑的零部件赛道，先给出静态倍数，再拆现有驱动与未来增量驱动，判断单位价值量是否还有提升空间、行业是否呈价值量膨胀。

**操作步骤 / 拆分口径**

1. 给静态倍数：新能源车热管理系统价值量约为燃油车的2-3倍。
2. 拆现有驱动：
   - 需要管理的部件更多：三电系统，尤其是电池对温度范围要求苛刻，需要精确加热和冷却以防自燃；
   - 缓解里程焦虑要求集成化（减重提效，靠重组系统架构耦合各回路）和低能耗（热泵替代PTC）。
3. 拆未来增量：
   - 架构继续升级：跨域融合、提升热泵利用率、云母和气凝胶隔热材料；
   - 电池带电量和能量密度提升、高压快充，要求更强散热（如宁德时代双面水冷）；
   - 智能化下高算力芯片的散热需求。
4. 汇总结论：单车价值量还有提升空间，行业呈价值量膨胀。

**关键指标与数据来源**：新能源车与燃油车热管理单车价值量倍数（2-3倍）；热泵渗透率；集成化模块（八通阀）渗透；电池能量密度和快充倍率；车载芯片算力。

**判断标准**：每一项驱动都对应一个可跟踪的变量（热泵渗透率、八通阀渗透、电池能量密度/快充倍率、车载芯片算力）；这些变量持续上行，单车价值量就继续膨胀；若变量停滞，则只剩存量倍数。

**海豚案例**：三花智控《三花智控：生意不起眼，凭什么总能抓住风口？》（2026-01-02）：第六部分第二、三节拆解价值量膨胀逻辑，用特斯拉第四代热管理（热泵取消PTC、八通阀高度集成）举例，论证单车价值量仍有提升空间。

**适用场景与注意事项**：适用于汽零、电子零部件等有单车（单机）价值量逻辑的赛道。原文价值量倍数为定性引用，做测算时需要找BOM拆解数据核实。

### 2.3.10 新场景带来的单位价值量跃升测算：参数倍数法（算力卫星）

**方法要点**：用新场景核心参数对比现有基准的倍数，测算新场景对上游各部件的拉动，从而判断单星（单机）价值量的跃升与受益部件。

**操作步骤 / 公式**

1. 公式：新场景核心参数（功耗、带宽）÷ 现有基准 → 价值量倍数 → 受益部件。
2. 太阳翼：算力卫星用电量将大幅超过通信卫星，假设单星功耗100kW，约为目前 Starlink 通信卫星的4倍。
3. 热管理：更高功耗带来更高散热需求，系统复杂度急剧上升，热管理部件价值量预计明显提升。
4. 激光通信：Starlink 卫星星间链路目前可达100Gbps，约为 GEO 高通量卫星的5倍；算力卫星所需带宽可达10Tbps，呈百倍量级增长。

**关键指标与数据来源**：单星功耗（100kW，约4倍）、星间带宽（100Gbps → 10Tbps）。

**判断标准**：核心参数的倍数越大，对应部件的价值量弹性越大（太阳翼约4倍、激光通信百倍量级、热管理明显提升）；不同部件的弹性要分开写，不能用一个倍数覆盖所有环节。

**海豚案例**：《SpaceX 的挑战者们》（2026-04-08）：测算算力卫星对太阳翼（单星功耗100kW、约为Starlink的4倍）、热管理（价值量明显提升）、激光设备（星间带宽100Gbps→10Tbps）的拉动。

**适用场景与注意事项**：适用于新应用场景的上游弹性测算。算力卫星仍属早期假设，参数需随技术与发射节奏更新；参数倍数只代表“潜在价值量”，要落到出货量与份额才是收入。

**本节速查清单**

- [ ] 是否把单机架/单机柜物料归并为清晰的环节（光连接、交换、铜连接、PCB&ABF等），并按价值量从高到低排序，且注明是哪个方案、哪个口径？
- [ ] 每个环节是否拆成“量（配比）×价（速率、形态、材料升级）”，并区分量价齐升、只有量增、边角料？
- [ ] 同一系列不同篇章或不同方案的排序是否核对过口径，避免直接套用？
- [ ] 材料升级类的ASP驱动（如PCB的M2-M9）是否做了“路线分叉下都要升级”的确定性检验？
- [ ] 规格跃升的部件是否给出了提升倍数，并拆了内部技术路线与竞争格局（谁垄断、谁匹配新架构）？
- [ ] 新增组件是否逐项回答了“旧方案为什么用不到、新方案为什么必须”，并映射到供应商？
- [ ] 高价值环节是否同时验证了价值占比、毛利率、供给紧张度、对整机性能的决定性四条标准？
- [ ] 零部件公司向高价值环节延伸时，是否估算了可触达市场扩张倍数，并区分间接/直接客户层级？
- [ ] 单位价值量膨胀是否同时拆了存量倍数和未来升级驱动，并找到可跟踪的变量与BOM数据？
- [ ] 新场景的单位价值量跃升是否用“参数÷基准”的倍数法，并标注参数仍属早期假设？

## 2.4 产业链利润分配与议价权

> 本节导读：本节回答“值钱的环节，利润最终归谁、能不能持续、会往哪里迁移”。2.3 先判断哪里值钱，本节继续追问谁拿走利润：先看技术变革如何改变话语权与价值流向（2.4.1-2.4.3），再看毛利率与合约结构揭示的真实议价权和利润池（2.4.4-2.4.7），然后是 AI 产业链从芯片到云到模型的利润切分与下游反制（2.4.8-2.4.12），最后是行业长期毛利率中枢的判断（2.4.13）。单一业务的毛利测算模型见 9.3，HBM 挤占 DDR 产能的供给传导见 4.3，选股层面的环节排序见 11.3。

### 2.4.1 新架构下的价值流向：平台/交换芯片商、代工封测、上游器件、传统模组商

**方法要点**：当技术从“独立模块”变成“与芯片共封装”时，原来的模组厂会失去主导地位，需要重新判断价值流向。判断标准是：谁掌握新架构下的核心工艺和标准，谁拿走更大的价值份额。

**操作步骤 / 拆分口径**

1. 还原旧架构的供给方式：传统光模块由光学组件和分立器件组成，中际旭创、新易盛、Coherent 等专业厂可以完整提供。
2. 判断新架构的集成层级：CPO 要在晶圆制造和先进封装层面集成，显然不再由模组厂主导。
3. 把价值流向分层并标注各层玩家：

| 层 | 代表玩家 | 角色 |
|---|---|---|
| ① 平台商与交换芯片商 | 英伟达、谷歌、博通、Marvell | 掌握核心技术，定义架构和标准，并卖整套产品 |
| ② Fab 与封测厂 | 台积电、日月光、Amkor | 负责晶圆制造、光电集成、先进封装代工 |
| ③ 上游器件厂 | Coherent、Lumentum | 继续供应光电器件 |
| ④ 传统光模块厂 | 中际旭创、新易盛、Coherent 等 | 过渡期提供 NPO、LPO 方案，以及出于可维护性考虑的折中 CPO 设计中的光引擎模块 |

4. 判断过渡期长短，评估旧玩家受损的节奏。

**关键指标与数据来源**：各环节技术门槛、对标准的掌控力、新旧路线下的角色变化、过渡期长短。

**判断标准**

- 推理链条：集成层级上移（模块级→晶圆/封装级）→ 核心工艺与标准由平台商、交换芯片商和代工封测掌握 → 模组厂的主导权下降，价值份额让位 → 但在过渡期内，NPO、LPO 与折中的 CPO 设计仍给传统模组厂留出空间。
- 路线替代意味着产业链价值被重新分配，新老玩家之间的分配会被市场反复争论，要用过渡期长短来校准节奏。

**海豚案例**

- 《AI 超连接时代：AI 向 “光” 飞奔？》（2026-06-03）：给出 CPO 下产业价值的四层走向（平台与交换芯片商、Fab 与封测厂、上游器件厂、传统光模块厂）。
- 《“‘铜’ 牛夫人” 不走！CPO：真机会 or 镜中花？》（2026-06-24）：强调路线替代意味着产业链价值重新分配，新老玩家之间的分配会被市场反复争论。

**适用场景与注意事项**：适用于集成度提升类的技术变革（SoC 化、共封装、一体化压铸等）。要结合过渡期长短，判断旧玩家受损的节奏；同一家公司在不同层可能同时出现（如 Coherent 既属传统模组厂，又是上游器件厂），需分业务拆开看。

### 2.4.2 话语权迁移分析：产出受制于外部产能、与客户共同设计 → 价值份额下降但总盘扩大

**方法要点**：由新工艺（共同封装、代工 Base Die）推导对某一环节话语权的影响：该环节的产出不再只取决于自身产能，产品又越来越由客户共同定制，于是独立自主权下降、价值份额可能走低；但整个产业链的总盘在扩大。

**操作步骤 / 拆分口径**

1. 产出受制于外部：检验该环节能交付的产量是否还取决于外部产能。HBM 的产量不再只取决于内存厂自身产能，还取决于能拿到多少代工 Base Die 产能和 CoWoS 封装产能；高性能内存已成为内存厂、封装厂和终端用户的共有产品。
2. 与客户共同设计：新一代 HBM 的规格由内存厂与下游客户共同设计，产品更定制化；绑定大客户变得生死攸关，一旦客户换供应商，专门研发的产品很难找到新买家。
3. 拆分谁做哪一段：以海力士 HBM4 为例，只有颗粒生产与堆叠由海力士独立完成；Base Die 与英伟达共同设计、由台积电制作；最终封装也由台积电完成。
4. 区分“份额”与“总盘”：独立自主权下降→价值量份额可能走低；但 AI 让 HBM 全产业链总价值盘大幅增加，目前仍是各方“共同富裕”的阶段。
5. 用毛利率和合约定价数据验证（见 2.4.4）。

**关键指标与数据来源**：各环节价值量份额、客户集中度、对外部产能（CoWoS、代工）的依赖度。

**判断标准**：同时满足“产出依赖外部产能”和“产品由客户共同定制”两条，即判定话语权下移；结论的表述形式是“份额降、总盘升”，不能只讲其中一半；“共同富裕”阶段可能随产能紧缺缓解或总盘增速放缓而结束，需要跟踪。

**海豚案例**

- 海力士、英伟达、台积电《存力接棒算力，HBM为什么“脱颖而出”？》（2026-09-17）：由共同封装和代工 Base Die 两项新工艺推导 HBM 行业的话语权变化，结论是内存厂的独立自主权下降、价值量份额可能走低，但总盘大幅增加。
- 《从HBM限高到NAND加量，英伟达vs存力到底谁拿捏谁？》（2026-09-29）：在情景分析中延伸这一话语权判断。

**适用场景与注意事项**：适用于判断产业链各环节的利润分配和议价权变化。需要用毛利率和合约定价数据验证；Base Die 与 CoWoS 两个入口的细节见 2.4.3，毛利率与合约结构的验证见 2.4.4。

### 2.4.3 HBM 价值与卡点向代工/封装迁移：Base Die + CoWoS 双入口分析

**方法要点**：识别产业链新增的关键工序由谁掌握，把“价值与卡点”从原环节迁移到新增工序的掌控者。HBM 的新入口有两个：Base Die（基底层）和 CoWoS（先进封装）。结论是：内存厂能交付多少 HBM，取决于能从台积电锁到多少代工与封装产能。

**操作步骤 / 拆分口径**

1. **入口一：Base Die**
   - HBM3e 及以前用20nm，内存厂自己能做；HBM4 升到12nm，旗舰需2/3nm，只能交台积电代工（三星可自产）。
   - 门槛抬升的三个原因：位宽翻倍对 PHY 精度要求更高；内存控制器等功能从 XPU 搬到基底层；基底层从通用件变为客户定制件（英伟达 NVHBM 用私有协议，号称带宽+30%、功耗-15%）。
2. **入口二：CoWoS**
   - HBM 与 XPU 共封装在硅中介层上，CoWoS-L 已是主流、占六成以上。
3. **产能对比**：DRAM 晶圆到2027年才有一定释放（+15-20%），CoWoS 产能2027年较2026年翻倍。
4. **推演不同方案的资源消耗**：若走向“降层多颗”，省的是 DRAM 晶圆，耗的是封装产能。

**关键指标与数据来源**：Base Die 制程、CoWoS 产能增速、DRAM 晶圆增速、CoWoS-L 占比。

**判断标准**

- 推理链条：Base Die 制程抬升且变成客户定制件→ 内存厂无法独立完成；CoWoS-L 成为主流且产能翻倍但仍被锁定→ 内存厂交付量取决于从台积电锁到的代工与封装产能→ 价值与卡点向代工、封装迁移。
- 两个入口的产能增速对比（DRAM 晶圆 +15-20% vs CoWoS 翻倍）用来判断瓶颈落在哪一端以及何时松动。

**海豚案例**：台积电/SK海力士/英伟达《(短评)台积电不生产内存却绕不开》（2026-10-08）：用 Base Die + CoWoS 双入口分析 HBM 价值与卡点向台积电迁移；海力士 HBM4 只独立完成颗粒生产和堆叠，基底层与英伟达共同设计、由台积电制作，最终封装也由台积电完成。

**适用场景与注意事项**：适用于半导体价值链话语权判断；产能数据需持续更新。HBM 挤占 DDR 产能的供给传导见 4.3。

### 2.4.4 毛利率悖论：工艺更复杂的 HBM 毛利反低于常规 DRAM，用客户结构和长协定价解释

**方法要点**：当“更复杂、更高端”的产品利润率反而低于常规产品时，不要停留在“工艺难度=议价权”的直觉，而是用客户结构和合约定价结构解释，从而判断议价权的真实归属。

**操作步骤 / 拆分口径**

1. 先摆观察：
   - HBM 成本约为常规 DRAM 的4倍，售价差距却在快速缩小，近几个月常规 DRAM 售价已达 HBM 的80%以上；
   - 海力士管理层年初称 HBM 毛利率约60%，常规 DRAM 可达80%以上。
2. 再给解释：HBM 只供少数大客户、以长约（LTA）锁价，无法灵活调价；常规 DRAM 客户分散，可以随行就市提价。
3. 推论：工艺复杂不等于议价权高，绑定少数大客户反而压低了内存厂的议价权和价值量占比（印证 2.4.2 的话语权迁移判断）。
4. 跟踪变量：据报道新一轮 HBM 合约价有望从15-17美元/GB上调到20-30美元/GB，毛利率劣势将有所缓解。

**关键指标与数据来源**：HBM 与常规 DRAM 毛利率、两者售价比、合约价、客户集中度、长协期限。

**判断标准**

- 议价权归属的判断依据：客户集中度（越集中议价权越弱）、定价结构（长协锁价 vs 随行就市）、售价与成本之比；
- 周期上行时，长协产品弹性低于随行就市的产品；周期下行时则相反；
- 合约价上调是毛利率劣势缓解的前瞻信号，需持续跟踪合约谈判与报道。

**海豚案例**：海力士《从HBM限高到NAND加量，英伟达vs存力到底谁拿捏谁？》（2026-09-29）：以 HBM 毛利约60%、常规 DRAM 毛利可达80%以上、常规 DRAM 售价已达 HBM 的80%以上，说明工艺更复杂的 HBM 毛利反而更低，用客户结构与长协定价解释，并跟踪新一轮合约价从15-17美元/GB向20-30美元/GB的上调。

**适用场景与注意事项**：适用于判断“高端产品”是否真的高利润。周期上行时，长协产品弹性低于随行就市的产品；周期下行时则相反。合约价上调属“据报道”信息，要有二次验证。

### 2.4.5 利润池结构拆分：常规 DDR vs HBM，追赶者即使没攻克高端也能冲击龙头利润

**方法要点**：拆龙头利润的真实来源，把“追赶者没有高端产品所以威胁有限”的直觉用利润池结构去检验——看追赶者切入的细分是不是龙头的利润池，而不是只看技术最前沿的产品。

**操作步骤 / 拆分口径**

1. 比较两条产品线的单GB价格：目前 DDR 与 HBM 单GB价格几乎相当。
2. 比较单GB成本：DDR 制造成本更低，因此 DDR 反而是内存厂主要利润来源。
3. 计算利润池结构：按海豚君此前测算，2028年海力士 DRAM 业务毛利润七成以上来自常规 DDR。
4. 把追赶者的切入点对照利润池：长鑫基于4F²的新产品，其首代产品直接切入服务器 DDR5（常规 DRAM 中门槛与利润都较高的市场）。
5. 判断：若新产品产能和良率爬坡良好，对三大厂利润冲击可能相当显著。

**关键指标与数据来源**：DDR 与 HBM 单GB价格、单GB成本、DRAM 毛利构成（常规 DDR 占比>70%）。

**判断标准**：追赶者的真实威胁取决于它切入的细分是不是龙头的利润池，而不是技术是不是最前沿；产能和良率爬坡是触发利润冲击的关键变量。

**海豚案例**：DRAM 行业/SK 海力士《长鑫把晶体管「竖起来」：绕开 EUV 的追赶路，会撼动存储三巨头吗？》（2026-10-16）：反驳“长鑫没有HBM所以威胁有限”，指出 DDR 与 HBM 单GB价格几乎相当而 DDR 成本更低，2028年海力士 DRAM 毛利润七成以上来自常规 DDR；长鑫基于4F²的新产品首代直接切入服务器 DDR5，竞争压力进一步上升。

**适用场景与注意事项**：适用于判断追赶者对龙头利润的真实威胁。2028年占比为海豚君测算而非公司披露，且依赖价格与成本假设；追赶者的技术追平判断见 8.7。

### 2.4.6 拆 AEC 价值链并找利润归属：Retimer 芯片价值量最大、利润归芯片方

**方法要点**：沿价值链从原材料到成品逐层拆，找出价值量最大的环节，再看利润归谁、份额是否集中、有没有垂直整合优势，从而在细分环节中找出利润池。

**操作步骤 / 拆分口径**

1. 画出价值链：AEC 上游是原材料（铜和塑料），往下是芯片、线缆、连接器制造。
2. 圈出两个高价值量的上游环节：Retimer 芯片和高速连接器。
3. 判断 Retimer 芯片是 AEC 里价值量最大的部分，利润主要归芯片方。
4. 看份额与整合度：Credo 份额超过80%，作为 AEC 的开创者，是目前唯一能同时提供芯片和成品线缆的垂直整合厂商，先发优势明显；Astera Labs 份额次之，Marvell、博通还在扩张。

**关键指标与数据来源**：各环节价值量占比、市场份额（Credo 超80%）、垂直整合程度。数据需来自第三方份额数据。

**判断标准**：四个判断要点——价值量占比、利润归属、份额集中度、垂直整合能力。价值量大、份额高度集中、有垂直整合能力的环节，利润最稳固；仍在扩张的后来者（Marvell、博通）会稀释份额。

**海豚案例**：AWS《AWS 图省事…》（2026-10-12）、《AWS 组网靠「买」…》（2026-10-13）：拆 AEC 价值链，建议关注 Retimer 芯片和高速连接器两个高价值量上游环节，Retimer 芯片价值量最大、利润归芯片方，Credo 份额超过80%。

**适用场景与注意事项**：适用于找细分环节中的利润池。需要第三方份额数据；份额判断随新进入者变化，需要定期更新。

### 2.4.7 看各环节毛利率是否稳定，判断涨价能否沿链传导、上游是否独占增量

**方法要点**：上游材料紧张、涨价时，检验产业链各环节毛利率的时间序列：下游毛利率稳定或提升，说明涨价能够顺价传导；下游毛利率下滑，说明增量被上游独占。

**操作步骤 / 拆分口径**

1. 先用成本树找出上游紧张的材料（见 2.2.2：玻纤布、铜箔等高端材料）。
2. 取涨价期间上下游各环节公司的毛利率时间序列。
3. 比较涨价前后各环节毛利率的变化：
   - 下游毛利率稳定或提升 → 能顺价，上游没有独占增量；
   - 下游毛利率下滑 → 增量被上游独占，下游被挤压。
4. 得出对中下游环节的投资判断。

**关键指标与数据来源**：各环节毛利率的时间序列；数据来自多个环节公司的财报。

**判断标准**：上游材料虽然紧张，但 PCB 产业链各环节的毛利率基本稳定在30-40%，说明涨价能够沿产业链传导，上游并没有独占增量；据此判断 PCB 制造环节不会被上游挤压利润，可以投资。

**海豚案例**：《AMD 跟英伟达 “掰手腕”，Helios 够格吗？》（2026-09-15）：在指出上游材料（玻纤布、铜箔）集中在日系厂商手里的同时，用各环节30-40%的稳定毛利判断 PCB 涨价可传导。

**适用场景与注意事项**：适用于判断涨价周期中的利润分配，需要多个环节公司的财报数据；毛利率稳定只说明涨价被传导，不代表下游一定有定价权，还要结合需求与竞争格局。

### 2.4.8 “上游超高毛利率→下游经济性承压→自研替代”，推导上游毛利率能否持续

**方法要点**：用一条推理链判断上游垄断者的高毛利能否持续：上游拿走绝大部分利润，下游经济性承压，下游就有动力自研或采购性价比更高的方案，上游的份额和毛利率因此面临下滑风险。

**操作步骤 / 推理链**

1. 上游龙头毛利率极高（75%），产业链大部分利润被它拿走。
2. 下游云厂商和模型厂的投入产出比因此承压。
3. 下游有很强的动力自研芯片或采购性价比更高的方案。
4. 上游份额和毛利率随之面临下滑风险。
5. 只有下游应用落地、模型经济性形成正循环，行业才能健康发展。
6. 配合跟踪：管理层目标毛利率（FY27为75%）和主流机构对 FY28 及以后毛利率逐步下滑的预期。

**关键指标与数据来源**：上游毛利率、下游ROI、自研芯片进展、机构远期毛利率预期。

**判断标准**：下游 ROI 是否改善、自研与替代方案进展是否加快，决定上游超额利润能否持续；这套逻辑用来解释“业绩确定、估值却偏低”——市场担心的是毛利率中枢下移与“一家独大”难以持续，而不是近期业绩。

**海豚案例**

- 英伟达（2026-02-26）：高达75%的毛利率意味着钱都被英伟达赚走，下游经济性不足会影响投入，市场认为“一家独大”难以持续。
- 英伟达（2026-05-21）：观点为“算力霸主，正在被‘性价比’围猎”，垄断溢价逐步削弱。

**适用场景与注意事项**：适用于产业链中议价权极强的环节（龙头芯片、垄断零部件），用来判断超额利润能否持续。需要同时看下游自研的实际进展与规模，而不是仅凭动机推断。

### 2.4.9 用第一性原理拆云厂利润率：终端模型价、AI Lab 算力租价、云厂算力成本三个价格

**方法要点**：云厂利润率的根本决定因素是它在 AI 产业链中的议价能力，把这个议价能力量化成三个可观测的价格，追踪价格走势就能推断产业链利润在芯片商、云厂、模型商之间往哪个方向迁移。

**操作步骤 / 公式**

1. 三个价格：
   - ① 终端用户使用大模型的价格（单位 Token 价）；
   - ② AI Lab 向云厂租算力的价格（云租赁价）；
   - ③ 云厂提供算力的成本，再拆成相对固定的电力等运营成本和弹性较大的硬件价格。
2. 两个利润池：
   - AI Lab 的毛利 = 终端价 − 云租价；
   - 云厂的毛利 = 云租价 − 算力成本（固定运营成本 + 硬件价格）。
3. 追踪三个价格的走势，推断利润往哪边迁移（见 2.4.10）。
4. 再叠加收入结构：高毛利的 MaaS/TaaS 业务部分取代了低毛利的裸金属 IaaS，是 AI 云利润率比预期好的另一个原因。

**关键指标与数据来源**：单位 Token 定价、云 GPU 租赁价（$/GPU时）、TCO（Capex 折旧+Opex）、收入结构（IaaS 与 MaaS 占比）。

**判断标准**：三个价格的相对变动决定利润迁移方向；云厂利润率好于预期时，要分别检验是租价上行（价格因素）还是收入结构向 MaaS/TaaS 倾斜（结构因素）。

**海豚案例**：《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：以单位 Token 经济性为主线，用三个价格拆云厂利润率，接续前作《“AI 拉胯” 亚马逊：会上演逆袭大戏吗？》中“云利润率为何好于预期”的疑问。

**适用场景与注意事项**：适用于多层级产业链的利润分配分析（芯片-云-模型、上游-制造-品牌）。前提是三个价格都能观测到；硬件成本的折旧与 Capex 口径要统一。

### 2.4.10 用云租赁价格的走势，判断成本通缩带来的“额外毛利”在云厂与模型商之间如何分配

**方法要点**：终端定价与硬件成本之间的利润由云厂和 AI Lab 共享，分多分少取决于云算力租赁价格的走势。

**操作步骤 / 推理链**

1. 确认成本通缩带来了“额外毛利”（硬件成本下降，终端定价与成本之间的空间变大）。
2. 看云租赁价：
   - 云价大体持平 → 额外毛利几乎全被 AI Lab 拿走；
   - 云价走高 → 云厂也能分到一部分。
3. 对照实际：2025年底以来云算力价格进入明显上行周期，所以云厂分到小头、模型商拿到大头。
4. 最终推论：硬件方的议价权正在向下游转移，其中模型商拿大头、云厂拿小头。

**关键指标与数据来源**：云租价走势、终端 Token 价、单位 Token 成本。

**判断标准**：云租价上行幅度越大，云厂分得的份额越高；只要租价涨幅追不上成本通缩与终端定价空间，大头仍归 AI Lab。

**海豚案例**：《AI 算力：从盛宴到 “剩宴”？》（2026-07-13）：用云租价走势解释云厂和模型商的毛利分配——云租价自2025年底起明显上行，云厂分到小头，模型商拿大头。

**适用场景与注意事项**：适用于三层以上产业链的利润切分。需要中间环节价格（租价、批发价）可观测；与 2.4.9 配套使用——2.4.9 给出三个价格的框架，本方法用租价走势做利润分配的方向判断。

### 2.4.11 跟踪推理单位成本下降，以及产业链利润分配（GPU 垄断溢价、CSP 中间商）

**方法要点**：AI 应用能否普及，取决于推理单位成本是否下降；而成本下降的空间来自对产业链利润分配的重构——绕过赚差价的 CSP 中间商、打破 GPU 的垄断溢价。

**操作步骤 / 拆分口径**

1. 看生产资料重置成本：成本太高，即使 ChatGPT 付费用户很多，AI 成本仍由 App 开发者承担；用户扎堆涌入时，开发商只能限制使用量来控制成本增幅。
2. 看 App 服务商的出路：优化模型架构、做大收入、找更便宜的算力方案，即绕过赚差价的中间商 CSP、打破 GPU 的垄断溢价（引用《AI泡沫原罪：英伟达是AI戒不掉的“毒丸”？》中的产业链利润分配框架）。
3. 看总量与单位的背离：到2025年末，Tokens 消耗仍在爆量，推理总开支依然很高；但由于 GPU 迭代和算力芯片多元化，推理单位成本两年下降了90%以上。
4. 判断：单位成本下降是应用普及的前提。

**关键指标与数据来源**：推理单位成本降幅（90%+）、Tokens 消耗量、推理总开支。需要 Token 价格的时间序列。

**判断标准**：单位成本持续下降（两年降90%以上）而总开支仍高，说明需求在被低成本打开；利润分配上，垄断溢价（GPU）与中间商价差（CSP）是成本下降的空间来源。

**海豚案例**：中国 AI 互联网《火拼 AI 互联网…》（2026-01-09）：以推理单位成本两年下降90%以上、Tokens 消耗仍在爆量为依据，判断应用普及的拐点，并引用利润分配框架说明 App 服务商需绕开 CSP 中间商、打破 GPU 垄断溢价。

**适用场景与注意事项**：适用于判断 AI 应用渗透的拐点。需要 Token 价格的时间序列；单位成本的下降不等于总成本下降，需同时看总开支。

### 2.4.12 开源追平闭源后的价值链议价权迁移：模型厂 → CSP（云厂摆脱裸卖算力的低毛利）

**方法要点**：判断技术格局变化如何改变产业链利润分配：开源模型大幅缩小与闭源的差距后，议价权从模型厂迁向拥有企业平台生态与渠道优势的 CSP。

**操作步骤 / 推理链**

1. 观察开源与闭源模型的性能差距是否大幅缩小。
2. CSP 凭企业平台生态与渠道优势，有望摆脱“裸卖算力”的低利润率模式，结合原有产品服务，把硬件下移带来的议价权收益从“滋润了大半年”的模型厂端拿回。
3. 开源降低门槛 → 加速大模型大宗商品化 → 提高全行业 AI 渗透 → 中游 CSP 企业服务与下游 C 端应用更快进入高速发展期，共同做大增量蛋糕。
4. 结论：模型商品化利空纯模型厂、利好平台与应用。

**关键指标与数据来源**：开源 vs 闭源性能差距、CSP 毛利率、模型厂毛利率。

**判断标准**：开源与闭源差距缩小的幅度越大，模型环节的议价权越弱、平台与渠道环节越强；同时用 CSP 与模型厂毛利率的变化验证议价权是否真的迁移。

**海豚案例**：大模型/云行业《Kimi K3 时刻：中美 AI 产业链叙事要变天？》（2026-07-22）：开源模型大幅缩小与闭源差距，判断 CSP 有望摆脱裸卖算力，把议价权收益从模型厂端拿回；模型商品化利空纯模型厂、利好平台与应用。

**适用场景与注意事项**：适用于判断 AI 产业链中哪一环节受益于模型商品化（云、应用、终端）。与 2.4.10 的“云价走高、模型商拿大头”形成前后对照：议价权的方向会随技术格局变化而反转，需要持续更新。

### 2.4.13 行业长期毛利率下行的四因素框架：区域扩张 / 成本 / 新进入者 / 产业链位置

**方法要点**：判断行业长期毛利率走向时，从四个维度推演毛利中枢，四者叠加则判断毛利中枢下移。

**操作步骤 / 拆分口径**

1. 区域扩张：市场从高价核心市场（美国、西欧、澳洲、中国）向价格敏感的新兴区域（东欧、中东、亚太、印度）扩张，平均单价与毛利下行。
2. 成本：上游原材料涨价无法完全转嫁。
3. 新进入者：高毛利（约40%）吸引新玩家进入。
4. 产业链位置：不生产电芯，受锂矿和电芯价格挤压。
5. 四者叠加，判断毛利中枢下移，并落到具体公司的毛利率假设。

**关键指标与数据来源**：区域需求结构、原材料价格、行业毛利率水平、进入者数量、垂直一体化程度。

**判断标准**：四个因素同时指向下行，则判断长期毛利中枢下移；落到公司层面，用中性假设给出下行幅度。

**海豚案例**：阳光电源《收入倒春寒》（2026-04-28）：欧洲从英国拓展至德国、西班牙，再到波兰、匈牙利、罗马尼亚等东欧市场，价格敏感度更高；结合碳酸锂涨价、新玩家进入、不产电芯，判断行业长期毛利率下行，中性假设阳光2026年储能毛利率30-32%（同比降4.5-6ppt）。

**适用场景与注意事项**：适用于高毛利吸引资本进入的成长型制造业赛道（储能、光伏、电动车等）。四因素的权重因行业而异，要分别给出证据；中性假设只是情景之一，需配合敏感性分析（见第13章）。

**本节速查清单**

- [ ] 技术变革是否改变了集成层级（模块级→晶圆/封装级），谁掌握核心工艺和标准、谁拿走更大价值份额，过渡期多长？
- [ ] 某环节的产出是否受制于外部产能、产品是否由客户共同设计，结论是否同时写了“份额降”与“总盘升”？
- [ ] 新增关键工序（如 Base Die、CoWoS）的掌控者是谁，外部产能增速与自身产能增速对比如何？
- [ ] 高端产品的毛利率是否真的高，是否用客户集中度、长协 vs 随行就市的定价结构解释了差异？
- [ ] 龙头的利润池由哪条产品线贡献，追赶者切入的细分是否正是龙头的利润池；细分环节的价值量占比、利润归属、份额集中度、垂直整合能力是否都核对了？
- [ ] 涨价周期内各环节毛利率时间序列是否稳定，能否据此判断涨价可传导、上游是否独占增量？
- [ ] 上游超额利润能否持续，是否检验了下游 ROI、自研替代进展与机构远期毛利率预期？
- [ ] 三个价格（终端价、租价、算力成本）是否都可观测，利润在各层之间往哪个方向迁移？
- [ ] 技术格局变化（如开源追平闭源）是否改变了产业链议价权的方向？
- [ ] 行业长期毛利率是否按区域扩张、成本、新进入者、产业链位置四因素做了推演并给出情景假设？

## 2.5 产业链传导与上下游联动

> 本节导读：本节回答“冲击沿产业链怎么传、传多快、最后落在谁身上”。当上游原材料或关键零部件涨价、短缺，或下游资本开支、销量发生变化时，用本节的方法写出显式的传导链和时滞，区分“价”与“量”两类冲击，并推导链上公司的指引与业绩预期差。以下游 Capex 测算上游需求总量见 3.1、3.3，HBM 挤占 DDR 产能的供给传导见 4.3，行业层面政策的传导链见 10.1。

### 2.5.1 上游原材料涨价/短缺的“成本→价格→需求→供给”四步传导分析

**方法要点**：上游关键零部件（如存储）涨价甚至短缺时，沿产业链分四步分析对下游的影响，最后评估公司客户结构带来的韧性。

**操作步骤 / 拆分口径**

1. 成本端：下游厂商毛利率受压。
2. 价格端：下游提价转嫁。
3. 需求端：终端出货放缓。
4. 供给端：能否拿到货——短缺比涨价更严重。
5. 评估公司客户结构带来的韧性（如以商用为主，受 C 端影响小）。

**关键指标与数据来源**：存储价格走势、行业 PC 出货增速、公司提价、毛利率。

**判断标准**

- 四步缺一不可：只分析前三步（成本、价格、需求）而忽略供给端，会低估短缺情形下的冲击；
- 推理链条：涨价→毛利率受压→提价转嫁→需求受抑；若进一步短缺，就演变为拿不到货（见 2.5.2）；
- 客户结构偏商用的公司，受C端需求波动影响小，韧性更强。

**海豚案例**

- 戴尔（2026-02-27）：存储价格自2025年下半年起剧烈上涨；结合高通等厂商的看法，问题已从涨价升级为短缺，即使加钱也不一定拿到货，CSG 业务会持续承压。
- 戴尔（2026-05-29）：PC 市场整体增速回落到4%，存储涨价也拉低了公司硬件毛利率（17.8%）；但商用电脑仍增长18%，体现客户结构的韧性。

**适用场景与注意事项**：适合分析上游关键元器件价格周期对中下游的影响。涨价与短缺是两个层级（见 2.5.2），终端厂商的对冲能力见 2.5.3。

### 2.5.2 上游涨价/短缺对下游的挤压：区分“涨价侵蚀毛利”与“短缺卡住出货”

**方法要点**：把上游供给问题对下游的影响拆成两个层级：涨价（压毛利、间接抑制需求）与短缺（直接卡住备货和出货、使营收下滑）。市场若只定价了第一层，短缺升级就构成预期差。

**操作步骤 / 拆分口径**

| 层级 | 机制 | 表现 | 例子 |
|---|---|---|---|
| ① 涨价 | 推高成本、侵蚀毛利率、间接抑制需求 | 下游毛利率下滑 | 美光手机和 PC 存储收入环增约50%，被判断为“手机厂和 PC 厂的毛利率要危了” |
| ② 短缺 | 直接卡住备货和出货 | 下游营收下滑 | 高通预计下季手机收入约60亿，同比约-13%，原因是 DRAM 供应不足 |

1. 先判断上游问题处在哪一层：只是价格上行，还是已经出现供应不足。
2. 若是第一层，估算毛利率压力与间接需求影响；若是第二层，估算出货与营收的直接下滑（存储短缺→备货/出货受阻→营收下滑）。
3. 对照市场预期：看市场是否只考虑了第一层。此前市场只考虑了第一层，预期（目标价）下调只到两位数下滑之前的水平，所以短缺升级就构成预期差。

**关键指标与数据来源**：上游价格涨幅；下游毛利率；下游出货量；下游收入指引。

**判断标准**：从“涨价”升级为“短缺”，是下游收入端而不仅是毛利端的下修信号；当市场预期只覆盖到第一层时，第二层的出现就是负向预期差。

**海豚案例**

- 高通《高通：“存储荒”加码，手机股“在劫难逃”？》（2026-02-05）：存储问题从“涨价”升级为“短缺”，预计下季手机收入约60亿、同比约-13%，原因是 DRAM 供应不足。
- 美光《美光：牛气冲天！…》（2026-06-25）：手机/PC 存储收入环增约50%，判断手机厂和 PC 厂的毛利率要危了。
- 英特尔（2026-04-24）：存储涨价对 PC 市场的挤压是确定性的。

**适用场景与注意事项**：适用于产业链上下游联动分析，尤其是上游大宗或核心零部件供给紧张期。要区分两层冲击，不能只用涨价模型去推短缺情形。

### 2.5.3 上游短缺或涨价对下游终端“价”和“量”的双重冲击，并比较终端厂的对冲能力

**方法要点**：存储涨价不只压低下游毛利率（价），短缺还会直接影响出货量（量）；再逐个比较各终端厂的对冲能力（定价、关税、汇率），得到同一冲击下的不同结果。

**操作步骤 / 拆分口径**

1. 对每家终端厂分别看“价”（毛利率）与“量”（出货、收入）两条线。
2. 列出对冲手段并比较：定价（提价能力）、关税、汇率。
3. 把对冲后的结果与估值、业务线（如 IoT、传统业务）联系起来。

**关键指标与数据来源**：存储价格；终端毛利率；出货量。

**判断标准**：同样的存储涨价/短缺，对冲能力强（有提价能力、受益于关税下降或汇率）的厂商毛利率仍可提升；缺乏对冲手段的厂商毛利率塌陷、出货下滑，估值被压制。

**海豚案例**

- 高通（2026-02-05）：DRAM 供应不足，下季手机营收只有约60亿，同比两位数下滑（“量”端受冲击）。
- 小米（2026-03-24）：手机毛利率跌到8.3%，IoT 同比-20%（“价”与“量”同时承压）。
- 苹果（2026-01-30）：存储涨价逆风下硬件毛利率仍提升（中国区关税从20%降到10%、美元贬值），下季毛利率指引48-49%（对冲能力强）。
- 戴尔（2026-02-27）：存储紧张困扰传统业务，压制估值。

**适用场景与注意事项**：适用于消费电子、PC、服务器。对冲因素各厂不同（关税、汇率、定价），要逐家拆开，避免把某一家的对冲收益误当作整个行业的趋势。

### 2.5.4 存储涨价 → 存储厂盈利 → 扩 Capex → 设备采购：传导链与时滞

**方法要点**：把存储周期向设备股的传导写成显式链条，并用设备商的订单与收入数据逐点验证，同时给出传导的时滞。

**操作步骤 / 拆分口径**

1. 写出链条：存储供需紧张 → 存储价格上涨 → 存储厂扩大资本开支扩产 → 加大对上游设备的采购。
2. 补充规律：多家存储厂的 Capex 与收入维持正相关，涨价推动业绩大增时，Capex 还有机会进一步上调，设备商的存储业务因此持续高增。
3. 逐点验证：
   - AMAT 存储收入同比提速；
   - ASML 存储订单74亿超季节性；
   - 韩国地区占比上升；
   - 美光与 ASML 签订多年期 EUV 供应协议。
4. 标注时滞：从涨价到设备收入通常滞后2-4个季度（先订单、后收入）。

**关键指标与数据来源**：存储价格；存储厂收入与 Capex 的比值；设备商存储收入/订单；韩国地区收入。

**判断标准**：链条上每一节点都有可观测的验证指标（价格→存储厂 Capex/收入比→设备商订单→设备商收入与地区结构）；订单领先收入，所以设备股的拐点先看订单，再看收入。

**海豚案例**

- 应用材料《Capex 狂飙在路上…》（2026-05-15）：给出传导链并指出存储厂 Capex 与收入正相关，涨价推动业绩大增时 Capex 还有机会进一步上调。
- 阿斯麦（2026-01-28）：存储订单爆单（存储订单74亿超季节性）。
- 美光《美光：牛气冲天！…》（2026-06-25）：与 ASML 签 EUV 多年期协议，利好上游设备。

**适用场景与注意事项**：适用于周期品上游设备与材料的研究。从涨价到设备收入通常滞后2-4个季度（先订单、后收入）；以下游 Capex 测算上游设备需求量见 3.1、3.3。

### 2.5.5 用产业链龙头的指引和下游 Capex 预期，推导链上公司的指引上修空间

**方法要点**：把产业链龙头上调后的下游 Capex 预期和自身增长指引当作上游锚，推导链上公司的指引上修空间和市场期待，同时梳理配套公司在龙头新平台中的位置。

**操作步骤 / 拆分口径**

1. 取龙头的新指引与下游 Capex 预期作为锚：英伟达给出五大 CSP 资本开支1.3万亿（原1.1-1.2万亿）、FY28 营收+70%（原约40%）。
2. 推导市场对链上公司的期待：戴尔不仅要上调全年指引，还要给出下一财年展望。
3. 梳理配套公司在龙头新平台中的位置：Blackwell、Vera Rubin、Feynman 合作，以及端到端全栈能力。
4. 估计份额分配：龙头增长不等于每个下游等比例增长。

**关键指标与数据来源**：龙头收入指引、CSP Capex 预期、链上公司指引、合作平台与产品线。

**判断标准**：龙头上调越多、链上公司与龙头的平台绑定越深、全栈能力越强，指引上修的空间和市场期待越大；但要考虑份额分配，避免“龙头增长×100%传导”。

**海豚案例**：戴尔（2026-09-02）：英伟达上调对2027自然年的展望后，市场期待戴尔给出更高全年指引甚至 FY28 增长展望；戴尔具备从 DGX 工作站、机架服务器、存储、网络交换机到软件编排和7×24服务的全栈能力，在 AI 云和企业客户中能拿到更多订单。

**适用场景与注意事项**：适用于上下游清晰的产业链（AI、半导体、汽车、光伏）。龙头增长不等于每个下游等比例增长，要考虑份额分配；Capex 数字需区分口径（年度、自然年、财年）。

### 2.5.6 下游整车销量与成本压力 → 上游零部件的出货与议价能力传导

**方法要点**：把下游整车行业的变化传导到上游零部件，沿“销量→出货”和“成本→议价/ASP”两条线，再叠加客户引入二供的份额稀释。

**操作步骤 / 拆分口径**

1. 销量线：下游新能源车受购置税退坡影响，销量增速放缓，直接压低零部件出货（大客户销量不及预期，零部件出货就不及预期）。
2. 成本线：下游车企面临大宗原材料涨价（铝、铁、电池、存储），对上游零部件价格更敏感，年降要求加强，压制零部件 ASP。
3. 份额线：下游客户引入二供，份额被稀释。
4. 交叉验证：用下游客户自己的财报和月度销量对上游出货做交叉验证。

**关键指标与数据来源**：下游车企销量、原材料价格、客户二供引入、零部件 ASP。

**判断标准**：下游大客户销量不及预期→零部件出货不及预期；原材料涨价→年降压力→ASP 下行；二供引入→份额稀释。三条线同时向下，上游零部件业绩承压；用下游客户财报与上游出货相互印证才算可靠。

**海豚案例**：禾赛（2026-08-19）：ADAS 出货48.6万，低于预期，与新能源车购置税退坡下大客户小米和理想销量增速不及预期有关；下游车企面对上游大宗商品涨价侵蚀毛利，对上游零部件价格敏感度进一步上升；小米引入速腾作为二供。对应理想文章（2026-08-26）中理想销量同比-11%，形成交叉验证。

**适用场景与注意事项**：适用于汽车、消费电子产业链上的零部件公司。需要同时跟踪下游客户的财报和月度销量；大客户占比高的零部件公司，传导更直接。

### 2.5.7 单一公司 Capex 自律对上游设备股的影响：按占比量化

**方法要点**：当某家制造厂“只赚不投”时，是否影响上游设备股的投资逻辑，不凭印象，而是按该公司 Capex 占全行业 Capex 的比重来量化影响是否实质。

**操作步骤 / 推理链**

1. 提出问题：制造厂“只赚不投”是否影响 AI 设备股（阿斯麦、拉姆研究、应用材料）的投资逻辑？
2. 判断产业链结构：产业链已不是齐涨齐跌；垂直堆叠的“全行业摩尔定律”时代，新增收入对应的边际 Capex 强度本就较低。
3. 按占比量化：闪迪26年 Capex 约20亿美元，与铠侠合计约40亿美元，在整个芯片制造 Capex 中占比不高。
4. 结论：难以引其他晶圆厂跟风，也不会拖累设备股逻辑。

**关键指标与数据来源**：公司 Capex、占全行业 Capex 比重、边际资本强度。

**判断标准**：单一公司 Capex 占全行业比重低，且难以引发他人跟风时，其自律对设备股影响有限；若占比高或会引发同行跟风，则要重新评估。

**海豚案例**：闪迪《比 DRAM 还摇钱树，闪迪真有那么香？》（2026-08-17）第三节（只赚不投）：闪迪26年 Capex 约20亿美元，与铠侠合计约40亿美元，在整个芯片制造 Capex 中占比不高，难引其他晶圆厂跟风，也不会拖累设备股逻辑。

**适用场景与注意事项**：产业链上下游传导分析；用占比判断影响是否实质。占比需用行业总 Capex 口径核对，且要同时看是否会引发同行行为的连锁反应。
