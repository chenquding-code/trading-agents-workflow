# 第1章 研究立项与信息准备

> **本章目的**：开题阶段要做四件事：明确研究主线和决定性变量，对标的和问题做性质判断，找出市场分歧与预期差，同时准备好信息来源和口径甄别工具。

**本章小节**：1.1 研究主线与核心变量定位｜1.2 投资属性与问题定性｜1.3 预期差与市场分歧识别｜1.4 信息来源、调研与另类数据｜1.5 口径辨析与信息甄别

## 1.1 研究主线与核心变量定位

> 本节导读：本节回答开题阶段的第一个问题——“这家公司到底研究什么最重要”。当公司业务繁多、叙事复杂或同时存在“旧业务现金牛 + 新业务故事”时，先用增量贡献、利润来源、估值引擎这几把尺子找出决定性板块，再收窄研究范围、给各板块定性、排好驱动因素的主次。本节的产出（决定性变量、板块属性、观察点清单）是后续各章拆解的“靶子”，与 1.2（投资属性定性）、1.3（预期差识别）和第 3 章业务架构拆解配合使用；首篇覆盖的问题框架和开篇写法见 14.3，纯描述性的业务架构拆分见 3.1。

### 1.1.1 用增量贡献占比定位决定性板块与“唯一增长引擎”

**方法要点**：用“增量”而不是“存量”的占比来判断哪个板块决定投资价值，找出单一决定性变量（或唯一增长引擎），据此把研究精力集中到它身上，其余板块用简洁假设带过。

**操作步骤 / 拆分口径 / 公式**：

1. 取公司长期指引（投资者日、长期目标、多年指引），或自建分业务预测，算出总营收增量：总增量 = 目标年总营收 − 基期总营收。
2. 逐板块计算增量贡献占比：板块增量贡献占比 =（板块目标年收入 − 板块基期收入）÷ 总增量；同时计算存量占比 = 板块基期收入 ÷ 基期总收入。
3. 对比“存量占比 vs 增量占比”，刻画业务两极分化：传统业务存量占比高但几乎不贡献增量，新业务存量小但贡献绝大部分增量。
4. 回看历史，把各板块的历史增速、占比变化和指引期内的同比净增额贡献逐一拆开：看非核心板块是否长期停滞或负增长、总营收增速被谁拖累、增长是否只来自单一板块。
5. 逐层下钻：先分“核心 vs 非核心”（如云 vs 非云），再在核心板块内部继续分（如 OCA vs OCI），直到找到真正驱动增长的最小单元；对其增速的持续性（例如多年维持近 50% 或更高）做验证。
6. 作出研究取舍：决定性板块层层细拆、多种方法交叉验证；贡献小的板块用简洁假设，甚至略过不谈。

变体：
- 变体 A（基于长期指引的增量占比）：以公司给出的多年指引为分母，适合有投资者日目标的公司。
- 变体 B（基于历史增速与指引期净增额的逐层下钻）：以历史拆解证明“其他业务基本停滞、增长高度集中”，再用指引期净增额占比确认。

**关键指标与数据来源**：长期指引营收、各板块营收增量、增量贡献占比、存量营收占比；分板块增速、占比、同比净增额贡献占比。来源为公司长期指引（投资者日、长期目标）与财报分部披露，细分口径不披露时用调研/投行测算补齐（见 1.4.2）。

**判断标准**：
- 如果某板块贡献了总增量的绝大部分（案例中为约 90%–100%），它就是“成败的唯一胜负手”，估值和风险都应围绕它展开。
- 存量占比高、增量占比低的板块只是“底仓”，决定下限而不决定估值弹性。
- 推理链条：总增量分解 → 找到唯一来源 → 验证该来源的增速是否持续 → 把研究范围收窄到该来源。
- 指引本身可能偏乐观，识别出核心变量之后必须回头验证指引能否兑现（指引可达成性见 8.5）。

**海豚案例**：
- Oracle《Oracle：AI 算力豪赌，赔率够了吗？》（2026-04-27）：25→30 财年总营收指引从 570 亿到 2250 亿（近 4x），约 92% 的增量（1550 亿）来自 OCI；OCI 以外业务在 26 财年仍占约 70% 营收，但增速只有低个位数到略高于 10%，由此把分析重心放在 OCI。
- 甲骨文《捡剩饭、傍大款！甲骨文拿命博生存？》（2026-01-22）：逐层拆解得出“成败的唯一胜负手：OCI”——a. FY18 以来非云传统业务基本停滞甚至负增长，年收入一直在 300–350 亿美元之间振荡，拖累总营收增速一直只有个位数；b. 云是唯一增长来源，FY26 将贡献过半收入；c. 云内部，原先占比更大的 OCA 增速不到 20% 并逐年放缓，真正的驱动是 OCI，从 FY22 起增速持续在近 50% 或更高；d. 指引期 FY27–30 每年总营收净增额的 90–100% 来自 OCI。由此得出结论：后面的分析只围绕 OCI 展开，其他传统业务略过不谈。

**适用场景与注意事项**：适用于业务繁多但增长高度集中的公司，以及给出多年长期指引的公司；用增量贡献而不是存量占比来决定研究重点。注意：①指引可能偏乐观，核心变量确定后要单独验证；②高度集中也意味着单点风险，需在风险章节（第 13 章）单独列示。

### 1.1.2 识别估值核心引擎业务与非核心业务，分配分析权重

**方法要点**：先判断各业务对“估值”（而不只是对收入）的贡献权重，让分析篇幅和结论向估值引擎倾斜；这是决定财报点评重点的第一步。

**操作步骤 / 拆分口径 / 公式**：

1. 列出分业务的收入占比、毛利率、成长性，估算各业务对估值的贡献。
2. 剔除“体量大但不定价”的业务：低毛利、重资产、强周期的业务（如 EPC/BT）即使收入体量大，也不是估值核心。
3. 锁定估值核心业务：其边际变化决定股价（如储能、美国商业、Neutron）。
4. 篇幅与结论倾斜：财报点评里对估值引擎写足、写透，对非引擎业务只做必要的交代。
5. 确认引擎有没有“换届”：例如某业务已取代旧支柱成为第一大收入来源和估值核心。

**关键指标与数据来源**：分业务收入占比、毛利率、成长性、估值贡献；数据来自公司分部披露与卖方估值拆分。

**判断标准**：毛利率长期偏低、与项目周期强相关的业务不贡献估值溢价；谁的边际变化能改变市场对公司“价值天花板”的看法，谁就是引擎。同一家公司在不同市场叙事下引擎可能不同（如 Palantir 的高估值看美国企业端需求，政府业务只是托底）。

**海豚案例**：
- 阳光电源《平地起惊雷》（2026-04-01）：储能已取代逆变器成为第一大收入支柱和估值核心；电站开发毛利率常年低位，不是利润和估值溢价的引擎。
- Palantir《瑕疵修复，信仰股满血复活？》（2026-08-04）：高估值逻辑主要看美国企业端（商业）需求，政府业务只是托底。
- Rocket Lab《中子号或延期》（2026-08-11）：Neutron 是估值框架中最大的变量。

**适用场景与注意事项**：通用，尤其适用于多业务公司。注意“收入最大”不等于“估值最重”；引擎判断要随业务结构变化滚动更新。

### 1.1.3 用利润来源拆解决定分析框架（会员费占经营利润比重）

**方法要点**：当某业务表观利润率偏低时，先拆解利润究竟来自哪里，再决定用什么框架评价它，避免用错框架得出“利润率低所以不好”的误判。

**操作步骤 / 拆分口径 / 公式**：

1. 取业务的营收、经营利润、经营利润率，与传统同类公司（如沃尔玛美国）比较。
2. 拆解经营利润的来源：会员费占经营利润的比例 = 会员费收入 ÷ 经营利润。该比例在公司不披露时通过调研估算。
3. 若绝大部分经营利润来自会员费、商品零售只是保本微利，则不能用普通零售商框架（看商品毛利率、经营利润率）评价，而应改用会员制框架（会员数、续费率、会员年均消费）。
4. 逻辑定性：商品是信任载体，会员费是沉淀下来的高质量利润。

**关键指标与数据来源**：营收、经营利润、经营利润率、会员费占经营利润比例；财报分部数据 + 调研估算。

**判断标准**：商品毛利率和经营利润率偏低不是减分项，反而说明让利换信任；真正要盯的是会员数、续费率和人均消费等会员经济指标。

**海豚案例**：
- 山姆《沃尔玛里的“Costco”：山姆养成的套路与反套路》（2026-06-09）：FY2026 山姆美国营收约 930 亿美元、经营利润约 24 亿美元、经营利润率约 2.6%（低于沃尔玛美国约 5%+），但约 90% 经营利润来自会员费（结合调研），因此改用会员制框架。

**适用场景与注意事项**：会员制仓储店、订阅制业务；会员费占比通常需调研估算，估算误差要在结论里留出余量。

### 1.1.4 “基本盘 vs 成长点”二分框架

**方法要点**：把公司业务分成“基本盘”（占比大，决定业绩底线）和“成长点”（市场据以给估值的增量逻辑），合起来判断整体增长和估值逻辑，尤其适合转型期公司。

**操作步骤 / 拆分口径 / 公式**：

1. 识别两者的占比：谁是占比大的基本盘，谁是市场给估值的成长点。
2. 看基本盘是否企稳：是在下滑、企稳还是回暖。
3. 看成长点的增速是否放缓、占比是否足以拉动整体。
4. 合在一起判断整体增长和估值逻辑：基本盘企稳 + 成长点放量 = 估值有支撑；基本盘下滑 + 成长点占比不足以拉动 = 整体承压。

**关键指标与数据来源**：各业务占比、增速、对整体增长的贡献度；来自财报分部披露。

**判断标准**：成长点“增速不够快、占比不够大”时，拉不动整体；基本盘受外部因素（如存储涨价）冲击而承压，在“难以避免”时要把它与成长点的看点分开表述。

**海豚案例**：
- 海康 2026-04-18：境内业务是最大的基本盘，三大事业群都在下滑；海外和创新业务是成长点，但海外下半年增速仅 6%、创新占比仅 27%，对整体拉动有限。
- 戴尔 2026-02-27：传统 CSG（客户端业务）受存储涨价影响，承压“难以避免”，AI 是最大看点。
- AMD 2026-02-04：CPU 回暖让基本盘稳步提升，AI GPU（MI450）是中长期看点。

**适用场景与注意事项**：通用的个股和财报框架，尤其适合转型期公司。与 1.1.5 的区别：本方法着重“占比 + 增速 + 对整体增长的拉动”，1.1.5 着重“业绩”与“估值倍数”由谁决定。

### 1.1.5 “业绩基本盘 vs 估值叙事”二分法

**方法要点**：把公司拆成两层——决定短期业绩的基本盘，和决定估值倍数的叙事（期权）；基本盘决定下限，叙事决定上限，叙事没兑现前，高 PE 已经包含预期。

**操作步骤 / 拆分口径 / 公式**：

1. 找出基本盘业务：哪块业务贡献当期收入和利润，它所处的周期位置（如涨价周期）。
2. 找出估值叙事业务：市场据以给估值弹性的新业务或期权。
3. 为叙事业务设定“里程碑”：能把叙事变成业绩的具体事件（大客户订单、量产、收入贡献）。
4. 检查当前 PE 里隐含了多少对叙事的预期；里程碑未兑现时，高估值意味着已透支预期。

**关键指标与数据来源**：基本盘业务收入与利润；叙事业务的里程碑（订单、量产）；PE 中隐含的预期。

**判断标准**：涨价、周期回暖只支撑业绩（下限）；真正的估值弹性要看叙事业务的实质订单和收入贡献。设备类公司则看扩产确定性与未来 2–3 年的高成长。

**海豚案例**：
- 英特尔《英特尔：CPU 涨价救场，翻身还得看代工？》（2026-07-24）：“涨价撑业绩，代工定估值”。CPU（客户端 + 服务器）是业绩基本盘，涨价周期带来直接支撑；真正的估值弹性来自对外代工，需要大客户在 14A/18A 上的实质订单和收入贡献。
- 高通（2026-02-05）：手机基本盘承压，AI PC 和数据中心提供成长看点（手机基本盘 vs AI 数据中心）。
- 应用材料（2026-08-14）：半导体设备投资主要关注扩产确定性和未来 2–3 年的高成长。

**适用场景与注意事项**：适用于转型期或有新业务期权的公司。关键是识别哪些里程碑能把叙事变成业绩，并为里程碑设定验证时间；叙事长期不兑现时要警惕估值回落。

### 1.1.6 分部投资属性定位与估值支柱（稳定现金流 / 内容周期 / 成长曲线）

**方法要点**：对多元化集团，先给每个板块定性投资属性、定义各自的驱动变量，再解读业务架构调整背后的战略逻辑，据此判断估值拉升来自新增长而不是靠守成保利润。

**操作步骤 / 拆分口径 / 公式**：

1. 梳理业务架构新旧对照：新架构如何重新划分（例如按内容划分为娱乐、体育、体验，内容与分发渠道融合）。
2. 为每个分部定性投资属性并定义驱动变量：
   - 成熟板块（如主题公园体验）= 消费驱动的稳定现金流，受整体消费影响；
   - 内容板块（娱乐）= 影片制作发行，看电影排片和电影市场消费力；
   - 流媒体 = 中长期重心，但很大一部分是在弥补传统渠道的没落，并非完全增量（流媒体与传统媒体像跷跷板两端）；
   - 体育 = 新的成长曲线（新版 ESPN、整合福克斯并联手华纳、与 NFL 交叉持股）。
3. 解读架构调整的战略逻辑：内容与分发渠道融合，从源头解决首发渠道冲突（热门大片先上流媒体还是先上影院）。
4. 财报跟踪时按分部看收入、分部 OPM、内容成本，核对各属性是否兑现。
5. 回到估值：判断估值拉升来自新媒体扩张，而不是退守死保利润。

**关键指标与数据来源**：分板块收入和利润占比、增长驱动、分部收入、分部 OPM、内容成本；数据来自财报分部披露。

**判断标准**：体验板块看 OPM 稳定性；娱乐看内容收入与排片；流媒体要区分“真增量”与“渠道迁移”；体育要看版权成本对 OPM 的影响。

**海豚案例**：
- 迪士尼《迪士尼：新官首秀不俗》（2026-05-06）：新架构下娱乐、体育、体验三块；内容与渠道不再割裂，从源头解决热门大片先上 Disney+ 还是先上影院的纠结；流媒体与传统媒体是跷跷板两端；体育（ESPN 新平台、与 NFL 交叉持股）是新成长路线。
- 迪士尼（2026-02-03）：娱乐内容收入 +7%（《疯狂动物城》），体育略 miss、高内容成本。
- 迪士尼（2026-08-05）：体验 OPM 30%+，娱乐收入 +6%、OPM 15%+5ppt，体育 OPM 同比 −5ppt（NBA 版权成本、总决赛安排紧凑）。

**适用场景与注意事项**：适合多业务集团，尤其综合性传媒集团；分部属性不是一成不变的，要随架构调整和阶段更新。

### 1.1.7 核心驱动因素的主次排序与关键观察点清单

**方法要点**：明确排出“决定股价的主要因素”和“次要因素”，并写下需要跟踪的具体事件，后续每季点评都能对照清单更新判断。

**操作步骤 / 拆分口径 / 公式**：

1. 列出所有可能影响股价的驱动变量，区分主要因素与次要因素：
   - 主要因素举例：宏观楼市景气度、云增速、Qwen 模型排名、MI450 量产交付、无人车格局；
   - 次要因素举例：控费能力、二航道增长、平头哥成本优势。
2. 对每个驱动变量写明量化口径或具体观察事件（新大客户、独立上市、SOTA 模型、MI450 新增客户与新增订单、机架级量产交付）。
3. 估算次要因素对大局的影响，写明“影响有限”的依据（如租赁利润占比不超过 10%）。
4. 每季财报后对照清单更新：哪些观察点已兑现、哪些被证伪、清单是否要增删。

**关键指标与数据来源**：主驱动变量、次驱动变量、观察事件；来自财报、行业数据与公司公告。

**判断标准**：把有限的篇幅给主要因素；次要因素只有在改变主要因素的判断时才升级；观察点要具体、可验证，避免写成泛泛的“关注 AI 进展”。

**海豚案例**：
- 贝壳《一线再松绑》（2026-08-21）：核心决定因素是国内楼市（尤其一二线），次要因素是控费挤利润的能力和二航道增长；租赁利润占比不超过 10%，对大局影响有限。
- 阿里《阿里狂投》（2026-08-21）：“2+1”个点，即阿里云提速幅度和 Qwen 旗舰模型排名，次要的是平头哥自研芯片的成本优势。
- 阿里《阿里：电商退位，AI 上位》（2026-05-14）：关键观察点包括能否推出稳定 SOTA 的大模型，以及平头哥对外销售和独立上市进展。
- AMD《CPU“狂飙”》（2026-05-06）：中长期关注 MI450 的新增客户、新增订单和机架级量产交付。

**适用场景与注意事项**：适合所有长期跟踪的公司。观察点清单应纳入系列文的跟踪档案（见 14.4）；证伪条件和关键跟踪指标见 13.2。

**相关方法交叉引用**：描述性的业务架构拆分详见 3.1；首篇覆盖的问题框架与开篇写法详见 14.3；收入驱动公式与量价拆分详见 3.2。

**本节速查清单**

- [ ] 是否用“增量贡献占比”而不是存量占比找出了决定性板块或唯一增长引擎，并据此收窄了研究范围？
- [ ] 是否区分了“收入最大”与“估值最重”的业务，把篇幅向估值引擎倾斜？
- [ ] 利润率偏低的业务，是否先拆过利润来源（如会员费占比）再选分析框架？
- [ ] 是否把公司拆成“基本盘 vs 成长点”，并说明基本盘是否企稳、成长点占比是否足以拉动整体？
- [ ] 是否把“业绩基本盘”与“估值叙事”分层，并为叙事设定了可验证的里程碑？
- [ ] 多元化集团的每个分部是否定了投资属性（稳定现金流 / 内容周期 / 成长曲线）与驱动变量？

## 1.2 投资属性与问题定性

> 本节导读：本节解决“这是一只什么性质的票、眼前的问题是什么性质的问题”。在深入拆财务和估值之前，先判断收益来自 Beta 还是 Alpha、周期还是成长、问题是结构性还是阶段性、股价由叙事还是基本面驱动、投资逻辑处于哪个验证阶段，这些定性决定了后面用什么估值方法、给什么时间尺度、采取什么姿态。与 1.1（决定性变量）、1.3（预期差）配合；估值驱动阶段与定价锚切换见 10.3，根据叙事阶段给入场策略见 14.2。

### 1.2.1 Beta vs Alpha、周期股 vs 成长股、左侧交易 vs 拐点的定位判断

**方法要点**：在财报观点里先给标的定性，三个二选一的问题决定结论姿态：收益来自行业/政策 Beta 还是公司 Alpha；是偏周期股还是能持续跑赢的成长股；低估值带来的修复是左侧交易机会还是基本面拐点。

**操作步骤 / 拆分口径 / 公式**：

1. 判断收益来源：主要来自行业或政策 Beta，还是公司层面的 Alpha（结合历史执行力判断）。
2. 判断股性：是跟随宏观需求的偏周期股，还是能持续跑赢的成长股。
3. 判断低估值的含义：属于左侧交易机会（估值修复），还是基本面拐点（盈利趋势确实向上）。
4. 把定位翻译成建议：机会票博弈、视为 Beta 敞口、观望等待验证、防御首选。

**关键指标与数据来源**：历史股价表现、业绩与行业相关性、估值分位。

**判断标准**：
- 业绩与宏观/行业景气高度相关、看点多为阶段性 → 偏周期股，可作机会票博弈，不值得长拿；
- 受益于政策红利（如海南封关）且公司自身 Alpha 不突出 → 视为 Beta 敞口，不期待公司 Alpha；
- 低估值但缺乏基本面拐点证据 → 左侧交易/估值修复，保守投资者观望等待验证；
- 波动小、业绩确定性高 → 防御性配置首选。

**海豚案例**：
- Airbnb（2026-02-13）：更多是跟随宏观酒旅需求的偏周期股，今年的看点多为阶段性，可作机会票博弈，不值得长拿。
- 中国中免（2026-03-31、2026-04-29）：视为获取海南封关红利的 Beta 股，不期待公司 Alpha。
- Lululemon（2026-03-18、2026-06-05）：低估值的左侧交易或估值修复机会，而非拐点，保守投资者观望。
- Costco（2026-09-25）：防御性配置的第一选择。

**适用场景与注意事项**：适用于所有个股观点输出。定位要有数据支撑（股价与行业相关性、估值分位、历史执行力），避免凭印象贴标签。

### 1.2.2 结构性问题 vs 周期/阶段性问题定性，以及修复时间尺度（年 vs 季）

**方法要点**：区分业绩下滑究竟是一两季新品没踩中（阶段性），还是核心品类的结构性退潮；结构性问题的修复以“年”计，估值修复也不应期待短期拐点。

**操作步骤 / 拆分口径 / 公式**：

1. 量化核心单品/核心品类的增速：是否持续下滑，下滑速率多大。
2. 做品类迁移调研：需求是否向其他品类、其他方向迁移。
3. 看竞品份额侵蚀：份额是在被谁拿走。
4. 评估品牌心智的深层壁垒（身份认同、社群文化）：这决定了品牌能否在结构性问题中保住基本盘。
5. 若品牌已过单品扩张期，检查新品是否同时满足功能、审美、场景和社交传播；只有更新而没有爆点，对客流拉动有限。
6. 给出修复的时间尺度：结构性 = 以年计；阶段性 = 以季计。

**关键指标与数据来源**：核心单品增速、品类需求迁移、份额变化；来源为财报单品披露、调研、第三方份额数据。

**判断标准**：核心品类以固定速度持续收缩（如每年约 20%）且新品对冲不了，就是结构性退潮；此时不应对估值修复抱短期拐点预期。

**海豚案例**：
- Lululemon（2026-09-04）：紧身裤约 −20%，Align、Wunder Train 经典款贡献女装大头，正以每年约 20% 的速度收缩，离身系列对冲不了，属于核心品类结构性退潮，修复时间尺度是年而不是季度。
- Lululemon（2026-06-05）：品牌过了单品扩张期后，新品必须同时满足功能、审美、场景和社交传播，只有更新而没有爆点，对客流拉动有限。

**适用场景与注意事项**：适用于大单品驱动的消费品牌在成熟期的判断。要避免两种误判：把结构性问题当成阶段性问题而过早抄底；把一两季的新品失误当成结构性问题而过度悲观。

### 1.2.3 区分战略性业绩空窗期与周期性或竞争性下滑

**方法要点**：面对连续下滑的业绩，先列客观原因，再判断这是“溃败”还是“主动选择的战略空窗期”，并为空窗期设定反转时间表和验证节点。

**操作步骤 / 拆分口径 / 公式**：

1. 描述事实：年度销量及同比（2025 年 164 万辆，同比 −8.6%，连续两年下滑）。
2. 列出客观原因：产品周期老化（Model 3 和 Y）、中国价格战、降价策略边际效用递减。
3. 判断是溃败还是主动选择：看公司是否主动放弃了某些项目（马斯克放弃没有全自动驾驶架构的廉价版 Model 2.5），资源是否转向了更有价值的新方向（全部投入 2026 年 4 月投产的 Cybercab）。
4. 给出反转路径：2026 年年化 250 万辆、2027 年 400 万辆、2028 年突破 500 万辆。
5. 设置验证节点：新项目投产时间、产能爬坡目标是否兑现。

**关键指标与数据来源**：年度销量和同比；产品周期年龄；被放弃的项目；新项目投产时间和产能爬坡目标。

**判断标准**：判断依据是①资源是否转向了更有价值的新方向；②是否有可验证的反转时间表。满足这两点，就定性为追求颠覆性创新主动选择的战略空窗期，而非周期性或竞争性溃败。

**海豚案例**：
- 特斯拉《从造车到造梦：1.5 万亿 AI 特斯拉真的贵了吗？》（2026-01-12，第三部分①）：称卖车业务处于“黎明前的至暗时刻”，定性为战略空窗期而非溃败。

**适用场景与注意事项**：适用于转型期公司的业绩下滑定性。战略空窗期的判断一定要设置验证节点，因为产能爬坡目标往往被延误。

### 1.2.4 周期属性判断：下行期收入下滑归因（价格驱动 vs 销量驱动）并与传统周期品对比

**方法要点**：在行业最差的年份拆解出货量、ASP、收入的同比，判断收入跌幅来自价还是量，再对照传统周期行业，判断公司/行业属于“需求型周期”还是“供给自动扩张型周期”，并由此界定下行期抗跌性的上限。

**操作步骤 / 拆分口径 / 公式**：

1. 取行业最差年份，分别计算公司与行业的出货量同比、ASP（每 GB 均价）同比、收入同比。
2. 做价量归因：收入同比 ≈ 量同比 + 价同比；判断跌幅来源（“销量对下滑的贡献为零”即纯价格驱动）。
3. 对照钢铁、化工、航运等传统周期行业：它们下行时需求萎缩、量价同向承压，减产后价格能企稳。
4. 检验 NAND 类行业：减了产出货不降、价格单独塌近四成 → 价格是寡头博弈的结果，技术与成本优势换不来溢价，只体现为亏损幅度的差异。
5. 界定抗跌性上限，并得出“成本领先 ≠ 定价权”的结论。

**关键指标与数据来源**：公司与行业的收入同比、ASP 同比、出货量同比；行业层面的量价数据需要 TrendForce 等机构数据。

**判断标准**：量价同向承压、减产能稳价 → 传统需求型周期；量不降、价单独塌 → 供给自动扩张、寡头博弈型周期，公司只能靠成本差异缩小亏损，不具定价权。

**海豚案例**：
- 闪迪《NAND 天性“多产”…》（2026-09-18）：2023 年闪迪出货基本持平，每 GB 均价与收入同比均降 37.8%；同年行业收入约 −37%、ASP −42%，“销量对下滑的贡献为零”。

**适用场景与注意事项**：适用于判断一个行业是需求型周期还是供给自动扩张型周期；需要行业层面的量价数据。更完整的周期股估值见 9.4。

### 1.2.5 “双周期共振”叙事框架：成长周期与传统周期同向向上

**方法要点**：把公司业务拆成成长周期和传统周期，两者同向向上时即“双周期共振”，构成“既有成长故事、又有传统周期加固稳定性”的叙事，并同时检验原本的破坏点是否发生。

**操作步骤 / 拆分口径 / 公式**：

1. 拆出成长周期：如 AI 服务器随 Blackwell/Rubin 放量。
2. 拆出传统周期：如数据中心传统服务器更新换代，加上 CPU 与存储紧缺带来的涨价。
3. 检验两者是否同向向上：收入和前瞻指标（积压订单）双双高增，利润率不降反升。
4. 检验原本的破坏点：低毛利 AI 服务器是否拉低整体毛利率（若毛利率随涨价反而抬头，破坏点未发生）。
5. 对照估值：业绩释放遇上要求不高的估值（如 PE 回落到 12x 附近），形成叙事。

**关键指标与数据来源**：AI 收入/订单、传统业务增速、毛利率、PE、积压订单。

**判断标准**：两个周期同向 + 利润率不降反升 + 估值仍低 = 共振成立；若毛利率被成长业务显著拖累，或两个周期其实由同一个驱动因素驱动，则共振不成立。

**海豚案例**：
- 戴尔（2026-09-02）：“戴尔是 AI 基建为主线下的显著双周期共振”，收入与积压订单双高增，毛利率随涨价“显著抬头”，估值回落到 12x PE 附近；业绩释放遇上要求不高的估值。

**适用场景与注意事项**：适用于同时拥有成长业务与周期业务的公司（服务器、半导体设备、电力设备）。要验证两个周期确实同向，且不是同一驱动因素的重复计算。把更多周期叠加起来的“多周期共振”框架与溢价持续的前提，详见 10.3。

### 1.2.6 识别股价由行业叙事还是基本面驱动；面对“归零”风险时观望；用行业指数对照

**方法要点**：当行业性叙事变化对股价的影响大于业绩时，股价主要跟随叙事和行业估值；此时用行业指数判断个股反弹是否只是行业估值修复，并在存在被完全颠覆的可能时先观望。

**操作步骤 / 拆分口径 / 公式**：

1. 判断驱动力：近期股价波动更多对应叙事变化（如“AI 如何改变软件”）还是公司业绩变化幅度。
2. 用行业指数（如 IGV）对照：看行业指数自低点的反弹幅度，以及与历史高点的距离，判断个股涨幅是不是行业估值修复。
3. 评估颠覆风险：是否存在“被完全颠覆（归零）”的可能。若两种对立情形（巨头凭 know-how 领先 vs AI 降低自研成本、坐席减少）无法判断，先观望（“君子不立于危墙之下”）。
4. 叙事被证伪后：估值可以修复，但不应回到过去的溢价水平。

**关键指标与数据来源**：行业指数涨跌（IGV）、与历史高点的距离、公司业绩变化幅度、行业估值。

**判断标准**：叙事变化 > 业绩变化时，股价是叙事股；业绩稳定但存在归零可能时，也不应因“便宜”而介入；便宜但看不到向上空间，“旁观”即可。

**海豚案例**：
- Salesforce《AI 替代论摧枯拉朽》（2026-02-26）：两种对立情形（巨头凭 know-how 领先 vs AI 降低自研成本、坐席减少）无法判断，类比此前对 Uber 的看法，选择观望。
- Salesforce《既没增长也没利润》（2026-05-28）：便宜但看不到向上空间，“旁观”即可。
- Salesforce《“AI 替代论”证伪？》（2026-08-27）：IGV 自低点反弹超 30%，距历史高点约 10%，盘后大涨来自叙事变化，而非业绩拐点；AI 替代论至少暂时被证伪，估值可修复，但回到 SaaS 溢价不合理。

**适用场景与注意事项**：适用于行业性叙事冲击（AI 颠覆、政策）下的个股判断。要区分“行业估值修复”与“公司基本面拐点”，前者不能外推为后者。

### 1.2.7 投资逻辑阶段切换判断：技术验证 → 产能爬坡验证

**方法要点**：先判断公司处于哪个验证阶段，以确定市场关注焦点：技术验证阶段看“技术可靠吗、客户会用吗”；需求确定性被消化后，焦点转向“供给能否跟上”，即产能爬坡验证。

**操作步骤 / 拆分口径 / 公式**：

1. 用里程碑事件判断技术验证是否完成：订单规模级别、客户类型、部署规模。
   - 此前为示范验证期：订单以中小规模为主（如韩国 SK），驱动力是企业或地方政府的清洁能源诉求；
   - 2024 年是分水岭：核心需求来自数据中心、出现 GW 级部署，产品角色从离网替代电源变为主力电源。
2. 需求确定性被市场消化后，切换到产能爬坡验证：瓶颈是工艺、外部供应还是组织（具体调研方法见 1.4.3）。
3. 以新阶段的核心矛盾重新组织研究与跟踪指标。

**关键指标与数据来源**：订单规模级别、客户类型、里程碑事件。

**判断标准**：当订单级别、客户类型发生质变（中小订单 → GW 级部署，示范客户 → 数据中心）时，技术验证阶段结束，市场的定价焦点转向供给兑现能力。

**海豚案例**：
- Bloom Energy（2026-07-20）：以 2024 年为分水岭，需求端从示范验证切换到数据中心驱动的 GW 级部署，之后市场焦点转向“供给能否跟上”，由此引出对工艺、供应商、组织瓶颈的调研（见 1.4.3）。

**适用场景与注意事项**：新能源、硬科技等成长型制造企业，用于识别不同阶段的核心矛盾。注意阶段不是单向的：产能爬坡不达预期会让市场重新质疑技术/需求。

### 1.2.8 业务纯度 = 弹性：在细分周期中选“纯血”标的

**方法要点**：用业务纯度判断哪只标的最能表达某一细分周期；周期主线切到哪个细分，就选在该细分里“收入占比最纯”的公司。

**操作步骤 / 拆分口径 / 公式**：

1. 梳理目标细分周期（如 NAND）的主要玩家，计算各自在该细分的收入占比（如 NAND 收入占比）。
2. 判断周期主线所在：周期主线在 HBM 时，重心在 DRAM/HBM 的原厂受益，纯 NAND 公司未受益；当存储周期转向 NAND，all in NAND 的公司弹性更大。
3. 选择纯度最高者作为最佳表达标的，同时记录“纯度越高，下行时风险越集中”。

**关键指标与数据来源**：分业务收入占比（NAND 收入占比）。

**判断标准**：NAND 三大原厂（三星、海力士、美光）重心在 DRAM/HBM；闪迪甩掉 HDD 后收入全部来自 NAND，是最纯粹的一个，因此在 NAND 周期中弹性最大。

**海豚案例**：
- 闪迪《AI 推理大爆发，“悲催”闪迪真有凤凰涅槃？》（2026-09-14，第二节）：闪迪收入全部来自 NAND，周期主线在 HBM 时未受益，周期转向 NAND 时弹性最大。
- 对比海力士：NAND 收入占比约 20%–25%（《海力士赴美…》2026-07-10、《SK 海力士：长协能熨平周期？…》2026-10-09）。

**适用场景与注意事项**：板块轮动、细分周期交易；纯度高也意味着下行时风险集中，需结合 1.2.4 的价量归因评估下行风险。

**相关方法交叉引用**：多周期共振框架（拆解暴涨的四大驱动周期，以及持续享受溢价的前提）详见 10.3；周期股估值详见 9.4。

**本节速查清单**

- [ ] 是否明确了标的收益来自 Beta 还是 Alpha、偏周期还是成长，并把定位翻译成了建议姿态？
- [ ] 低估值的含义是否分清了“左侧交易/估值修复”与“基本面拐点”？
- [ ] 业绩问题是结构性还是阶段性？是否给出了以“年”或“季”计的修复时间尺度？
- [ ] 业绩下滑是战略空窗期还是周期性/竞争性下滑？是否列了客观原因、放弃项目和可验证的反转时间表？
- [ ] 周期下行期的收入跌幅是否做了价/量归因，并与传统周期品对比？
- [ ] 若主张“双周期共振”，是否验证了两周期同向、非同一驱动重复计算、原破坏点未发生？
- [ ] 股价是叙事驱动还是基本面驱动？是否用行业指数对照，并对“归零”风险保持观望？
- [ ] 当前投资逻辑处于技术验证还是产能爬坡验证阶段？该阶段的核心矛盾是什么？
- [ ] 选股表达细分周期时，是否对比了业务纯度及其带来的下行风险集中？

## 1.3 预期差与市场分歧识别

> 本节导读：本节用定性的方式回答“市场已经知道什么、相信什么、分歧在哪里”——区分已知已定价与边际增量，看机构预期分布与是否 priced in，拆解市场已打入的悲观预期，把多空双方的论证摆在一起并检验共同的隐含前提，识别公司战略与市场偏好的错配，并对未来预期差来源排序。财报前后点评、事件快评都从这一步起笔。与之配合：从估值倒推隐含预期的定量方法见 10.1，自有预测与公司指引的差额见 8.5，发布会“期待清单 vs 实际内容”见 12.5，做空报告的增量信息判断见 12.2。

### 1.3.1 “已知已定价”与“边际增量信息”的区分

**方法要点**：看财报或事件后的股价反应，第一步是把信息分成“事件前已知、已被定价”和“真正的边际增量”两类；股价方向由边际增量决定，而不是业绩本身的好坏。

**操作步骤 / 拆分口径 / 公式**：

1. 梳理事件前已被定价的信息：公司此前的展望、已发生的客户变动、市场一致预期（卖方一致预期、买方预期、社区讨论）。
2. 对照事件新披露的数据（Capex、FCF、订单、指引），找出真正的边际增量。
3. 用“边际增量”而不是“业绩好坏”解释股价方向：边际增量为负时，业绩再好也可能下跌；边际增量被预期覆盖时，只算“符合预期”。
4. 同类情形举例对照：
   - 业绩好股价跌：好的部分（云加速、电商亏损触底）早在展望里，增量是天量 Capex 和负自由现金流；
   - 事件已发生：客户变动在财报前已发生、机构已提前下调预期，增量只是管理层的“认证”；
   - 指引低于或等于预期：指引数字如果低于市场已经抬高的预期，只算“符合预期”。

**关键指标与数据来源**：事件前一致预期；公司前次指引；事件新披露的数据（Capex、FCF、订单）；来源包括卖方一致预期、买方预期、社区讨论。

**判断标准**：事件分析的第一步。信息的增量越大，对基本面与估值的调整幅度越大；非增量信息只影响情绪。

**海豚案例**：
- 阿里《阿里 800 亿融资：外卖补贴市场买单，AI 才真未来？》（2026-08-24）：“业绩好股价跌”——云加速和电商亏损触底早在展望里，边际增量是 670 亿资本开支和 −450 亿自由现金流。
- 博通（2026-07-07）：客户变动在财报前已发生，主流机构已提前下调 AI 收入展望，增量只是管理层的“认证”。
- 英伟达（2026-03-17）：GTC 的 2025–2027 数据中心累计 1 万亿收入指引，低于市场预期（已在 1 万亿以上），只算“符合预期”。

**适用场景与注意事项**：所有事件驱动分析的第一步。前提是准确掌握事件前的市场预期；如果对预期的把握有偏差，增量判断会整体失真。

### 1.3.2 机构预期分布与 priced-in 判断

**方法要点**：汇总机构对即将发布季度的预期分布，结合股价年内走势，判断调整已经消化了多少负面，从而评估财报事件的风险收益比。

**操作步骤 / 拆分口径 / 公式**：

1. 汇总机构对即将发布季度的收入预期分布：是符合指引、小 beat 还是大幅超指引。
2. 看对下一季度的担忧：如高基数下的增速压力（基数效应）。
3. 结合开年以来的股价调整：判断调整是否已消化部分负面与不确定性（priced in）。
4. 综合判断：预期本身不高 + 股价已调整 → 财报事件的风险收益比改善。

**关键指标与数据来源**：机构季度收入预期 vs 公司指引、下一季度基数效应、年内股价调整幅度。

**判断标准**：多数机构预期中性略偏积极（符合指引或小 beat），且股价已调整，说明部分负面已被消化，下行风险有限。

**海豚案例**：
- AppLovin（2026-01-20）：机构对 Q4 预期多为符合指引或小 beat，部分担忧 Q1 高基数下的增速，开年以来的股价调整说明已 priced in 一部分负面。

**适用场景与注意事项**：适用于财报前的个股点评；需要卖方覆盖充分才有可靠的预期分布。

### 1.3.3 讨论新业务叙事时同步检查传统业务，并拆解市场已打入的悲观预期

**方法要点**：讨论新业务（如 AI）预期时，同步检查传统业务是否稳健作为估值的“底仓”论据，再逐条拆解市场已经打进股价的悲观预期，判断哪些可能被证伪。

**操作步骤 / 拆分口径 / 公式**：

1. 列出传统业务的“底仓”论据：游戏看产品管线，广告看效率提升是否走完。
2. 列出市场已打入股价的悲观预期清单（如对 AI 入口的悲观、去年高基数导致增长放缓、高 Capex 使盈利提效暂缓）。
3. 逐条检验这些悲观预期：用产品管线、去年基数、效率提升空间判断哪些可能被证伪。
4. 给出结论：被证伪的悲观预期，就是潜在的预期差来源。

**关键指标与数据来源**：游戏产品管线；广告增速与效率；去年基数。

**判断标准**：新业务讲故事时，老业务是否仍是现金牛是估值安全垫；悲观预期里有被产品管线、基数变化或效率提升证伪的部分，说明股价已隐含过度悲观。

**海豚案例**：
- 腾讯（2026-01-26）：市场打入的悲观预期包括 AI 入口的悲观、去年游戏和广告高基数导致增长放缓、高 Capex 使盈利提效暂缓；但 2026 年是游戏大年，《王者荣耀世界》即将公测，还有《逆战：未来》《洛克王国》等，《无畏契约》《三角洲》靠赛季运营维持热度；广告短期市场担心投流税，但 AI 带来的投放效率提升还没走完（视频号、微信搜一搜、QQ 浏览器）。

**适用场景与注意事项**：适用于“新业务讲故事、老业务做现金牛”的公司。

### 1.3.4 “公司战略 vs 市场偏好”错配框架，明确股价拐点的两类催化

**方法要点**：把股价下跌解释为公司的选择（重增长、轻利润）与市场偏好（对非 AI 受益公司更看重即期可见的利润）的错配，再把股价拐点的催化剂明确为两条，并判断各自何时到来。

**操作步骤 / 拆分口径 / 公式**：

1. 描述错配：公司选择 vs 市场偏好，把它作为股价下跌的核心原因之一。
2. 明确股价拐点的两类催化：
   - a. 公司利润、尤其是核心板块利润率出现拐点；
   - b. 市场风险偏好扭转，愿意为远期增长定价。
3. 判断 a 什么时候到来：中短期仍承压，中长期必然改善；对照卖方对利润率拐点的共识时点，判断本季是否可能提前。
4. 找出“唯一可能让利润率永远达不到目标的因素”（只有行业激烈竞争），论证阶段性投入不会让利润率永久低于目标。

**关键指标与数据来源**：核心板块利润率、市场风格偏好、卖方对利润率拐点的共识时点。

**判断标准**：若投入是阶段性的、利润率目标有支撑，则错配会随着利润拐点或风险偏好扭转而修复；若存在永久性的竞争压制，则属于另一类问题。

**海豚案例**：
- SEA（2026-05-12）：“这个公司战略选择和市场偏好间的错配可以说是导致公司近期股价跌跌不休的核心原因之一”；主流卖方共识是 26 年下半年电商利润率触底回升，本季可能提前；阶段性投入不会让利润率永久低于目标（2%）。

**适用场景与注意事项**：适用于处在投入期的成长公司。

### 1.3.5 多空对立论证，并检验双方共同的隐含前提

**方法要点**：处理“股价表现丑陋”类问题时，把多头和空头逻辑并列写出，找出双方推演共享的前提，再用公司实际战略动作证伪该前提，而不是在结论上来回打转。

**操作步骤 / 拆分口径 / 公式**：

1. 列多头逻辑：如腾讯一贯后发先至；拥有市场唯一的全量关系网沉淀，用户刷完抖音、逛完淘宝仍回微信。
2. 列空头逻辑：短中期离不开，但时长被侵蚀，类比抖音对腾讯生态的影响；长期社交关系迁移有先例（微博、QQ → 微信）。
3. 指出双方推演共享的隐含前提：如“腾讯长时间无从反击”。
4. 用公司实际战略动作证伪该前提：LLM 人才抢人大战与团队搭建，补基模与组织架构的课；审慎的 Capex 背后可能有客观限制。
5. 给出时间窗口与待观察事项：如 Q1 春节最易获曝光，巨头必有动作；元宝出什么牌。

**关键指标与数据来源**：用户时长份额、人才招聘、资本开支、产品发布节奏。

**判断标准**：关键是找出多空共有的前提，而不是在结论上拉扯；当该前提被公司实际动作削弱，空头论证的基础就不稳。

**海豚案例**：
- 腾讯《（短评）腾讯 AI 太安静》（2026-01-16）：多头（后发先至、全量关系网）、空头（时长被侵蚀、社交关系迁移有先例）并列，检验“腾讯长时间无从反击”这一共同前提，并用人才抢人大战与团队搭建、审慎 capex 的背后限制证伪，给出春节窗口与元宝动作的观察点。

**适用场景与注意事项**：适用于有争议的龙头股。多空论证后要落到可跟踪的事件与时间窗口。

### 1.3.6 按优先级列出未来预期差来源

**方法要点**：明确“未来潜在预期差在哪里”并排序，把高估值成长股的结论落在可验证的优先级上，并与当前收入规模对比潜在空间。

**操作步骤 / 拆分口径 / 公式**：

1. 列出潜在预期差来源并排序：
   - ① 首要看关键产品进度（如 Neutron 成败决定能否与 SpaceX 站在同一水平）：判断确定性高，只是时间问题；不考虑 SpaceX 与 Blue Origin 时，进度领先其余竞争者且差距拉大；地缘政治因素使中国竞争者难以直接影响；
   - ② 在此基础上看各类订单获取能力（美国军方与政府、商业、海外）：确定性有，问题在于拿多少；
   - ③ 盈利端随规模扩大改善，无需担心。
2. 与当前收入对比潜在空间：当前收入仅略超 6 亿美元，说明增长空间极大。

**关键指标与数据来源**：关键产品进度、订单获取、毛利率与费用率。

**判断标准**：预期差来源的优先级 = 对结论影响大小 × 不确定性；确定性高、只是时间问题的，放在前面做“确定性论证”；真正有预期差的是“拿多少”这一类。

**海豚案例**：
- Rocket Lab（2026-04-10）：按“关键产品进度 → 订单获取能力 → 盈利端”排序预期差来源，对照当前收入仅略超 6 亿美元的体量说明增长空间极大。

**适用场景与注意事项**：高估值成长股的投资结论表达；与 14.1 结论表达配合使用。

### 1.3.7 看增速趋势而非绝对值

**方法要点**：绝对值受口径影响很大，长期视角更应看增速趋势；比较头部玩家近一个季度的平均月环比，判断行业整体是否还在增长、份额往谁那边转。

**操作步骤 / 拆分口径 / 公式**：

1. 当数字口径存在争议时，不纠缠绝对值，转看各玩家近一个季度的平均月环比（如 ARR 季度平均月环比）。
2. 比较头部玩家的环比：判断行业整体是否继续增长；份额往谁那边转。
3. 数字争议引发回调时，用增速趋势判断基本面有没有变。

**关键指标与数据来源**：ARR 季度平均月环比。

**判断标准**：增速趋势没有变坏，则争议只是口径或情绪问题，不构成基本面利空。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”…》（2026-10-09）：OpenAI Q3 月环比平均约 10%，Anthropic 约 3%（存在一些小麻烦），全行业继续增长。

**适用场景与注意事项**：适用于口径不一的高增长行业。口径辨析的具体方法见 1.5.4–1.5.8；按月环比增速外推并对比公司年度目标与市场预期的方法详见 8.6。

**相关方法交叉引用**：ARR 按月环比增速外推 + 对比公司年度目标与市场预期 +“超目标已 priced in”与隐含年化增速判断，详见 8.6。

- [ ] 是否把未来预期差来源按优先级排序，并与当前收入规模对比空间？
- [ ] 数字口径有争议时，是否转看增速趋势（平均月环比）而非绝对值？

## 1.4 信息来源、调研与另类数据

> 本节导读：本节讲“信息从哪里来、公司没披露的怎么补、怎么用一手体验和高频数据验证判断”。当公司不披露分部数据、新业务没有口径、需要验证技术对旧业务的侵蚀，或需要提前捕捉战略意图和潜在大单时使用。核心纪律是：多层次组合数据源、逐条标注来源、区分事实/调研/推测，并对每个来源的口径偏差保持警觉。与 1.5（口径辨析与信息甄别）紧密配套——本节负责“拿到信息”，1.5 负责“判断信息真伪与口径”。持股变动监测（CCASS 等）见 11.2，行业专属月度经营数据（如券商 DARTs）见 15.8，新业务里程碑进度跟踪见 7.3。

### 1.4.1 多层次数据源组合与来源标注（区分事实、调研与推测）

**方法要点**：在个股分析中组合使用多层级数据源，并在图表下方和行文中逐条标注来源，让读者能区分哪些是事实、哪些是调研、哪些是推测；同时评估每个来源的口径偏差，调研信息矛盾时用合同、周期等硬信息裁决。

**操作步骤 / 拆分口径 / 公式**：

1. 搭建多层数据底座，每一层都标注来源（图表下方标注“资料来源：…，Dolphin Research”）：
   - ① 一手官方文档：Electron/Neutron Payload User's Guide、公司官网与专利、官方安全架构图、AWS 实例参数、官方芯片参数；
   - ② 第三方高频数据：Sensor Tower 的 DAU 与流水、BofA 的 Pixel 追踪、Northbeam、BuiltWith、App Store 榜单、QuestMobile 的 DAU、IDC 出货份额；
   - ③ 行业研究机构：SemiAnalysis 对云 AI 收入结构与数据中心产能的统计；
   - ④ 卖方研究与调研：UBS 游戏开发商调研、Wells Fargo 项目预测、JPM 调研、大摩（MS）的 CSP 模型与机柜 BOM、卖方调研和模型；
   - ⑤ 公开基准平台：OpenBenchmarking、MMLU-Pro 跑分；
   - ⑥ 媒体报道与产业调研：路透的 14GW，电堆工序、供应商、单用户成本、行业调研价格（如 P800 价格）、香港经济日报的收入预期、业内披露的加价幅度；
   - ⑦ 公司沟通渠道：管理层电话会和小会（业绩小会、Callback 小会）、草根调研、亲测内测。
2. 对每一条数据标注类型：事实（官方披露）、调研（渠道/专家）、推测（自己的推演）。
3. 评估每个来源的口径偏差与样本偏差。
4. 调研信息互相矛盾时，用合同、周期等硬信息裁决（方法见 1.5.10）。

**关键指标与数据来源**：数据源清单及各自口径；图表来源标注。

**判断标准**：越是硬信息（官方文档、合同条款、财报披露），权重越高；调研/媒体信息只用于判断量级和结构；推测要明确标注并留有不确定性。

**海豚案例**：
- 博通（2026-07-07）：JPM 调研、MS 的机柜 BOM（图表标注 Source：MS, Dolphin Research）、业内披露的加价幅度。
- 昆仑芯（2026-01-02）：IDC 出货份额、香港经济日报的收入预期、行业调研的 P800 价格。
- 百度（2026-09-07）：大摩的 CSP 模型、Callback 小会。
- 腾讯（2026-01-26）：公众号点击量的草根调研、业绩小会。
- 阿里（2026-01-16）：QuestMobile 的 DAU。
- Rocket Lab（2026-04-10）、Meta（2026-09-23）、Amazon（2026-06-24）、AppLovin（2026-01-20）、Bloom Energy（2026-07-20）、Meta（2026-07-10）：均按上述一手文档、第三方高频、行业研究机构、卖方调研、公开基准、媒体与产业调研等分层组合数据源，并在图表下标注“资料来源：…，Dolphin Research”。

**适用场景与注意事项**：个股研究的数据底座搭建，通用。数据源口径不一时，要在后续估值中做敏感性或统一口径。

### 1.4.2 公司未披露数据时，用产业链调研、投行/外资行测算、第三方机构与电话会信息补全

**方法要点**：公司不披露产品级收入、分业务利润、费用率、渗透率时，用产业链调研、投行/外资行测算、第三方机构数据和电话会信息拼出量级与结构，并在文中注明“据调研”“参考投行测算”“参考外行拆分”，只用于判断量级和结构。

**操作步骤 / 拆分口径 / 公式**：

变体 A：补齐细分产品线收入、占比与毛利率
1. 收集产业链调研与主流投行的测算，给出各产品线的收入规模、占比和毛利率。
2. 在文中显式注明数据来源类型（“据调研”“参考投行测算”）。
3. 用公司电话会指引和第三方机构数据（Gartner、Yole、LightCounting、Cignal AI、SemiAnalysis、The Information、Bernstein 等）交叉印证。
4. 只把这些数字用于判断量级和结构，结论要稳健到数据误差之外。

变体 B：补齐分业务利润、费用率、渗透率等经营指标
1. 对公司未单独披露的指标，引用外资行调研/模型（如 1P EBIT、履约费用率、会员渗透率）、第三方机构数据（CPC、3P GMV、线上渗透率、消费频次）、公司电话会/业绩会交流信息，并标注来源。
2. 注意不同来源口径不一致：同一指标不同文章引用的数值可能差异较大，需要统一口径或在估值中对不同来源做敏感性。

**关键指标与数据来源**：产品线收入、占比、毛利率；产业链调研、投行测算、Gartner、Yole、LightCounting、Cignal AI、SemiAnalysis、The Information、Bernstein；外资行调研、摩根士丹利、Marketplace Pulse、Market Pulse、Statista、E-marketer、MetricsCart、中金、沙利文、中国旅游饭店业协会、混沌学园、行业白皮书。

**判断标准**：补数的数据只作量级与结构判断，不作精确数字；两个以上独立来源能相互印证时可信度更高；来源口径冲突时以口径更清晰、与公司披露更一致的为准，并留出敏感性。

**海豚案例**：
- Lumentum 上篇和中篇（2026-09-24 / 2026-10-05）：EML 约 6.4 亿（约 20%）、CW 约 0.5 亿（2%）、光模块约 7.2 亿（约 24%）、电信约 12 亿（其中 AI 约 3 亿），均为调研口径。
- Oracle（2026-04-27）：OCI 细项（数据库 20–21 亿、Core OCI 75 亿+、AI 不足 20 亿）参考投行测算。
- Meta（2026-07-06）：新签算力规模引用 SemiAnalysis。
- 沃尔玛《沃尔玛：老兵“奇袭”电商…》（2026-06-08）：1P EBIT 约 −2% 来自外资行调研，WFS vs FBA 来自摩根士丹利，CPC 来自 Marketplace Pulse。
- 沃尔玛《沃尔玛：老兵不老…》（2026-06-10）：3P GMV 180 亿/11% 来自 Market Pulse，与中篇大行调研 450 亿/26% 口径不同。
- 亚朵（2026-01-13）：睡眠数据来自中国睡眠研究会白皮书，服务一致性来自 2024 中国连锁酒店服务质量白皮书。

**适用场景与注意事项**：通用，适用于所有缺乏分部披露的公司；调研和外部估算误差较大。1P 自营与 3P 平台盈利结构拆解（缺披露时借外资行调研）详见 8.1。

### 1.4.3 产业调研识别真实执行瓶颈，并用内部预期分歧给出自身出货区间

**方法要点**：先排除“伪瓶颈”，再用产业调研找真实卡点（工艺、外部供应、组织），结合内部不同团队的出货预期与爬坡节奏，给出自己的出货区间，并区分“硬瓶颈/产能天花板”与“爬坡速度”问题。

**操作步骤 / 拆分口径 / 公式**：

1. 排除伪瓶颈：先确认哪些看似瓶颈的环节不是真正限制。
2. 用调研找真实卡点，分三类：
   - 工艺：如电堆烧结的还原工序需改造标准烧结炉（加装氢气/氩气管道），单批次改造超 1 个月且需测试验证，叠加内部工程师资源有限；
   - 外部供应：台湾高力的翅片式微通道换热器、印度厂商的热盒与重整器组件；
   - 组织：内部供应链路线分歧（一方倾向引入中国供应商以降本保质，另一方倾向留在印度），新供应商导入慢。
3. 收集内部不同团队的出货预期（印度团队 3.5GW、生产端专家约 2GW），结合爬坡节奏，给出自己的区间：2027 年实际出货约 2–2.5GW，大概率达不到 3GW。
4. 区分“硬瓶颈/产能天花板”与“爬坡速度”问题：本例中路径清晰，关键在执行效率。

**关键指标与数据来源**：工序改造周期、关键供应商、内部各团队出货预期；来源为产业调研与专家访谈。

**判断标准**：看卡点是否有明确的解决路径和时间；内部预期分歧大时，采用偏保守的区间并说明依据；执行效率而非技术可行性是主要风险。

**海豚案例**：
- Bloom Energy（2026-07-20）：调研识别电堆烧结工序改造、外部关键组件供应、内部供应链路线分歧三类瓶颈，给出 2027 年实际出货约 2–2.5GW、大概率达不到 3GW 的判断。

**适用场景与注意事项**：制造业产能兑现尽调；调研信息需交叉验证，不同团队的预期分歧本身是重要信息。与 1.2.7（产能爬坡验证阶段）配合使用。

### 1.4.4 第一时间亲测或参会体验新产品，记录功能边界、bug 和闭环程度

**方法要点**：新产品发布后第一时间亲自体验（还会拉上亲友一起用），把体验结论变成可验证的一手信息，并通过与 AI 对话“套话”获取后续功能规划。

**操作步骤 / 拆分口径 / 公式**：

1. 第一时间体验或参会：申请内测、现场参加发布会、拉亲友一起用。
2. 记录三件事：功能实现到什么程度；有什么 bug；交易或任务能否在应用内闭环（是否需要跳转）。
3. 与产品内的 AI 对话“套话”，获取后续功能规划。
4. 把体验结论与数据（用户数据、DAU 等）交叉验证，避免仅凭体验下结论。

**关键指标与数据来源**：功能清单；交互体验；bug；闭环程度（是否需要跳转）。

**判断标准**：功能停留在 Chatbot 与简单任务 Agent，还是已形成复杂场景的闭环；能否无跳转完成“选择到支付”的全流程，是判断商业化与生态协同能力的关键。

**海豚案例**：
- 腾讯《偷袭珍珠港时刻！腾讯 AI 上群聊“王炸”，豆包会危吗？》（2026-01-26）：海豚君参与元宝派内测，功能暂时停留在 Chatbot（文字和图片）和简单任务 Agent（提醒、天气、文章总结、简易 PPT），融入了腾讯会议；bug 是微信文件不能一键转发到元宝派；从元宝口中得知后续还有更多派对功能。
- 阿里《千问：AI 互联网时代，阿里要卷土重来？》（2026-01-16）：现场参加发布会，发现只有淘宝闪购能在千问 App 内无跳转完成从选择到支付的全流程。

**适用场景与注意事项**：适用于 C 端产品和互联网公司。体验结论需要用数据验证（用户口径见 1.5.1）。

### 1.4.5 用草根调研的高频数据验证新技术对旧业务的侵蚀

**方法要点**：用草根调研拿到的高频数据，验证新技术对存量业务的侵蚀程度，剔除公司内部策略调整的干扰后，判断用户注意力是否真在转移，由此推出公司必须应对的紧迫性。

**操作步骤 / 拆分口径 / 公式**：

1. 取草根调研的高频数据（内容点击量同比、使用时长）。
2. 剔除公司内部策略调整的影响（如推荐算法变化）。
3. 判断剩余的变化是否反映用户注意力转移，以及转移的原因（如 AI 缩短了获取信息的时间，不必再读长文）。
4. 推演影响范围：核心腹地（公众号、朋友圈）是否会被侵蚀，由此推出公司的应对紧迫性（“必须出牌”）。

**关键指标与数据来源**：内容点击量同比；使用时长；草根调研。

**判断标准**：剔除内部因素后仍显著下滑，才算真实侵蚀；侵蚀指向核心腹地时，公司必须有动作，应对节奏成为跟踪点。

**海豚案例**：
- 腾讯（2026-01-26）：草根调研显示，微信四季度公众号点击量同比下滑近 30%；剔除推荐算法调整的影响后，判断用户注意力在转移，公众号、朋友圈这些核心腹地会被侵蚀，所以腾讯必须出牌。

**适用场景与注意事项**：适用于判断颠覆性技术对存量业务的影响；需要剔除内部策略带来的干扰。

### 1.4.6 第三方高频追踪：用代理指标跟踪运营规模与未单独披露业务的渗透

**方法要点**：公司不披露高频运营指标或不单独披露新业务时，用第三方追踪网站和代理指标（车队规模、像素安装商户数）跟踪扩张速度与渗透，同时标注口径差异与统计方式。

**操作步骤 / 拆分口径 / 公式**：

变体 A：第三方追踪网站跟踪车队规模，并标注注册与可运营的口径差异
1. 用第三方 Robotaxi 追踪网站的数据跟踪扩张速度：无监督车队规模、车队增速、运营城市数、无监督累计里程。
2. 对比竞品规模，判断商业化阶段。
3. 提醒口径：登记车辆并非全部处于可运营状态，部分可能仍用于测试或配有安全监督员。

变体 B：用第三方追踪的 Pixel 安装商户数跟踪未单独披露的新业务渗透（APP 电商广告）
1. 用美银去重统计的 AXON Pixel 安装商户数：看月净增量、累计商户数、相对其此前预期、净增环比变化。
2. 看新增商户来源结构（73% 来自 Shopify）推断客户规模与平均 GMV（Shopify 商户偏小，平均 GMV 偏小）。
3. 判断逻辑：累计数略高于预期为正面，但净增环比下降、新增偏中小商家，提示中大商家投放意愿未进一步提升。

**关键指标与数据来源**：
- A：无监督车队规模；车队增速；运营城市数；无监督累计里程；竞品车队规模；注册与可运营的差异。
- B：Pixel 月净增安装数（12 月 +450）、累计安装商户（约 4000 家）、新增来源结构（Shopify 占 73%）、隐含平均 GMV。

**判断标准**：
- A：车队增速、城市覆盖和累计里程显示扩张速度，但要与竞品规模对比定位阶段；注册数不等于可运营数。
- B：累计数与预期、净增环比、来源结构三者合看；总量略超预期但结构偏中小商家、净增放缓时，不能解读为中大客户加速。

**海豚案例**：
- 特斯拉《Cybercab 发布会：告别概念，开启 Robotaxi 大时代？》（2026-09-04）：第三方追踪网站显示，特斯拉无监督 Robotaxi 车队从 6 月 30 日的 57 辆增至 8 月 31 日的 156 辆，扩张约 200%；覆盖美国 7 座城市，无监督行驶里程超 100 万英里；对比 Waymo 约 3800 辆、30 多个城市，特斯拉仍处商业化早期；同时提醒登记车辆并非全部处于可运营状态，部分可能仍用于测试或配有安全监督员（特斯拉在德州登记的自动驾驶车辆总计约 420 辆）。
- AppLovin（2026-01-20）：BofA 数据显示 12 月净增 450、隐含累计 4000 家，稍高于其预期但净增环比下降；新增来源 73% 来自 Shopify。

**适用场景与注意事项**：A 适用于需要高频跟踪运营指标的新业务；B 适合 SDK、像素、插件型产品的渗透追踪（广告技术、SaaS 插件）。第三方数据需注意统计口径、去重方式和滞后性；对口径差异的进一步辨析见 1.5.9。

### 1.4.7 用 Sensor Tower 流水倒推付费人数与付费率，并修正偏差方向

**方法要点**：用榜单与 Sensor Tower 数据追踪热度，再由日流水倒推付费人数和付费率，对假设的偏差方向给出修正，并对标龙头产品的付费率判断订阅变现空间。

**操作步骤 / 拆分口径 / 公式**：

1. 追踪热度：榜单与 Sensor Tower（仅 iOS）数据，上线两周仍为 iOS 美区免费榜 TOP1，DAU 近 25 万，日流水 2000–3000 美元。
2. 倒推步骤：
   - ① iOS 付费人数 ≈ 两周日均流水 2000 美元 ÷ 最低套餐 20 美元/月 ≈ 1500 人；
   - ② 假设 iOS 占全端付费人口 1/3 → 全端约 4500 人；
   - ③ 付费率 = 全端付费人数 ÷ 过去两周平均 DAU 15 万 ≈ 3%；
   - ④ 修正偏差方向：套餐按最低价算、iOS 占比一般不止 1/3 → 实际付费率明显更低；
   - ⑤ 对标：ChatGPT 覆盖更复杂生产场景、10 亿周活，付费率也仅 5%。
3. 结论：订阅付费不宜乐观，多数用户停留在免费层（每周 1 亿 Tokens 额度）。

**关键指标与数据来源**：下载榜排名、DAU、日流水、套餐价格、iOS 占比假设、对标付费率；来源为 Sensor Tower、App Store 榜单。

**判断标准**：倒推付费率明显低于对标产品（如 5%）时，订阅变现预期应保守；所有假设（套餐价格、iOS 占比）都要写明偏差方向，不要给出单点精确值。

**海豚案例**：
- Meta（2026-09-23）“订阅：短期很难乐观”：上述倒推链条，付费率约 3% 且实际更低，对标 ChatGPT 的 5%。

**适用场景与注意事项**：订阅制 App 早期付费估算；结果对假设敏感，必须写明偏差方向。该类“流水倒推付费人数”属于单位经济的起点，完整单位经济模型见 4.1。

### 1.4.8 利用环保审批等监管文件追踪潜在大单

**方法要点**：在公司公告之外，用环保许可、并网申请等公开监管文件挖掘潜在订单，这类文件常比公司公告更早透露项目规模和设备选型。

**操作步骤 / 拆分口径 / 公式**：

1. 检索监管文件（环保审批、并网申请等），提取项目装机规模（GW）与设备选型。
2. 与公司产品的交付能力对照（如 90–120 天“即插即用”交付），判断公司是否切入顶级云厂商供应链。
3. 把审批规模折算成潜在订单规模，并对其打折处理（审批不等于确定订单）。

**关键指标与数据来源**：环保审批文件中的装机规模（GW）、设备选型。

**判断标准**：审批文件披露的规模 + 公司交付能力匹配 → 超级大单仍有爆发潜力；但审批不等于订单，需折价并等待公司公告确认。

**海豚案例**：
- 《AI 电荒突围》（2026-04-14）：据最新环保审批文件披露，德州规划中的离网数据中心集群有望部署约 1.5GW 的 BE（Bloom Energy）设备；结合 BE 90–120 天“即插即用”的交付能力，判断其正切入 Meta、Google 等顶级云厂商供应链，未来超级大单仍有爆发潜力。

**适用场景与注意事项**：适用于能源、基建、数据中心等需监管审批的项目。审批文件不等于确定订单，需打折处理。

### 1.4.9 招聘岗位 JD 作为公司战略意图信号

**方法要点**：从公司官网招聘信息挖掘未公开的新业务方向，结合历史行为强化推断，并明确标注“未证实”。

**操作步骤 / 拆分口径 / 公式**：

1. 浏览公司官网招聘，寻找与现有业务不同的新岗位及其关键词（如“下一代社交平台创始后端工程师”、内容分发引擎）。
2. 由岗位职责推断业务意图：做内容分发引擎 → 做社交是为获取 1P 用户数据，以提升电商广告投放效果。
3. 用历史行为（如曾参与竞购 TikTok）加强推断，给出可能路径（自建或直接收购社交平台）。
4. 显式标注“未证实”，不把推断当作事实。

**关键指标与数据来源**：招聘岗位关键词、历史并购/竞购行为。

**判断标准**：岗位职责与现有业务缺口吻合、历史行为方向一致时，推断可信度更高；但招聘信号不等于确定投入。

**海豚案例**：
- AppLovin《（短评）AppLovin 盘中盘后大涨》（2026-02-20）：从“下一代社交平台创始后端工程师”岗位推断其做社交平台是为获取 1P 用户数据、提升电商广告投放效果，并以曾参与竞购 TikTok 的历史行为加强推断。

**适用场景与注意事项**：适用于判断公司未公开的新业务布局；招聘信号不等于确定投入，需标注“未证实”。

**相关方法交叉引用**：1P 自营与 3P 平台盈利结构拆解（缺披露时借外资行调研）详见 8.1；多源另类数据交叉验证并甄别数据质量详见 1.5.9。

## 1.5 口径辨析与信息甄别

> 本节导读：本节解决“拿到的数字和消息是不是真的、口径是不是可比、增量到底有多大”。当公司官宣的用户/付费/ARR 数字口径含混、跨公司比较口径不一、调研信息互相矛盾、社媒传闻或媒体报道驱动股价异动时使用。核心思路是：先统一口径，再用合同、周期、估值倍数、公司自身规划等硬约束交叉校验，最后量化“真实利空/利多有多大”。与 1.4（信息来源与调研）配合——1.4 负责取得信息，本节负责甄别；指引口径见 8.5，订单与 RPO 口径见 8.4。

### 1.5.1 辨析用户数据口径：用 DAU 代替全渠道 MAU 衡量高频用户

**方法要点**：对公司官宣的用户数据做口径辨析——全渠道 MAU（含 App、手机 Web、PC）是低频指标，真正的高频用户体量要看 DAU，最好再用第三方单渠道数据交叉验证。

**操作步骤 / 拆分口径 / 公式**：

1. 识别官宣数据的口径：MAU 还是 DAU；全渠道（App、手机 Web、PC）还是单渠道。
2. 找对应的高频口径：DAU。
3. 用第三方统计（如 QuestMobile）取同口径的单渠道数据，与官宣数据交叉验证。
4. 与对手比较时统一到同一口径，并计算起步时间与差距。

**关键指标与数据来源**：MAU；DAU；渠道口径；第三方统计（QuestMobile）。

**判断标准**：官宣口径宽（全渠道 MAU）而竞品用窄口径（单渠道 DAU）时，两者不可直接比较；以同口径 DAU 衡量，才是真实的高频用户体量与差距。

**海豚案例**：
- 阿里（2026-01-16）：千问官宣全渠道月活过 1 亿，但豆包全渠道日活已过亿，千问日活只在百万级；QuestMobile 统计 12 月仅 App 渠道 DAU，豆包约 7000 万，千问不到 500 万；起步约 3 个月，差距仍然巨大。
- 腾讯（2026-01-26）：豆包用两年时间达到 1 亿日活（作为对照的时间尺度）。

**适用场景与注意事项**：适用于验证互联网产品的用户数据；与 1.4.4（亲测体验）一起使用，体验结论用 DAU 验证。

### 1.5.2 剥离付费用户口径中的“搭售会员”，算出纯产品付费用户和 ARR，再与龙头对比

**方法要点**：公司披露的付费用户可能混有捆绑口径，要拆开后得到“纯产品付费用户”和对应 ARR，再与同样以 C 端起家的龙头对比，量化变现差距。

**操作步骤 / 拆分口径 / 公式**：

1. 取披露的总付费用户。
2. 识别并剔除捆绑会员：纯产品付费用户 = 总付费用户 − 捆绑会员数（如 X 平台社交订阅会员）。
3. 算出纯产品付费用户对应的 ARR。
4. 与同类龙头对比付费用户和 ARR，量化差距。
5. 补充注意：B 端 API 企业层上线时间（本例到 2025 年底才上线）。

**关键指标与数据来源**：总付费用户、捆绑会员数、纯 AI 付费用户、ARR、竞品付费用户和 ARR。

**判断标准**：捆绑会员占比越高，表观付费用户越“有水分”；纯产品付费用户和 ARR 与龙头的差距，才是真实的变现进度。

**海豚案例**：
- SpaceX《SpaceX：AI 烧钱不止…》（2026-06-30）：Grok 生态付费用户 630 万中，约 440 万其实是 X 平台的社交订阅会员（Grok 只是增值服务），真正为独立 AI 功能（SuperGrok）付费的只有约 190 万，对应 ARR 约 10 亿美元；与 OpenAI（付费用户超过 5000 万，ARR 超过 250 亿美元）对比，变现进度没跟上投入规模。

**适用场景与注意事项**：适用于订阅类公司的用户数据甄别（捆绑会员、免费试用、家庭账户）。

### 1.5.3 会员口径偏宽时，用人均产品数和交叉销售占比验证真实粘性

**方法要点**：先承认会员增长数据有水分（注册即算会员），再用行为型粘性指标（人均使用产品数、交叉销售占比）验证增长质量，用行为指标替代注册数。

**操作步骤 / 拆分口径 / 公式**：

1. 识别会员口径宽松之处：会员不要求入金或真实贷款，注册即算会员；与头部相比差距也不小；高增长部分来自低基数。
2. 用粘性指标验证质量：
   - ① 用户扩张时人均使用产品数保持稳定，高频金融服务类产品的人均使用量还在增加；
   - ② 新功能销售中 30–40% 来自老用户交叉销售。
3. 综合判断：存在一定的品牌心智。
4. 补充参照：近 5 年会员 CAGR 40%，管理层指引 2026 年会员增长 30%。

**关键指标与数据来源**：会员数、会员 CAGR、人均产品数、高频产品人均使用量、交叉销售占比。

**判断标准**：会员数增速不是质量证据；人均产品数稳定/上升、交叉销售占比高才说明粘性，增量用户并未稀释。

**海豚案例**：
- SoFi《被浑水盯上的 SoFi：真金科新贵 or“高科技噱头”？》（2026-06-16）：1370 万会员不要求入金或真实贷款；5 年 CAGR 40%，交叉销售 30–40%，据此判断存在一定的品牌心智。

**适用场景与注意事项**：适合用户口径宽松的互联网和金融平台。与 12.2（做空报告核查）配合，遇到做空质疑用户质量时使用。

### 1.5.4 ARR 口径辨析清单：毛收入 vs 净收入、计算窗口、宣布时点

**方法要点**：横向比较 ARR 前先统一三个口径，否则无法横向对比，还会造成很大的预期乌龙。

**操作步骤 / 拆分口径 / 公式**：

1. 毛收入 vs 净收入：ARR 是否含要付给外部渠道的分销收入（毛收入），还是剔除了各种分成（净收入）。
2. 计算窗口：过去 28 天平均 × 12，还是最近一周 × 52。
3. 宣布时点：是否刚好在畅销旗舰模型发布或促销之后（时点效应会抬高短期 ARR）。
4. 统一口径后再比较；统一不了时，对差异做还原（见 1.5.8）。

**关键指标与数据来源**：ARR 口径、计算窗口、发布时点。

**判断标准**：同一指标的“毛”与“净”可以相差很大，跨公司比较前必须先对齐口径，口径不齐就不下比较结论。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”：真实威力没那么大，一场情绪乌龙！》（2026-10-09）：Anthropic 的 ARR 一直用 Gross 口径，OpenAI 用剔除微软和云平台分成的 Net 口径；OpenAI CRO 4 月给员工的备忘录也提到 Anthropic 营收因含云渠道分成而“夸大”。

**适用场景与注意事项**：适用于所有非 GAAP 经营指标（ARR、GMV、MAU）的跨公司比较。

### 1.5.5 渠道分成比例测算，并用招股书数据交叉校验

**方法要点**：按合作协议推算渠道/股东分成比例，再用招股书披露的分销费用与分销收入做交叉校验，解释差异，把“表观分成”还原成真实结构。

**操作步骤 / 拆分口径 / 公式**：

1. 按合作协议推算分成：
   - 微软拿 OpenAI 每 1 美元收入中的 20 美分（到 2030 年，有累计上限）；
   - Bedrock 拿（毛收入 − 推理成本）× 50%，假设推理成本 35%，得出 (1 − 35%) × 50% = 32%。
2. 用招股书披露的“分销费用 ÷ 经云平台的分销收入”交叉校验，得到实际比例。
3. 解释差异：IPO 材料披露的云收入既包括 Bedrock 等分销（TaaS，分成主要在这里），也包括 Anthropic 自己直销 API、只把云基础设施放在 AWS 和 Google 的部分，后者没有分销分成，只有云托管成本。
4. 得出结论：两家渠道分成比例本质一样，差别在分销依赖度和微软的 20% 权益分成。

**关键指标与数据来源**：分成比例、推理成本占比、分销费用、分销收入；合作协议条款与招股书。

**判断标准**：理论分成（如 32%）与招股书实测（约 16%）出现差异时，不是其中一个错了，而是分母口径混合了分销与直销；要分开归因。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”…》（2026-10-09）：OpenAI 与微软新协议约定到 2030 年每 1 美元付 20 美分，累计上限 380 亿美元；Anthropic 2025 年付给 Amazon 和 Google 的综合分销费用约 3.51 亿 ÷ 两云平台分销收入 21.6 亿 ≈ 16%；1H26 之前 Anthropic 对云渠道的分销依赖更重。

**适用场景与注意事项**：适用于平台分成型业务（云市场、应用商店、分销）的收入口径还原。

### 1.5.6 多信源时间序列交叉核对，判断数据口径

**方法要点**：把媒体、高管表态、知情人士、另类数据的多个数字排成时间序列，先倒推、再检验隐含环比是否合理，最后与另类数据的趋势比对；出现矛盾时判定各数字口径不同，并用产品事件解释增速波动。

**操作步骤 / 拆分口径 / 公式**：

1. 把各信源的数字按时间排成序列。
2. 由增速倒推前一时点的数值。
3. 检查同口径假设下隐含的环比是否合理（如是否出现零增长）。
4. 与另类数据（如 TickerTrends，模型拟合时引入了官方数据）的趋势比对。
5. 出现矛盾时，判定各数字口径不同，差额对应特定的分成（如微软 20%）。
6. 用产品事件解释增速波动：竞品旗舰发布期零增长；自家新模型发布、降价后开始抢份额。

**关键指标与数据来源**：各信源 ARR 数值、隐含环比、另类数据增速。

**判断标准**：若同口径假设下得到不合理的环比（如零增长）且与另类数据趋势矛盾，就认定数字不是同口径；差额恰好对应某一分成比例，则判定为毛/净口径差。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”…》（2026-10-09）：路透称 ARR 接近 700 亿、自 Q3 以来增长 70%，倒推 6 月约 400 亿；高管称 2025 年底 ARR 超 200 亿、7 月约为年底两倍，与 Bloomberg 的“7 月 400 亿”对应；若同口径则 7 月环比零增长，与 TickerTrends 的 7 月 +10% 矛盾，因此判断 6 月 400 亿与 700 亿为毛收入、7 月 400 亿为净收入；当时云渠道分销还很低（Google 4 月、Bedrock 6 月才开始分销 ChatGPT）；3–4 月 Claude Opus 4.6 配合 coding agent 火热时 OpenAI 零增长，4 月底 GPT 5.5 设为默认、Codex 进入 ChatGPT 移动端并叠加降价后开始抢份额。

**适用场景与注意事项**：适用于非上市公司或口径不透明数据的辨伪；使用另类数据时要了解其建模方式（是否引入了官方数据）。

### 1.5.7 用可比公司估值倍数的一致性反推数据口径

**方法要点**：把有争议的数据代入估值倍数，看与可比公司同口径倍数是否一致，作为口径判断的旁证。

**操作步骤 / 拆分口径 / 公式**：

1. 取有争议的数据（如 700 亿 ARR）与对应估值。
2. 计算倍数：P/ARR = 估值 ÷ ARR。
3. 与可比公司（同口径）的倍数比较；若某一口径假设下两者倍数完全一致，说明该口径假设成立。

**关键指标与数据来源**：融资/IPO 估值、ARR、P/ARR。

**判断标准**：假设“700 亿是毛收入”时，OpenAI 的 P/ARR 与 Anthropic 的 P/Gross ARR 完全一致，成为口径判断的旁证。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”…》（2026-10-09）：OpenAI 最新一轮融资 1.4 万亿美元 ÷ 700 亿 ARR = 20x；Anthropic 2 万亿 IPO 估值 ÷ 年底 1000 亿 Gross ARR = 20x。

**适用场景与注意事项**：适用于一级市场估值与二级可比的交叉检验。该方法只是旁证，不单独作为结论。

### 1.5.8 净收入口径还原为毛收入口径的分步计算

**方法要点**：消息面冲击时，把净口径的数字分步还原到毛口径，与传闻数字比较绝对差距和百分比差距，判断“缺口”有没有标题说的那么大。

**操作步骤 / 拆分口径 / 公式**：

1. 加回主要股东分成：净收入 ÷ (1 − 股东分成比例)（如 ÷ (1 − 20%)）。
2. 估算外部平台分销占流水的比例（参考第三方对可比公司的估计作上限），乘以渠道分成比例，得到要加回的分成部分。
3. 再除以 (1 − 该比例)：毛收入 = 中间结果 ÷ (1 − 外部分销占比 × 渠道分成比例)。
4. 还原后与传闻数字比较：绝对差距和百分比差距。
5. 提示：绝对值差异会影响产业链短期业绩预期。

**关键指标与数据来源**：净 ARR、股东分成比例、外部分销占比、渠道分成比例。

**判断标准**：还原后的差距远小于标题数字，则标题属于情绪乌龙；但绝对值差异仍要计入产业链的短期业绩预期。

**海豚案例**：
- 《OpenAI 收入 200 亿缺口“炸锅”…》（2026-10-09）：500 亿 ÷ (1 − 20%) = 625 亿；假设 Vertex、Bedrock 等外部平台分销占 10%（SemiAnalysis：Anthropic 经 Bedrock 的流水也只约 15%）× 25% 渠道分成 = 2.5%，625 ÷ (1 − 2.5%) ≈ 640 亿；距 700 亿约 10%、60 亿，远小于“少了 200 亿”的惊悚标题。

**适用场景与注意事项**：适用于消息面冲击时快速判断利空的真实幅度。

### 1.5.9 多源另类数据交叉验证并甄别数据质量

**方法要点**：对同一问题引用多个独立数据源，评估各自的口径与可靠性，用“相互印证”得出结论，并克制地说明结论的边界。

**操作步骤 / 拆分口径 / 公式**：

1. 找多个独立数据源：如 Northbeam（为 DTC 大牌做广告归因的平台）披露客户在 APP 的投放份额变化；BuiltWith 用爬虫跟踪安装 AXON Pixel 的商家域名数；BofA 去重商户数。
2. 评估各来源可靠性：爬虫数据可能受算法稳定性和单商家多域名变化影响，可靠性弱于美银去重数据。
3. 用“相互印证”得出结论：BofA + Northbeam 说明新增客户主要来自中小商家。
4. 克制地说明边界：这不代表短中期增长趋势被扭转。

**关键指标与数据来源**：Northbeam 客户在 APP 投放份额（圣诞期间 −60bp）、BuiltWith 域名数、BofA 去重商户数。

**判断标准**：多个独立来源指向同一方向，结论才可采信；单一来源的数据要标注样本偏差；可靠性较弱的数据只作辅证。

**海豚案例**：
- AppLovin（2026-01-20）：Northbeam、BuiltWith、BofA 三方数据交叉，结论为新增客户集中于中小商家。

**适用场景与注意事项**：广告平台、电商、App 等有大量第三方追踪数据的标的；每个数据源需标注样本偏差。第三方追踪数据的取得与代理指标设计见 1.4.6。

### 1.5.10 调研信息互相矛盾时，用长期协议和产品开发周期等硬约束来裁决

**方法要点**：市场调研互相打架时，不在两方之间选边，而是找更硬的约束（合同条款、工程周期）来裁决。

**操作步骤 / 拆分口径 / 公式**：

1. 摆出互相矛盾的调研结论（如一方说下一代 TPU 可能降规由联发科主导，等于 COT 跑通；另一方说 COT 团队还在艰难优化上一代）。
2. 转看两条硬信息：
   - ① 长期协议：博通为谷歌未来若干代 TPU 开发并供应定制芯片，虽不排他，但提高了锁定确定性；
   - ② 产品周期：参照 Trainium-3，从概念到量产约 3 年，合作伙伴在发布前约 18 个月敲定，研发后段很难改方向。
3. 据此判断中短期供应格局基本已锁定。

**关键指标与数据来源**：长期协议条款；产品开发周期（概念到量产）；合作伙伴敲定时点。

**判断标准**：合同和工程周期是可验证的锚；当调研结论与这些硬约束冲突时，以硬约束为准，短中期脱钩概率低。

**海豚案例**：
- 博通（2026-07-07）：v9 降规与 v8 仍在优化两种调研互相矛盾，用长期协议加 3 年/18 个月周期判断短中期脱钩概率低。

**适用场景与注意事项**：适用于渠道调研噪音大的科技硬件行业，合同和工程周期是可验证的锚。

### 1.5.11 用立项到收入确认的时间反推首批出货的产品形态

**方法要点**：用产品开发周期的常识校验管理层给出的时间表，由“立项到收入确认”的时长反推首批出货的产品形态，并进一步判断对竞争对手冲击的先后。

**操作步骤 / 拆分口径 / 公式**：

1. 取管理层的时间表：签约/立项时间、收入确认时间。
2. 对照产品开发周期常识：签约/立项到确认收入不到 1 年，不可能是全定制 ASIC（至少约 2 年）。
3. 反推第一阶段出货形态：大概率是定制 ASIC 的周边芯片（I/O die、SerDes chiplet、retimer、网络周边硅等）；全定制 ASIC（第二阶段）量产至少要到 2028 年及之后。
4. 据此判断对竞争对手的冲击时间先后（短期 vs 中长期）。

**关键指标与数据来源**：签约时间、收入确认时间、产品开发周期。

**判断标准**：管理层时间表与产品周期常识不符时，说明首批出货的形态不是宣传中的最终形态。

**海豚案例**：
- 高通《抱上亚马逊大腿…》（2026-09-09）：公司预计 FY27Q1 开始推出定制 ASIC 产品，海豚君据此推断首批是周边芯片，全定制要到 2028 年及之后，进而判断 Alchip 短期风险不大、中长期风险不小。

**适用场景与注意事项**：适用于芯片设计服务、定制化业务的收入节奏判断。

### 1.5.12 用公司自身规划测算校验媒体报道（GW 口径）

**方法要点**：市场按媒体报道给出激进预期时，用公司自己披露的数据中心建设规划逐项测算，识别报道和自建口径之间的净差，判断 capex 指引是否被市场高估。

**操作步骤 / 拆分口径 / 公式**：

1. 取媒体报道的目标（如 GW 规模）。
2. 取公司披露的数据中心建设规划，逐项测算自建算力的合理值（如各年底 GW）。
3. 计算报道与自建口径之间的净差。
4. 判断 capex 指引是否被市场高估。

**关键指标与数据来源**：数据中心规划 GW、媒体报道目标、Capex 指引。

**判断标准**：自建测算显著低于报道值，说明市场对 capex 的预期过激。

**海豚案例**：
- Meta（2026-07-30）：路透报道 2027 年 14GW（今年底的两倍），海豚君按规划测算 2026 年约 7GW、2027 年底 9–10GW，差约 4GW；结论是“嘴上很猛、数字很稳”，让 capex 多头不安。

**适用场景与注意事项**：AI capex 预期博弈；要明确报道口径与自建口径的差异来源。

### 1.5.13 社媒传闻可信度检验：来源立场 / 官方证实 / 技术可行 / 对方动机 / 电话会契合度

**方法要点**：对社媒传闻用五个维度逐一检验可信度，并显式披露来源的利益冲突，结论不夸大。

**操作步骤 / 拆分口径 / 公式**：

1. 来源立场：传闻发布者是谁、有无利益相关（如本人是公司多头）。
2. 官方证实：是否已获官方证实。
3. 技术可行：实操上是否有绝对障碍。
4. 对方动机：对方是否有合作诉求（如变现诉求极高，与成熟第三方合作可以预期，也可能多家并行）。
5. 与公司既有表述的契合度：与电话会提及的内容是否吻合（如 Q4 电话会提到 AXON 对中小商家品牌发现很有帮助，与大模型基于用户偏好做小众品牌种草相合）。
6. 给出克制结论：有助于消退负面情绪，但尚无实质进展。

**关键指标与数据来源**：信息来源、官方确认状态、管理层电话会表述。

**判断标准**：五个维度中官方证实是决定性的；其余四项只能提升“可能性”，不能把传闻当成事实。

**海豚案例**：
- AppLovin/OpenAI《（短评）AppLovin 盘中盘后大涨》（2026-02-20）：对“OpenAI 与 AppLovin 合作做 ChatGPT 广告变现”的 X 传闻——来源是金融大 V Jonah Lupton，本人是 AppLovin 多头；未获官方证实；技术上无绝对障碍；OpenAI 今年变现诉求极高；与 Q4 电话会表述契合；结论是有助于消退因 AI 和 Meta 竞争带来的负面情绪，但尚无实质进展。

**适用场景与注意事项**：适用于传闻驱动的股价异动；需显式披露来源的利益冲突。

### 1.5.14 区分“新增规划”与“计划内进展”，以及“早有预期”与“首次曝光”

**方法要点**：点评公告或新闻时，先判断信息有多少增量；增量大小决定对基本面和估值的调整幅度，非增量信息主要影响情绪。

**操作步骤 / 拆分口径 / 公式**：

1. 判断信息是纯新增规划，还是此前已定下规划的新进展。
2. 判断是早有预期（此前渠道调研、电话会已提过），还是首次曝光；增量可能只在于具体细节（如时间线）首次泄露。
3. 对尚无实质进展的传闻/招聘信息，不当作增量。
4. 据此决定调整幅度：重点转到真正的增量（如融资结构）。

**关键指标与数据来源**：信息首次出现时间、官方确认状态、此前渠道调研/电话会表述。

**判断标准**：增量大 → 调整基本面与估值；非增量 → 影响情绪而已。

**海豚案例**：
- Meta《（短评）Meta 与 BlackRock 数据中心合资》（2026-07-28）：并非纯新增规划，而是早已定下的五大自有数据中心之一的新进展，重点转到融资结构。
- 腾讯《（短评）腾讯暴力反弹》（2026-03-11）：微信 Agent 项目去年已启动，渠道调研和业绩会都提过，增量只在于具体时间线首次泄露。
- AppLovin《（短评）AppLovin 盘中盘后大涨》（2026-02-20）：社交平台和 OpenAI 合作只是招聘信息与传闻，尚无实质进展。

**适用场景与注意事项**：适用于所有新闻/公告驱动的事件快评。与 1.3.1（已知已定价 vs 边际增量）互补：1.3.1 面向财报与事件后的股价反应，本方法面向快评中对单条新闻的增量判断。

### 1.5.15 公开信息拼图推断大单客户与合同结构

**方法要点**：公司没披露客户时，用多源公开信息推断大单背后的客户和合同结构，并标明哪些是市场共识、哪些是自己的推断。

**操作步骤 / 拆分口径 / 公式**：

1. 梳理前序公告：如 1Q26 前，公司曾公告与某客户签订从 FY28 开始每年约 300 亿美元的云服务订单（没披露年限）。
2. 结合外部事件：7 月 22 日 OpenAI 宣布在 Stargate 框架下新增约 4.5GW 算力协议（Stargate II 的 4 个项目），市场按 5 年合同期预期 RPO 环比 +1500 亿。
3. 对比实际：实际 RPO 环比 +3000 亿以上，是预期的两倍；官方说法是“来自 3 个不同客户”，市场找不到另外两个大客户。
4. 推断：OpenAI 合同实为每年 600 亿、从 2027 年起 5 年，即订单规模翻倍，而不是找到了体量相近的新客户。
5. 补充：2Q26 新增约 600 亿据报道来自 Meta 和 Nvidia。
6. 标明哪些是市场共识、哪些是自己的推断。

**关键指标与数据来源**：公告年化订单额、合同期、RPO 环比增量、GW 规模。

**判断标准**：公开信息之间的数字关系（预期 vs 实际翻倍、客户数与可识别客户数不符）是拼图的核心线索；推断要给出最简洁、能自洽解释全部数字的结构。

**海豚案例**：
- 甲骨文《捡剩饭、傍大款！甲骨文拿命博生存？》（2026-01-22）：推断 3000 亿大部分来自 OpenAI。

**适用场景与注意事项**：适合客户不透明的大单事件。推断结论要标明是市场共识还是自己的推断。RPO 口径本身见 8.4。

### 1.5.16 行业竞争假说 + 公司零散新闻拼图推理

**方法要点**：用行业流行的竞争假说，回头解释公司近一年看似怪异的新闻，拼出“厚积薄发、弯道超车”的逻辑，并保持结论开放、落到可跟踪的组织问题上。

**操作步骤 / 拆分口径 / 公式**：

1. 确立行业假说：头部大模型竞赛越来越看重数据壁垒——对齐环节 RLHF 的高质量标注数据、用户真实操作的长轨迹数据（如 Coding 领域的 B 端脱敏编程轨迹）。
2. 用假说解释公司零散新闻：收购 Scale AI 后自建内部标注团队（员工转岗不从即被裁）、用电脑屏幕与鼠标移动收集员工工作流程数据。
3. 拼出逻辑：数据资产与标注团队在积累，是“厚积薄发”。
4. 用同一假说解释竞品差异：如 Google 受合规红线限制，可训练的长轨迹数据少于 Anthropic、OpenAI。
5. 结论保持开放：继续跟踪组织问题能否修正，以产品表现验证。

**关键指标与数据来源**：数据资产类型、标注团队建设、合规约束。

**判断标准**：假说需要既解释自身又解释竞品差异；它只是假说，需要后续产品表现验证，不能当事实陈述。

**海豚案例**：
- Meta（2026-07-10）“为什么 Meta 大模型能力似乎又行了？”一节：用数据壁垒假说串联收购 Scale AI、自建标注团队、收集员工工作流程数据等新闻。

**适用场景与注意事项**：解释技术能力突变的定性推理；属假说，需后续产品表现验证。

### 1.5.17 用平台披露 + 问卷调查多源推算不可直接统计的用途占比

**方法要点**：关键变量（如个贷具体用途）无法从官方统计口径直接获得时，用同业平台披露和公司自身问卷交叉推算，并以“区间 + 来源标注”的方式呈现，让后续情景测算有据可依。

**操作步骤 / 拆分口径 / 公式**：

1. 取同业平台披露：如 LendingTree，平台超一半借款人为偿债，主要是信用卡债务整合。
2. 取公司自身问卷：如约 1/4 受访者把债务整合列为首要用途，其中 70% 用于还信用卡 → 1/4 × 70% ≈ 18%。
3. 综合给出区间（20%–40%）作为假设范围，而不是单点值。
4. 标注每个数字的来源，并把区间用于后续情景测算。

**关键指标与数据来源**：借款人用途问卷占比、平台用户行为披露。

**判断标准**：问卷和同业披露的口径不同，推算只能给区间；区间上下限要在情景测算里都跑一遍。

**海豚案例**：
- SoFi《槽点多多的 SoFi，“贵”得有理？》（2026-06-29）：推算信用卡债再融资需求约 18%，最终使用 20%–40% 区间做分子测算。

**适用场景与注意事项**：适用于难以直接统计的行为类变量（用途、场景、渗透率）；注意问卷样本偏差、平台客群偏差，应以区间而非精确值呈现。

**组合用法提示**：关于 ARR 口径的几个方法（1.5.4–1.5.8）构成一条完整的“口径辨析链”：先列口径清单 → 测算渠道分成并用招股书校验 → 多信源时间序列核对 → 用估值倍数一致性旁证 → 分步还原到统一口径并量化“缺口”真实幅度；对其他行业的非 GAAP 指标同样适用。

**相关方法交叉引用**：中美同业 ROIC 差异分析，并追溯第三方测算的偏差来源，详见 6.2；用第三方追踪网站跟踪车队规模，并标注注册与可运营的口径差异，详见 1.4.6；大客户收入贡献测算与会计口径辨析（总额 vs 佣金、避免重复计算），详见 6.7。
